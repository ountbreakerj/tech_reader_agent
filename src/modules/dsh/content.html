1Cordis：插件与服务

整个项目的「操作系统」——理解它，后面所有模块都是它的应用
DSH 没有「主程序里硬编码初始化 A、B、C」。运行时是一棵被「声明」出来的插件树：每个功能（哪怕是 LLM 调用、工具、UI、沙箱）都是一个 Cordis 插件（plugin）。插件要么是一个继承 Service 的类，要么是一个函数 apply(ctx)。
代码讲解（做了什么）

核心 API 极其简单，但语义很强：

// 插件 = 类（服务定义）或函数（副作用装配）
export class FooService extends Service {
  static inject = ['bar']        // 声明我依赖谁（决定挂载顺序）
  constructor(ctx) { super(ctx, 'foo'); /* 注册到 ctx.foo */ }
}

// 或者函数式插件
export function apply(ctx, config) {
  ctx.effect(() => ctx.foo.register(...), 'foo.register')  // 可逆的副作用
}
  • ctx：共享的「服务仓库」，按名字 ctx.<key> 存取。你在任意插件里都能拿到别人注册的服务。
  • inject：声明依赖。Loader 据此推导挂载顺序（被依赖者先挂），不是你手写 boot 顺序。
  • ctx.effect() / ctx.on()：所有「注册」都是可逆效应。插件卸载时自动回滚——没有手动清理的意大利面条。
白话梳理（怎么做的 / 为什么）

把它想成 Python 的 依赖注入容器（如 dependency-injector / FastAPI 的 Depends）：

  • ctx 就是一个全局容器，里面按名字存各种「单例服务」（LLM、工具表、会话仓库……）。
  • 你写一个插件，等于「往容器里塞一个服务，并声明我需要哪些别的已存在的服务」。
  • 关键好处：没有特权核心。Cordis 内核本身不知道「LLM」「工具」是什么，它只提供「挂载/注入/效应回滚」机制。所有业务都是平等的插件。换一个能力（比如把本地 bash 换成沙箱 bash）只是换一个插件，上层工具一行都不用动。
  • 为什么用 effect 而不是 return 注册：因为插件卸载要干净。effect 返回一个「撤销函数」，卸载时 Cordis 自动调用——类比 Python 的 try/finally 或 context manager 的 __exit__。
代码讲解：三种模式到底怎么跑（均对照 vendor/cordis/src/events.ts 真实实现）

Cordis 的事件总线 ctx.events 一共支持 5 种派发模式：emit / parallel / serial / bail / waterfall。你日常高频率只会用到前三种，parallel 与 bail 是它们的近亲，文末顺带一提。所有模式都用 ctx.on('<事件名>', 监听器) 注册监听器，区别只在「监听器签名」和「调用方怎么把控制权交下去」。

模式 监听器签名 运行机制 典型用途 / 真实事件
waterfall (payload, next) 由外到内包裹；调 next() 放行，不调则否决整条链（含内置行为）；return 覆盖结果 改写/拦截：agent/pre-step、agent/request、tools/pre-execute/execute/post-execute、llm/stream
serial (payload)
（无 next）		 依次 await 每个监听器；遇到首个「bail 值」（非 null / 非 false / 非 undefined）立即停并把它作为结果。不会把上值喂给下个 有序裁决：agent/turn-stopping（「该停了吗」）
emit (...args) 同步调用所有监听器，不 await 它们返回的 Promise；发了就走 广播事实：所有 durable 会话日志（turn/start、assistant/message、tool/result…）、agent/error、agent/status

① waterfall —— 环绕中间件（最强大，也最常用）

  • 监听器签名 (payload, next)：最后一个参数才是 next，前面的参数是派发的 payload（如 { agent, messages, signal }）。
  • 机制（events.ts:234）：所有监听器按注册顺序「由外到内」包裹，最内层是派发时传入的默认实现（built-in）。调用 next() 才把控制权交给下一个监听器（最终到底层默认行为）；不调用 next() 就等于否决整条链路，包括内置行为。return 一个值则覆盖整条链路的结果。
  • 真实例子（packages/session/session-checkpoint-policy）：每个 step 前先 flush 会话，再放行： 
    ctx.on('agent/pre-step', async ({ agent }, next): Promise<PreStepDecision> => {
  await ctx.sessions.flush(agent.session)
  return next()            // 放行，并返回 next() 的结果
})
  • 真实例子（packages/subagent/subagent-in-process-driver）：先 await next() 拿到下游决策，再据结果改写： 
    childCtx.on('agent/pre-step', async ({ agent }, next) => {
  const decision = await next()   // 先让链走完
  if (!appended && decision.kind === 'enter') { /* 再改写 */ }
})
  • 类比 Python/ASGI：就是 middleware(request, call_next)，包裹在「真正处理」外面；call_next() ≈ next()。
  • 高频坑：忘了 next() → 链路卡死或被静默否决；想改写结果就 await next() 后处理再 return，或自己 return 一个值短路。

② serial —— 有序裁决链（注意：不是值管道！）

  • 监听器签名 (payload)：没有 next。
  • 机制（events.ts:204）：按注册顺序依次 await 每个监听器；一旦某个监听器返回一个「bail 值」（isBailed(value) = value !== null && value !== false && value !== undefined），立即停止并把该值作为结果返回。否则全部跑完、返回 undefined。
  • 关键纠正：serial 不会把上一个返回值喂给下一个监听器——每个监听器拿到的都是同一份原始参数。它本质是「谁先表态谁说了算 / 第一个要停的就让整轮停」的有序短路，不是 reduce 式的值管道。（之前简版说「前一个喂给后一个」是不准确的，以此为准。）
  • 真实例子（packages/core/agent-loop/src/agent.ts:296）：每轮结束前问所有插件「该停了吗」： 
    // 调用方
await this.dispatch.serial('agent/turn-stopping', { turn, signal })

// 某个插件：想继续就注入一条消息，把轮子再转一轮
ctx.on('agent/turn-stopping', ({ agent: subject }) => {
  if (steps < 3) subject.steer(createUserMessage({
    content: [{ type: 'text', text: 'continue' }], source: { kind: 'plugin' }
  }))
})
  • 类比 Python： 
    async def serial(listeners, payload):
    for listener in listeners:            # 按注册顺序
        r = await listener(payload)       # 永远拿到同一份 payload
        if r not in (None, False):        # 首个「bail 值」即终
            return r
  • 与 waterfall 区别一句话：waterfall 用 next() 串成「包裹链」可改写可放行；serial 没有 next，用「返回值是否 bail」做有序短路。

③ emit —— 广播（只发不收）

  • 监听器签名 (...args)：任意参数，无返回值约定。
  • 机制（events.ts:194）：同步遍历所有监听器并调用，不会 await 监听器返回的 Promise。发了就走，不等回执。
  • 真实例子：会话服务对每个 durable 事件只发不收；持久化插件只是订阅去落盘，发的人根本不等它： 
    // 会话服务：durable 事件只发不收
ctx.emit('session/event', session, event)

// 持久化插件：订阅去落盘，发的人不等它
ctx.on('session/event', (_session, event) => {
  if (event.type === 'step/end') steps++
})
  • 类比 Python：logging.info(...) 或发布-订阅总线 bus.publish(topic, payload)——发布者不关心谁在听、听的人多久处理完。
  • 坑：若在 emit 监听器里做异步工作却没自己接住 Promise，错误会被吞掉（emit 不 await）。需要「等结果」就该用 waterfall/serial 而非 emit。

补充两位近亲：parallel 并发跑所有监听器、await 全部（Promise.allSettled，任一拒绝则抛 AggregateError），用于「都要做、互不依赖、要等全做完」；bail 是 serial 的同步版（按注册顺序跑，遇首个 bail 值即停、同步返回）。记忆口诀：要「改写/拦截」用 waterfall；要「谁先表态谁定」用 serial；要「只通知不等」用 emit。

设计哲学：为什么这三种模式必须分开（各自回答什么问题）

每一种模式不是「调用方式不同」这么浅，而是 Cordis 把「插件怎么介入运行时」这个问题，按「扩展点到底要向贡献者问什么」拆成了三个原语。三者回答的是三类本质不同的问题，硬塞进一个机制会丢表达力或逼出 hack：

  • emit 回答「我发生了」（通知）。可观测性 / 持久化 / UI 必须在事件发生时作出反应，但绝不能影响控制流。若把通知做成「要等返回值」，发日志的人就被迫关心谁在听、听的人多久处理完——日志与观察者被耦合死。所以 emit 单向、不收返回值、不同步等待。Python 类比：logging.info(...) 或发布-订阅 bus.publish(topic, payload)。agent 里用在 session/event：一条 step/end 发生了，持久化 / 遥测 / UI 都去听，但都不改变循环走向。
  • waterfall 回答「你来处理 / 审批这个东西」（加工）。此时值才是重点：同一个 payload（要发给模型的 prompt、要执行的工具调用）需被多个插件依次丰富 / 校验 / 改写 / 否决，真正被用的是「最后一个环节产出的那个版本」。这正是嵌套包裹（middleware）语义：外层先拿控制权，调 next() 把值交给内层，内层结果再返给外层。Python 类比：ASGI 的 middleware(request, call_next)、functools.reduce 合成包装函数、装饰器堆叠——一份文件依次盖几个部门的章，最后一版才生效。agent 里用在 agent/pre-step / agent/request / tools/* / llm/stream：凡是「模型看到的 payload」都走 waterfall。
  • serial 回答「你来决定」（裁决）。决策必须「任何参与者（尤其安全护栏）都能立即叫停、且顺序优先」。若用 waterfall 做裁决，值会流过所有监听器、只有最后一个能真正决定，那「任意方可否决」就被破坏。serial 契约：每个监听器拿同一份原始参数，返回 void 表示放行，返回 bail 值表示「停，用这个值」，第一个 bail 立即终止整条链。Python 类比：for h in handlers: r = h(payload); if r: return r（顺序短路、首个非零即定）；Django 的 process_request 返回 HttpResponse 即短路。agent 里用在 agent/turn-stopping（「这轮该停了吗」）——护栏一旦 bail，整轮立即停，不用等其他插件表态。注意：serial 不是值管道，不会把上一个人的返回值喂给下一个人，它要的是「裁决」不是「加工」。

为什么不能合并成一个机制：① 只用 emit → 收不到结果，被迫建带外通道（如全局变量传「该停了吗」），脆弱且类型不安全；② 只用 waterfall → 把决策塞进值管道，只有最后一个监听器能真正决定，破坏「任意方可否决」；③ 只用 serial → 值无法沿链变形，做不了 prompt 拼装这类「多贡献者富集同一份 payload」的事。所以本质是：把「扩展点要问的问题的语义」显式建模，并让类型系统强制贡献者匹配契约——这是把「依赖倒置」用到了控制流上：核心只依赖「事件 + 模式」这个抽象，不依赖任何具体行为。agent-loop 作者写 dispatch.waterfall('agent/pre-step', ...) 时，根本不知道、也不需要知道有哪些插件挂上来了。

收尾·映射回你学过的 turn/step 生命周期：emit → session/event（被多人观察但不影响流程）；waterfall → pre-step / request / tools/* / llm/stream（塑造「模型看到的 payload」）；serial → turn-stopping（决定控制流走向：停还是继续）。

白话梳理（怎么做的 / 为什么这样设计）
  • 总纲：Cordis 把「插件如何介入运行时」统一抽象成 5 种派发语义；核心脊梁和所有能力接缝，都只是这些语义的具体实例。你不用改框架，只要 ctx.on('<事件名>', 监听器) 就能挂到任意扩展点。
  • 为什么需要三种：因为「介入」有三种本质不同的意图——(a) 围绕一个动作前后包裹并可能改写（waterfall）；(b) 多个判断者按序表决、第一个反对就停（serial）；(c) 只是广播一个事实、谁爱听听（emit）。只用一种，要么丢失表达力、要么逼大家 hack。
  • 关键不变量：所有 durable 会话事件都是 emit（只记不拦）；所有「钩子 / 接缝」（pre-step、request、tools/*、llm/stream）都是 waterfall；turn-stopping 这种「有序裁决」用 serial。
  • 关联已学：这正是第 3 章「接缝三件套」在运行时的落点——Definition 声明事件名，Provider/Consumer 通过 ctx.on() 挂监听器介入；而「事件名 + 派发模式」就是这个接缝的接口契约。比如 llm/stream 是 waterfall 接缝，packages/llm/llm/src/invariant.ts:88 用 { global:true, prepend:true } 在最外层包了一层流校验：ctx.on('llm/stream', (_options, next) => validateStream(next(), fail), { global:true, prepend:true })。
  • 一句话上手：看到 ctx.on('xxx', (...args, next) => ...) 带 next 的就是可改写拦截点；看到没 next 且用于「表决」的就是 serial；看到 ctx.emit 就是记账/广播、别指望它返回东西。

白话梳理（怎么做的 / 为什么）

把一次对话当成一条 git commit 历史：

  • 每说一句话、模型每回一句、每次调工具，都等于 git commit 一条不可变记录。
  • deriveMessages() 就像 git checkout 出「当前工作区」——从整条历史重建出模型这次该看到的消息列表。改了历史？视图自动跟着变。
  • 为什么这样设计：可回放、可压缩、可查询、可跨进程重建。崩溃恢复 = 重放日志。这是后面 compaction / session-query / projection 全部模块的基石。
深入：真实 API 与运行机理（packages/core/session/src/index.ts）
  • 核心类：class Session（index.ts:425）持有 log: SessionEvent[]；append<T>(type, data)（index.ts:604）写入 deepFreeze({ type, seq: log.length, time, data })（index.ts:627）——seq 即数组下标，必须连续从 0 起，缺一个就抛错。
  • 投影：deriveMessages()（index.ts:726）只挑日志里被标记为「模型可见 surface」的事件，按序重建消息历史；日志是真相，消息只是视图。
  • 存储层：class SessionStore（index.ts:792）负责落盘；flush(session)（index.ts:1022）把内存日志写存储；fork(source, boundary)（index.ts:1069）从某个 seq 之前切出「分支会话」——这就是「回溯重来」的原生能力。
  • Python 类比：一个只追加的 list[Event]，元素冻成 tuple；deriveMessages 像对这张表做「只选模型该行」的 SQL VIEW；fork 像 git branch 从某 commit 切新分支。
Python 实现（对照理解，可运行）
from dataclasses import dataclass, field
from typing import Any
import time

# 事件溯源日志 = 真相源。Event 用 frozen 近似 deepFreeze（不可变）
@dataclass(frozen=True)
class Event:
    seq: int
    type: str
    data: Any
    time: float = field(default_factory=time.time)

class Session:
    def __init__(self):
        self._log: list = []

    def append(self, type: str, data: Any) -> Event:
        seq = len(self._log)
        ev = Event(seq=seq, type=type, data=data)
        assert ev.seq == len(self._log), "seq 必须连续（缺一个就抛错）"
        self._log.append(ev)
        return ev

    def derive_messages(self):
        # 投影：只挑「模型可见」的事件重建消息历史（日志是真相，消息只是视图）
        out = []
        for ev in self._log:
            if ev.type == "user/message":
                out.append({"role": "user", "content": ev.data})
            elif ev.type == "assistant/message":
                out.append({"role": "assistant", "content": ev.data})
            elif ev.type == "tool/result":
                out.append({"role": "tool", "content": ev.data})
        return out

    def fork(self, boundary: int) -> "Session":
        child = Session()
        child._log = list(self._log[:boundary])   # ≈ git branch 从某 seq 切分叉
        return child

# ---- demo ----
s = Session()
s.append("user/message", "帮我写快排")
s.append("assistant/message", "好的，这是代码…")
s.append("tool/call", {"name": "bash", "args": "python sort.py"})
s.append("tool/result", "PASS")
print("投影:", s.derive_messages())
child = s.fork(2)   # 从 tool/call 之前分叉
print("分叉后长度:", len(child._log))

// AgentLoop 把自己注册成 agent 工厂
export class AgentLoop extends Service implements AgentFactory {
  static inject = ['agents','sessions','llm','tools','systemPrompt']
  ctx.effect(() => ctx.agents.setFactory(this), 'agentLoop.setFactory()')
}

// ReactLoopAgent：循环本体
private async kick() { while (await this.turn()) {} }

private async turn() {
  this.append('turn/start', ...)
  while (/* 还有活干 */) {
    await this.preStep(...)   // 领输入 + 拼提示 + agent/pre-step
    await this.step(...)      // 一次模型请求 + 工具调用
  }
  // agent/turn-stopping (serial) 判定是否停
  this.append('turn/end', ...)
}

private async preStep(target, position) {
  const claimed = this.inbox.claim(...)
  const assembly = this.loopCtx.systemPrompt.assemble(...)
  return this.dispatch.waterfall('agent/pre-step', {...},
    () => Promise.resolve({ kind:'enter', messages: claimed }))
}

private async step(assembly) {
  const request = await this.loopCtx.buildRequest(assembly) // agent/request 瀑布
  const stream = this.loopCtx.llm.stream(request)           // llm/stream 瀑布
  for await (const chunk of stream) this.append('assistant/chunk', chunk)
  // 若模型要调工具 → executeToolCalls(...)
}
  • 一个 turn（轮） = 0..N 个 step（步）；一个 step = 一次模型请求 + 其工具调用。

  • step：模型思考一次。模型可能回一句普通话，也可能回「我要调工具」——后者就进入工具执行，结果再喂回模型，开启下一个 step。

from dataclasses import dataclass, field
from typing import Any, Callable

@dataclass
class Exec:
    name: str
    args: dict
    result: Any = None

class ToolRuntime:
    def __init__(self):
        self._tools: dict = {}
        self._pre: list = []          # pre-execute waterfall
        self._post: list = []         # post-execute waterfall
        self._guards: list = []       # 单调护栏：每次必跑，不可 bypass

    def register(self, name, fn) -> Callable:
        self._tools[name] = fn
        def dispose():                # 返回注销函数（Cordis effect 风格）
            self._tools.pop(name, None)
        return dispose

    def pre_execute(self, hook):  self._pre.append(hook)
    def post_execute(self, hook): self._post.append(hook)
    def register_guard(self, hook): self._guards.append(hook)

    async def run(self, name, args):
        exec = Exec(name=name, args=args)
        await self._waterfall(self._pre, exec)        # 1) pre-execute（可否决）
        async def _noop_next():                        # 2) 单调护栏
            return None
        for g in self._guards:
            await g(exec, _noop_next)
        result = self._tools[name](**args)            # 3) execute（兼容同步/异步工具）
        if asyncio.iscoroutine(result):
            result = await result
        exec.result = result
        await self._waterfall(self._post, exec)       # 4) post-execute
        return exec

    async def _waterfall(self, hooks, exec):
        async def nxt(i=0):            # 由外到内包裹：最后一个调用真正逻辑
            if i >= len(hooks):
                return None
            return await hooks[i](exec, lambda: nxt(i+1))
        return await nxt()

from typing import Callable

_current_agent: ContextVar = ContextVar("current_agent")  # ≈ Node AsyncLocalStorage

@dataclass
class Agent:
    id: str
    persona: str
    parent: "Agent | None" = None
    scope: dict = field(default_factory=dict)   # 独立作用域：persona/工具/护栏隔离

@dataclass
class AgentHandle:
    agent: Agent
    def dispose(self):
        print(f"agent {self.agent.id} 已销毁")

class AgentRegistry:
    def __init__(self):
        self._agents: dict = {}
        self._factory = None

    def set_factory(self, f): self._factory = f

    def with_initiator(self, agent, op):
        # 把"当前 agent"钉在整条 async 链上（因果归属）
        token = _current_agent.set(agent)
        try:
            return op()
        finally:
            _current_agent.reset(token)

        a = Agent(id=id, persona=persona, parent=parent)
        self._agents[id] = a                      # register + enter + announce
        return AgentHandle(agent=a)

    def resume(self, id) -> AgentHandle:
        a = self._agents.get(id) or Agent(id=id, persona="<recovered>")  # 日志复活
        return AgentHandle(agent=a)

    def current(self): return _current_agent.get()
    def list(self):    return list(self._agents.values())
    def roots(self):   return [a for a in self._agents.values() if a.parent is None]

from dataclasses import dataclass

@dataclass
class Section:
    id: str
    order: int
    text: str

class SystemPrompt:
    def __init__(self):
        self._sections: dict = {}
        self._vars: dict = {}        # 惰性 getter：拼装时才求值
        self._hooks: list = []       # ≈ assemble 瀑布

    def section(self, id, text, order=0):
        self._sections[id] = Section(id, order, text)

    def variable(self, name, getter):
        self._vars[name] = getter

    def on_assemble(self, hook):
        self._hooks.append(hook)

    def assemble(self) -> str:
        ordered = sorted(self._sections.values(), key=lambda s: s.order)
        prompt = "\n".join(s.text for s in ordered)
        for name, getter in self._vars.items():     # {{var}} 严格插值
            token = "{{" + name + "}}"
            if token in prompt:
                prompt = prompt.replace(token, getter())
            else:
                raise KeyError(f"变量 {name} 未在模板中声明")
        for hook in self._hooks:                    # 跑 assemble 瀑布
            prompt = hook(self, prompt)
        return prompt

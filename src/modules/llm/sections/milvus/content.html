向量数据库基础

类比：传统数据库就像图书馆的目录系统，通过书名、作者等关键词找到书籍。向量数据库则像是能"理解语义"的图书管理员——你描述"一本关于太空冒险的科幻小说"，它能帮你找到最相关的内容，即使书名中没有这些词。

什么是向量嵌入（Embedding）

向量嵌入是将文本、图片、音频等非结构化数据转换成高维数值向量（数组）的过程。

Python 
# 使用Sentence-Transformers生成文本嵌入
from sentence_transformers import SentenceTransformer

# 加载预训练模型
model = SentenceTransformer('all-MiniLM-L6-v2')

# 生成嵌入向量
texts = [
    "机器学习是人工智能的一个分支",
    "深度学习使用神经网络进行学习",
    "今天天气真好，适合出去玩"
]

embeddings = model.encode(texts)
print(embeddings.shape)  # (3, 384) - 3个文本，每个384维向量

向量相似度计算

相似度度量公式适用场景
余弦相似度cos(A,B) = (A·B) / (|A|·|B|)最常用，适用于文本、推荐系统
欧氏距离d(A,B) = √∑(Ai-Bi)²适用于图像特征
内积（点积）A·B = ∑Ai·Bi适用于已归一化的向量
Python 
import numpy as np
from sklearn.metrics.pairwise import cosine_similarity

# 生成两个向量
vec1 = np.array([[0.2, 0.8, 0.1, 0.5]])
vec2 = np.array([[0.3, 0.7, 0.2, 0.4]])

# 计算余弦相似度
similarity = cosine_similarity(vec1, vec2)
print(f"余弦相似度: {similarity[0][0]:.4f}")  # 接近1表示很相似

# 计算欧氏距离
euclidean_dist = np.linalg.norm(vec1 - vec2)
print(f"欧氏距离: {euclidean_dist:.4f}")  # 越小越相似

向量检索问题

暴力搜索（Linear Search）的复杂度是O(n)，当向量数量达到百万级时太慢。因此需要近似最近邻（ANN）算法。

❌ 暴力搜索

  • 100%召回率
  • 搜索时间：O(n)
  • 百万向量：秒级延迟
  • 适用于小规模数据

✅ ANN算法

  • 95-99%召回率
  • 搜索时间：O(log n) 或 O(1)
  • 百万向量：毫秒级延迟
  • 适用于大规模数据

部署模式

模式适用场景复杂度

三种部署模式详解：

  • Milvus Lite：嵌入式模式，数据存储在本地文件（如 ./milvus_demo.db），无需启动任何服务，适合开发和测试
  • Milvus Standalone：单机服务模式，通过 Docker 部署，监听 localhost:19530，适合中小规模生产环境
  • Milvus Distributed：分布式集群模式，基于 Kubernetes 部署，支持水平扩展和高可用，适合大规模生产环境

三种模式的 API 完全兼容，代码无需修改即可切换。

基础操作

完整示例：图片相似度搜索

Python 
from pymilvus import (
    MilvusClient,
    DataType,
    CollectionSchema,
    FieldSchema
)
import numpy as np

# 1. 连接到Milvus
client = MilvusClient("./milvus_demo.db")

# 2. 定义Schema
fields = [
    FieldSchema(name="id", dtype=DataType.INT64, is_primary=True, auto_id=True),
    FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=128),
    FieldSchema(name="filename", dtype=DataType.VARCHAR, max_length=256),
]

schema = CollectionSchema(fields=fields, description="图片相似度搜索")

# 3. 创建Collection
collection_name = "image_embeddings"
if client.has_collection(collection_name):
    client.drop_collection(collection_name)

client.create_collection(
    collection_name=collection_name,
    schema=schema
)

# 4. 生成模拟的图片嵌入向量
np.random.seed(42)
num_images = 1000
embeddings = np.random.randn(num_images, 128).astype(np.float32)
filenames = [f"image_{i:04d}.jpg" for i in range(num_images)]

# 5. 插入数据
data = [
    {"embedding": emb.tolist(), "filename": fname}
    for emb, fname in zip(embeddings, filenames)
]

insert_result = client.insert(
    collection_name=collection_name,
    data=data
)
print(f"✅ 插入 {insert_result['insert_count']} 条数据")

# 6. 创建索引
index_params = client.prepare_index_params()
index_params.add_index(
    field_name="embedding",
    index_type="IVF_FLAT",
    metric_type="COSINE",
    params={"nlist": 128}
)

client.create_index(
    collection_name=collection_name,
    index_params=index_params
)

# 7. 搜索相似图片
query_embedding = np.random.randn(1, 128).astype(np.float32).tolist()

search_results = client.search(
    collection_name=collection_name,
    data=query_embedding,
    limit=5,
    output_fields=["filename"]
)

# 8. 打印结果
print("\n📸 最相似的5张图片：")
for result in search_results[0]:
    print(f"  ID: {result['id']}, 文件: {result['entity']['filename']}, 相似度: {result['distance']:.4f}")

索引算法详解

类比：索引就像是图书馆的检索系统。IVF索引像是先按类别分架，再在每个架子内搜索；HNSW索引像是建立了一个楼层导航系统，从高层快速定位到目标区域。

IVF（Inverted File Index）

IVF索引的核心思想：先聚类，再搜索。

原理

  1. 使用K-Means算法将向量聚类成若干簇（clusters）
  2. 搜索时，先找到最近的几个簇
  3. 只在这些簇内进行精确搜索
Python 
# IVF_FLAT索引参数
index_params.add_index(
    field_name="embedding",
    index_type="IVF_FLAT",     # 索引类型
    metric_type="COSINE",       # 相似度度量
    params={
        "nlist": 128           # 聚类数量（推荐：sqrt(n)到4*sqrt(n)）
    }
)

# 搜索时的参数
search_results = client.search(
    collection_name="image_embeddings",
    data=query_embedding,
    limit=5,
    search_params={
        "metric_type": "COSINE",
        "params": {"nprobe": 16}  # 搜索时探测的簇数量
    }
)

IVF变体

类型特点适用场景
IVF_FLAT精确存储原始向量精度要求高，内存充足
IVF_SQ8量化压缩，节省内存内存有限，可接受轻微精度损失
IVF_PQ乘积量化，大幅压缩超大规模数据，内存紧张

HNSW（Hierarchical Navigable Small World）

HNSW的核心思想：基于图的导航，逐层搜索。

原理

  1. 构建多层图结构，每层都是一个导航图
  2. 搜索从最高层开始，逐层向下
  3. 每层内进行贪心搜索，找到最近邻
Python 
# HNSW索引参数
index_params.add_index(
    field_name="embedding",
    index_type="HNSW",         # 索引类型
    metric_type="COSINE",
    params={
        "M": 16,                # 每层的最大连接数（推荐：16-64）
        "efConstruction": 200  # 构建时的搜索范围（推荐：100-500）
    }
)

# 搜索时的参数
search_results = client.search(
    collection_name="image_embeddings",
    data=query_embedding,
    limit=5,
    search_params={
        "metric_type": "COSINE",
        "params": {"ef": 100}  # 搜索时的搜索范围
    }
)

HNSW参数详解：

  • M：每个节点的最大连接数。越大召回率越高，但内存占用越大
  • efConstruction：构建索引时的搜索范围。越大索引质量越好，但构建时间越长
  • ef：搜索时的搜索范围。越大召回率越高，但搜索速度越慢

索引选择指南

索引类型速度召回率内存适用场景
FLAT慢100%高小数据集（<10万），精度要求极高
IVF_FLAT中高高中等规模，平衡速度和精度
IVF_SQ8快中中大规模数据，内存有限
HNSW快高高频繁查询，低延迟要求
SCANN快高中大规模数据，平衡性能
DISKANN中高低超大规模数据，内存受限

选择建议：

  • 学习阶段：用 IVF_FLAT，参数少，容易理解
  • 生产环境：用 HNSW，性能最好
  • 内存紧张：用 IVF_SQ8 或 DISKANN
  • 超大规模（亿级）：用 IVF_PQ 或 DISKANN
  • 不确定选哪个：AUTOINDEX 会自动选择合适的索引类型

# Milvus 2.5+ 全文搜索示例（基于 tantivy 的 BM25）
from pymilvus import MilvusClient, DataType

client = MilvusClient("./milvus_demo.db")

# 创建带全文搜索功能的Schema
schema = client.create_schema()
schema.add_field("id", DataType.INT64, is_primary=True, auto_id=True)
schema.add_field("text", DataType.VARCHAR, max_length=65535,
                 enable_analyzer=True)  # 启用分词器
schema.add_field("sparse_vector", DataType.SPARSE_FLOAT_VECTOR)

# 创建BM25函数将文本转换为稀疏向量
from pymilvus import Function, FunctionType
bm25_fn = Function(
    name="text_to_bm25",
    input_field_names=["text"],
    output_field_names=["sparse_vector"],
    function_type=FunctionType.BM25,
)
schema.add_function(bm25_fn)

# 全文搜索（关键词检索）
results = client.search(
    collection_name="my_docs",
    data=["机器学习"],
    anns_field="sparse_vector",
    limit=5
)

Python集成

与LangChain集成

Python 
from langchain_milvus import Milvus
from langchain_openai import OpenAIEmbeddings
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.document_loaders import TextLoader

# 加载文档
loader = TextLoader("./document.txt")
documents = loader.load()

# 分割文本
text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50
)
docs = text_splitter.split_documents(documents)

# 创建向量存储
vectorstore = Milvus.from_documents(
    documents=docs,
    embedding=OpenAIEmbeddings(),
    collection_name="my_documents",
    connection_args={"host": "localhost", "port": 19530}
)

# 相似度搜索
results = vectorstore.similarity_search("什么是机器学习？", k=3)

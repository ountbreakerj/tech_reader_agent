对齐训练：RLHF 与 DPO

从 SFT 到 PPO、DPO、GRPO——让大模型学会"说人话"

1. 对齐训练概述

经过预训练和 SFT（Supervised Fine-Tuning）后的模型虽然能完成指令，但仍可能产生有害内容、编造事实或拒绝合理请求。对齐训练的目标是让模型的行为符合人类的价值观和偏好。

为什么 SFT 不够？

SFT 教会模型"如何回答"，但没有教模型"哪种回答更好"。对齐训练通过引入人类偏好信号，优化模型在多个候选回答之间做出更好的选择。

阶段方法训练信号目标
1. 预训练Next Token Prediction海量文本语言建模能力
2. SFT指令微调高质量指令-回答对指令遵循能力
3. 对齐RLHF / DPO / GRPO人类偏好（排名/评分）有用、安全、诚实
Anthropic 的研究发现，RLHF 训练后的 Claude 模型在"有帮助"和"无害"之间找到了更好的平衡点——既能拒绝真正有害的请求，又不会过度拒绝合理的问题。

2. RLHF 完整流程

RLHF（Reinforcement Learning from Human Feedback）包含三个阶段：SFT 训练、Reward Model 训练、PPO 强化学习优化。

阶段一：SFT（已在前置课程中介绍）

在高质量指令数据上微调预训练模型，得到 SFT 模型，作为后续 RL 训练的起点。

阶段二：训练 Reward Model

收集人类偏好数据：对同一个 prompt 的多个回答进行排序（如 A > B > C）。
用排序数据训练 Reward Model，使其对"好回答"打高分，"差回答"打低分。

阶段三：PPO 强化学习

将 SFT 模型作为策略模型，Reward Model 的打分作为奖励信号，用 PPO 算法优化策略。
加入 KL 散度惩罚，防止策略偏离 SFT 模型太远（避免奖励黑客攻击）。

PPO 目标函数：
max E[R(x, y) - beta * KL(pi(y|x) || pi_ref(y|x))]
R = Reward Model 打分, pi = 策略模型, pi_ref = SFT 参考模型

Stage 2: Reward Model 训练代码（TRL）

from trl import RewardTrainer, RewardConfig
from transformers import AutoModelForSequenceClassification, AutoTokenizer

# 加载基础模型，添加标量奖励头
model = AutoModelForSequenceClassification.from_pretrained(
    "meta-llama/Llama-3.1-8B",

# 偏好数据格式：每条包含 prompt + chosen + rejected

training_args = RewardConfig(

    logging_steps=10,
    save_strategy="epoch",

trainer = RewardTrainer(
    model=model,

Stage 3: PPO 训练代码（TRL experimental）

TRL 新版将 PPO 放在 trl.experimental.ppo，接口遵循 Transformers Trainer 风格：配置继承 TrainingArguments，奖励模型和值模型在构造训练器时传入，训练由 trainer.train() 驱动。PPO 仍属实验功能；生产项目可优先评估 DPO 或 GRPO。

from trl.experimental.ppo import PPOTrainer, PPOConfig
from transformers import AutoModelForCausalLM, AutoModelForSequenceClassification, AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("sft_model_path")
policy_model = AutoModelForCausalLM.from_pretrained("sft_model_path")
ref_model = AutoModelForCausalLM.from_pretrained("sft_model_path")
reward_model = AutoModelForSequenceClassification.from_pretrained("./reward_model")
value_model = AutoModelForSequenceClassification.from_pretrained("./value_model")

ppo_config = PPOConfig(
    output_dir="./ppo_output",
    learning_rate=1.4e-5,
    per_device_train_batch_size=8,
    num_train_epochs=1,
    gradient_accumulation_steps=8,
)

ppo_trainer = PPOTrainer(
    args=ppo_config,
    model=policy_model,
    ref_model=ref_model,
    reward_model=reward_model,
    value_model=value_model,
    processing_class=tokenizer,
    train_dataset=prompt_dataset,
)
ppo_trainer.train()
PPO 训练的工程复杂度很高：需要同时维护 4 个模型（策略模型、参考模型、Reward Model、Value 模型），显存需求约为普通 SFT 的 4 倍。这也是 DPO 等方法兴起的重要原因。

3. DPO（Direct Preference Optimization）

DPO 的核心洞察：可以直接从偏好数据中推导出最优策略，无需训练 Reward Model，无需 RL 循环。它将 RLHF 的目标重写为一个简单的分类损失。

DPO 损失函数：
L = -E[log sigma(beta * (log pi(y_w|x)/pi_ref(y_w|x) - log pi(y_l|x)/pi_ref(y_l|x)))]
y_w = 偏好回答 (chosen), y_l = 非偏好回答 (rejected)

DPO 训练代码（TRL）

from trl import DPOTrainer, DPOConfig
from transformers import AutoModelForCausalLM

# 加载 SFT 模型（同时作为策略模型和参考模型）
model = AutoModelForCausalLM.from_pretrained(
    "sft_model_path",
    torch_dtype=torch.bfloat16,
)
ref_model = AutoModelForCausalLM.from_pretrained(
    "sft_model_path",
    torch_dtype=torch.bfloat16,
)

dpo_config = DPOConfig(
    output_dir="./dpo_model",
    per_device_train_batch_size=4,
    learning_rate=5e-7,        # DPO 学习率要小，通常 1e-7 ~ 5e-6
    num_train_epochs=3,
    beta=0.1,                  # KL 约束强度，控制偏离程度
    loss_type="sigmoid",       # 标准 DPO loss
    bf16=True,
    max_length=2048,
    max_prompt_length=1024,
    logging_steps=10,
    save_strategy="steps",
    save_steps=500,
)

# 偏好数据格式
# {"prompt": "...", "chosen": "...", "rejected": "..."}

trainer = DPOTrainer(
    model=model,
    ref_model=ref_model,
    args=dpo_config,
    train_dataset=preference_dataset,
    processing_class=tokenizer,
)
trainer.train()
DPO 的 beta 参数非常关键：beta 越大，模型越保守（越接近 SFT 模型）；beta 越小，模型越激进（可能过拟合偏好数据）。推荐从 0.1 开始尝试。

4. ORPO（Odds Ratio Preference Optimization）

ORPO 进一步简化了对齐训练——它不需要参考模型，在 SFT 的交叉熵损失基础上直接加入偏好优化目标，一步完成 SFT + 对齐。

ORPO 捩失 = SFT 损失(chosen) + lambda * OR 损失
OR = log(sigma(log_odds(y_w) - log_odds(y_l)))
log_odds(y) = log P(y|x) / (1 - P(y|x)) 
from trl import ORPOTrainer, ORPOConfig

orpo_config = ORPOConfig(
    output_dir="./orpo_model",
    per_device_train_batch_size=4,
    learning_rate=8e-6,
    beta=0.1,            # OR 损失权重
    num_train_epochs=3,
    bf16=True,
    max_length=2048,
)

# ORPO 不需要 ref_model 参数！
trainer = ORPOTrainer(
    model=model,            # 只需一个模型
    args=orpo_config,
    train_dataset=preference_dataset,
    processing_class=tokenizer,
)
trainer.train()
ORPO 的优势：显存只需 DPO 的约 60%（无需加载参考模型），训练流程更简单。实验表明 ORPO 在 AlpacaEval 等基准上能达到与 DPO 相当甚至更好的效果。

5. KTO（Kahneman-Tversky Optimization）

KTO 受前景理论启发：人类对损失的敏感度高于收益。它只需要 正/负标签（而非配对的 chosen/rejected），大大降低了数据收集成本。

KTO vs DPO 数据需求对比

DPO：需要配对数据 (prompt, chosen, rejected)——同一个 prompt 必须有好和差两个回答
KTO：只需要 (prompt, response, label)——label 是好(1)或差(0)，不需要配对

from trl import KTOTrainer, KTOConfig

kto_config = KTOConfig(
    output_dir="./kto_model",
    per_device_train_batch_size=4,
    learning_rate=5e-7,
    num_train_epochs=3,
    bf16=True,
    max_length=2048,
    beta=0.1,
    desirable_weight=1.0,    # 正样本损失权重
    undesirable_weight=1.0,  # 负样本损失权重
)

# KTO 数据格式：不需要配对
# {"prompt": "...", "completion": "...", "label": true/false}

trainer = KTOTrainer(
    model=model,
    ref_model=ref_model,
    args=kto_config,
    train_dataset=kto_dataset,  # 只需 prompt + completion + bool label
    processing_class=tokenizer,
)
trainer.train()
KTO 特别适合从真实用户反馈中学习——你可以直接从用户的点赞/点踩数据中构建训练集，不需要人工标注配对的偏好数据。

6. GRPO（Group Relative Policy Optimization）

GRPO 由 DeepSeek 团队提出，在 DeepSeek-R1 训练中大放异彩。它的核心创新是：用同一 prompt 的多个采样的相对排名作为奖励信号，无需独立的 Value 模型。

GRPO 工作流程

1. 对每个 prompt，采样 G 个回答（如 G=16）
2. 用 Reward Model 或规则奖励对每个回答打分
3. 在组内做标准化：advantage = (reward - mean) / std
4. 用 PPO 风格的 clipped objective 更新策略，但用组内相对 advantage 替代 GAE

GRPO 目标：
L = E[min(r_t * A_t, clip(r_t, 1-eps, 1+eps) * A_t)] - beta * KL
r_t = pi(y|x) / pi_old(y|x), A_t = (R_i - mean(R)) / std(R) 
import torch.nn.functional as F

def grpo_loss(model, ref_model, prompts, tokenizer, reward_fn,
             n_samples=16, beta=0.04, eps=0.2):
    """GRPO 核心算法实现"""
    # 1. 对每个 prompt 采样 G 个回答
    all_responses = []
    for prompt in prompts:
        responses = model.generate(
            prompt, num_return_sequences=n_samples,
            temperature=0.7, do_sample=True,
            max_new_tokens=512,
        )
        all_responses.append(responses)

    # 2. 计算每个回答的奖励
    rewards = reward_fn(all_responses)  # (B, G)

    # 3. 组内标准化 advantage
    advantages = (rewards - rewards.mean(dim=1, keepdim=True)) \
               / (rewards.std(dim=1, keepdim=True) + 1e-8)

    # 4. 计算策略比率和 KL 惩罚
    log_probs = model.log_prob(all_responses)
    ref_log_probs = ref_model.log_prob(all_responses).detach()
    log_ratio = log_probs - ref_log_probs  # 对数策略比率

    # 5. PPO 风格 clipped loss
    ratio = torch.exp(log_probs - log_probs.detach())  # 新策略 / 旧策略
    surr1 = ratio * advantages
    surr2 = torch.clamp(ratio, 1 - eps, 1 + eps) * advantages
    policy_loss = -torch.min(surr1, surr2).mean()

    # 6. KL 散度惩罚
    kl_loss = beta * log_ratio.mean()

    return policy_loss + kl_loss
DeepSeek-R1 使用 GRPO 训练时，reward 信号主要来自规则奖励（如数学题答案正确性、代码测试通过率），而非神经网络 Reward Model。这使得训练更加稳定和可扩展。

7. 对齐方法全面对比

方法是否需要 Reward Model是否需要参考模型数据格式训练复杂度显存需求
RLHF (PPO)是是偏好排序高（4 个模型）极高
DPO否是chosen/rejected 对低（2 个模型）中
ORPO否否chosen/rejected 对低（1 个模型）低
KTO否是正/负标签低（2 个模型）中
GRPO可选（规则奖励）是prompt + 奖励函数中（2 个模型 + 采样）中高
2026 年的实践建议：数据充足且需要最高质量时用 PPO/DPO；数据有限或想简化流程用 ORPO/KTO；有明确规则奖励（数学、代码）时优先考虑 GRPO。DeepSeek V4-Pro 即采用 GRPO + 规则奖励训练策略。

8. 实战：完整的 SFT -> DPO 流程

以下展示使用 TRL 1.7.0（截至 2026-08）完成从 SFT 到 DPO 的完整对齐流程。

Step 1: SFT 训练

from trl import SFTTrainer, SFTConfig
from transformers import AutoModelForCausalLM, AutoTokenizer

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3.1-8B", torch_dtype=torch.bfloat16,
)
tokenizer = AutoTokenizer.from_pretrained("meta-llama/Llama-3.1-8B")
tokenizer.pad_token = tokenizer.eos_token

sft_config = SFTConfig(
    output_dir="./sft_model",
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,
    learning_rate=2e-5,
    num_train_epochs=3,
    bf16=True,
    max_seq_length=2048,
    logging_steps=10,
    save_strategy="epoch",
    dataset_text_field="text",
)

trainer = SFTTrainer(
    model=model, args=sft_config,
    train_dataset=sft_dataset, processing_class=tokenizer,
)
trainer.train()
trainer.save_model("./sft_model")

Step 2: DPO 对齐

# 加载 SFT 模型
sft_model = AutoModelForCausalLM.from_pretrained(
    "./sft_model", torch_dtype=torch.bfloat16,

    "./sft_model", torch_dtype=torch.bfloat16,

dpo_config = DPOConfig(

# 偏好数据示例
# dataset 格式: {"prompt": "...", "chosen": "...", "rejected": "..."}

trainer = DPOTrainer(
    model=sft_model, ref_model=ref_model,

trainer.save_model("./aligned_model")
DPO 训练中的常见陷阱：学习率过大会导致模型退化；beta 过小会导致 reward hacking（模型找到 shortcut 提高 chosen 概率但质量没提升）；偏好数据质量比数量更重要，通常几万条高质量数据就够了。

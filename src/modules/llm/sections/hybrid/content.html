为什么需要混合检索

单一检索的局限

❌ 纯向量检索

  • 擅长语义匹配
  • 无法精确匹配关键词
  • 对专有名词、编号支持差
  • 示例：搜"订单号123"可能找不到

❌ 纯文本检索（BM25）

  • 擅长精确关键词匹配
  • 无法理解语义
  • 同义词、近义词匹配差
  • 示例：搜"电脑"找不到"计算机"

混合检索的优势

类比：混合检索就像是既会看关键词又懂语义的超级图书管理员——既能在目录中快速定位（关键词匹配），又能理解你真正想要找什么书（语义匹配）。
检索方式关键词匹配语义理解适用场景
MySQL (SQL)✅ 精确❌ 不支持结构化数据查询
BM25✅ 模糊❌ 不支持全文搜索（ES/Milvus 2.5+）
MySQL FULLTEXT✅ 模糊❌ 不支持注意：使用TF-IDF变体，非真正BM25
向量检索⚠️ 弱✅ 理解语义相似度
混合检索✅ 精确✅ 理解生产环境（推荐）
MySQL FULLTEXT的限制：MySQL的FULLTEXT搜索使用的是TF-IDF变体评分算法，不是真正的BM25。如果需要标准BM25评分，应使用Elasticsearch/OpenSearch或Milvus 2.5+的原生全文检索（基于tantivy引擎）。

多路召回算法

多路召回原理：同时使用多种检索方式（MySQL SQL + BM25 + 向量检索），分别召回一批结果，然后用融合算法合并排序，得到最终结果。

Reciprocal Rank Fusion (RRF)

RRF是最常用的多路召回融合算法：根据每个结果在各路检索中的排名来计算综合分数。

Python 
def reciprocal_rank_fusion(rankings: list[list[int]], k: int = 60) -> dict[int, float]:
    """
    Reciprocal Rank Fusion (RRF) 算法

    参数:
        rankings: 多路检索的排名列表，每个列表是一组文档ID
        k: 平滑参数（通常设为60）

    返回:
        每个文档的RRF分数
    """
    fused_scores = {}

    for ranking in rankings:
        for rank, doc_id in enumerate(ranking, start=1):
            if doc_id not in fused_scores:
                fused_scores[doc_id] = 0
            # RRF公式: 1 / (k + rank)
            fused_scores[doc_id] += 1 / (k + rank)

    return fused_scores

# 示例：3路召回融合
# MySQL召回：文档ID [1, 3, 5, 7, 9]
# BM25召回：文档ID [2, 3, 5, 8, 10]
# 向量召回：文档ID [3, 4, 5, 6, 7]

rankings = [
    [1, 3, 5, 7, 9],
    [2, 3, 5, 8, 10],
    [3, 4, 5, 6, 7]
]

rrf_scores = reciprocal_rank_fusion(rankings)

# 按分数排序
sorted_docs = sorted(rrf_scores.items(), key=lambda x: x[1], reverse=True)

print("融合结果：")
for doc_id, score in sorted_docs[:5]:
    print(f"文档{doc_id}: 分数={score:.4f}")
# 文档5: 分数=0.0491 (出现在所有3路中)
# 文档3: 分数=0.0486 (出现在所有3路中)

线性组合（Linear Combination）

Python
def linear_combination_fusion(
    mysql_scores: dict,
    bm25_scores: dict,
    vector_scores: dict,
    weights: tuple = (0.3, 0.3, 0.4)  # 各路权重
) -> dict[int, float]:
    """
    线性组合融合：加权平均各路分数

    参数:
        weights: (MySQL权重, BM25权重, 向量权重)
    """
    all_docs = set(mysql_scores) | set(bm25_scores) | set(vector_scores)
    fused_scores = {}

    for doc_id in all_docs:
        score = (
            weights[0] * mysql_scores.get(doc_id, 0) +
            weights[1] * bm25_scores.get(doc_id, 0) +
            weights[2] * vector_scores.get(doc_id, 0)
        )
        fused_scores[doc_id] = score

    return fused_scores
分数归一化问题：使用线性组合时，不同检索方法的分数量纲差异很大——余弦相似度有界 [0, 1]，但BM25分数无上界。不做归一化会导致某一路主导融合结果。常用归一化方法：
  • Min-Max归一化：将分数映射到 [0, 1]，简单直观
  • Z-Score归一化：基于均值和标准差标准化，对异常值鲁棒
  • Rank-Based归一化：用排名代替原始分数，天然消除量纲差异
RRF算法天然基于排名，不受此问题影响，因此在多路召回场景中更受推荐。

数据同步方案

MySQL → Milvus实时同步

Python
import mysql.connector
from pymilvus import MilvusClient
from sentence_transformers import SentenceTransformer

class HybridSearchSync:
    """MySQL + Milvus混合检索同步"""

    def __init__(self):
        self.mysql = mysql.connector.connect(
            host="localhost", user="root",
            password="password", database="rag_db"
        )
        self.milvus = MilvusClient("./milvus_rag.db")
        self.embed_model = SentenceTransformer("BAAI/bge-base-zh-v1.5")
        self.last_synced_id = 0

    def sync增量(self):
        """增量同步MySQL到Milvus"""
        cursor = self.mysql.cursor(dictionary=True)
        cursor.execute(
            "SELECT id, title, content FROM documents WHERE id > %s LIMIT 1000",
            (self.last_synced_id,)
        )
        rows = cursor.fetchall()

        if not rows:
            return 0

        # 生成向量
        embeddings = self.embed_model.encode([r["content"] for r in rows]).tolist()

        # 写入Milvus
        data = [
            {"id": r["id"], "embedding": emb, "title": r["title"]}
            for r, emb in zip(rows, embeddings)
        ]
        self.milvus.insert(collection_name="documents", data=data)

        self.last_synced_id = rows[-1]["id"]
        return len(rows)

class HybridRetriever:
    """完整混合检索系统"""

    def __init__(self, mysql_conn, milvus_client, embed_model):
        self.mysql = mysql_conn
        self.milvus = milvus_client
        self.embed_model = embed_model

    def retrieve(self, query: str, top_k: int = 10) -> list:
        """多路召回 + 融合排序"""

        # 1. MySQL结构化查询
        mysql_results = self.mysql_search(query)

        # 2. BM25全文检索
        bm25_results = self.bm25_search(query)

        # 3. 向量语义检索
        vector_results = self.vector_search(query)

        # 4. RRF融合
        rankings = [
            [r["id"] for r in mysql_results],
            [r["id"] for r in bm25_results],
            [r["id"] for r in vector_results],
        ]
        rrf_scores = reciprocal_rank_fusion(rankings)

        # 5. 返回Top-K结果
        sorted_ids = sorted(rrf_scores, key=rrf_scores.get, reverse=True)[:top_k]
        return self.get_documents_by_ids(sorted_ids)

    def mysql_search(self, query):
        """MySQL关键词搜索"""
        cursor = self.mysql.cursor(dictionary=True)
        sql = "SELECT id, title, content FROM documents WHERE MATCH(title, content) AGAINST(%s IN BOOLEAN MODE)"
        cursor.execute(sql, (query,))
        return cursor.fetchall()

    def vector_search(self, query):
        """Milvus向量搜索"""
        embedding = self.embed_model.encode([query]).tolist()
        results = self.milvus.search(
            collection_name="documents",
            data=embedding,
            limit=10
        )
        return [{"id": r["id"], "score": r["distance"]} for r in results[0]]

原生混合检索（Native Hybrid Search）

前面的方案需要维护MySQL + Milvus两套系统并手动同步数据，架构复杂。现代向量数据库已原生支持混合检索，大幅简化架构：

数据库混合检索支持特点
Milvus 2.5+dense + sparse + 全文BM25基于tantivy引擎，单库实现完整混合检索
Weaviatedense + BM25原生混合搜索，API简洁
Qdrantdense + sparse支持稀疏向量与稠密向量联合检索
Pineconedense + sparse全托管服务，混合检索开箱即用
架构简化建议：如果使用Milvus 2.5+，可以直接用单个Milvus实例替代MySQL + Milvus双库方案，同时获得dense向量检索 + sparse检索 + 全文BM25检索三路召回能力，消除数据同步的复杂性。对于新项目，优先考虑原生混合检索方案。

Elasticsearch / OpenSearch

在生产环境中，Elasticsearch和OpenSearch（AWS维护的ES开源分支）是BM25全文检索的行业标准方案，广泛应用于搜索引擎、日志分析和RAG系统。

为什么生产环境推荐ES：
  • 真正的BM25实现：标准BM25评分，而非MySQL的TF-IDF变体
  • 丰富的查询DSL：支持布尔查询、模糊匹配、同义词、自定义分析器
  • 向量检索支持：ES 8.x+原生支持dense_vector和kNN搜索
  • 可扩展性：分布式架构，支持PB级数据
典型生产架构：Elasticsearch（BM25全文检索 + 结构化过滤）+ Milvus（向量语义检索），通过RRF或线性组合融合。这套组合是目前业界最常见的生产级RAG检索架构。

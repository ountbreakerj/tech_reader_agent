多模态 RAG

让 RAG 系统理解图片、表格、图表与公式 — 从文档解析到跨模态检索的完整方案

1. 为什么需要多模态 RAG

传统 RAG（Retrieval-Augmented Generation）系统专注于纯文本的检索与生成，但真实世界的文档远非纯文字构成。企业年报中嵌入了大量图表、法律文书中包含签章扫描件、医疗报告中有影像图片、学术论文中充满公式和示意图 — 这些非文本信息往往承载着关键语义。

纯文本 RAG 的局限

  • 信息丢失：仅提取文字会导致图表中的趋势、表格中的数值关系、公式中的逻辑完全丢失
  • 上下文断裂：一张图表配文通常只有简短标题，脱离图像后标题无法独立表达含义
  • 用户期望落差：用户问"这个季度的营收趋势如何？"时，期望系统能读懂折线图

现实文档中的多模态数据

企业文档中 80% 的关键信息以非纯文本形式存在 McKinsey 的报告指出，企业知识管理中，结构化表格、可视化图表和扫描图片占据信息总量的绝大多数。纯文本 RAG 只触及了冰山一角。
文档类型关键多模态元素典型场景
金融报告折线图、柱状图、财务表格、KPI 仪表盘年报分析、投研报告
医疗文档CT/MRI 影像、检验报告表格、处方图片辅助诊断、病历检索
法律文书签章扫描件、证据图片、表格化条款合规审查、案件检索
学术论文公式、实验图表、流程图、算法伪代码文献综述、技术调研
产品手册产品图片、规格参数表、安装示意图客服问答、技术支持

多模态 RAG 的核心目标是：将文本、图像、表格、公式等不同模态的信息统一纳入检索与生成流程，让系统具备真正的"文档理解"能力。

2. 文档解析技术栈

多模态 RAG 的第一步是将复杂文档"拆解"为可处理的元素。不同格式的文档需要不同的解析工具。

2.1 PDF 解析

PDF 是企业文档最普遍的格式，但解析难度很高 — PDF 本质上是一种排版描述语言，而非结构化数据格式。

工具类型特点适用场景
PyMuPDF (fitz) 开源 速度极快，C 底层实现，支持提取文本/图片/矢量图形 大批量 PDF 处理、图像提取
PDFPlumber 开源 精确的表格检测与提取，基于 PDF 坐标系统 包含大量表格的文档
unstructured.io 开源 + 云服务 自动检测文档元素类型（标题/段落/表格/图片），支持多种格式 通用文档解析 pipeline
Docling（IBM 开源） 开源 深度学习驱动的文档解析，理解页面布局，支持 DOCX/PPT/PDF 复杂版式文档、需要布局理解
LlamaParse 商业 API LLM 增强解析，将复杂页面转为 Markdown 快速原型开发

2.2 表格提取

表格是最常见也最难正确提取的元素。错误的表格解析会导致数据完全失真。

# 结构化 JSON 表示
def table_to_json(table):
    if not table or len(table) < 2:
        return {}
    headers = table[0]
    rows = table[1:]
    return [dict(zip(headers, row)) for row in rows]

3. ColPali：文档图像检索

ColPali 是一种革命性的文档检索方法，它完全跳过了传统的 OCR + 文本索引流程，直接将文档页面作为图像进行检索。

3.1 核心原理

ColPali 将 ColBERT 的 late interaction 思想应用到文档图像检索领域：

  1. 文档页面图像化：将每一页文档渲染为图像，无需任何 OCR 或文本提取预处理
  2. 视觉编码：使用 PaliGemma 视觉语言模型将页面图像编码为一组 token 级别的向量
  3. 查询编码：文本查询同样被编码为 token 级别的向量
  4. MaxSim 评分：对查询的每个 token，找到文档中相似度最高的 token，求和得到最终相关性分数
# ColPali 检索示例
from colpali_engine.models import ColPali, ColPaliProcessor
from PIL import Image
import torch

# 加载模型
model = ColPali.from_pretrained("vidore/colpali-v1.3")
processor = ColPaliProcessor.from_pretrained("vidore/colpali-v1.3")

# 将文档页面渲染为图像
page_image = Image.open("page_001.png")

# 编码文档页面 -> 得到 token 级 embeddings
doc_inputs = processor.process_images([page_image])
doc_embeddings = model(**doc_inputs)  # shape: (1, num_tokens, dim)

# 编码查询
query = "2025年第三季度的营收增长趋势"
query_inputs = processor.process_queries([query])
query_embeddings = model(**query_inputs)  # shape: (1, num_tokens, dim)

# MaxSim 评分
# 对 query 的每个 token，取与 doc 所有 token 的最大相似度，然后求和
scores = torch.einsum("bnd,bmd->bnm", query_embeddings, doc_embeddings)
max_sim = scores.max(dim=2).values  # query 每个 token 的最大匹配
relevance_score = max_sim.sum(dim=1)  # 求和得到最终分数
print(f"相关性得分: {relevance_score.item():.4f}")

3.2 ColPali 的优势

优势说明
保留布局信息直接处理图像，页面的空间布局、字体大小、颜色等视觉信号都被编码
无需预处理省去 OCR、版面分析、文本清洗等复杂 pipeline，大幅降低工程复杂度
天然多语言视觉模型不依赖特定语言的 tokenizer，对中文、日文、阿拉伯文等都有效
表格/图表友好表格结构和图表趋势在视觉层面更容易被理解
端到端从文档图像到检索结果，单一模型完成，无需组装多个组件
ColPali 适用场景 文档版式复杂（如杂志、海报、信息图）、表格密集、多语言混合、或者需要快速搭建原型而不愿投入 OCR pipeline 建设的场景。对于纯文本文档，传统方法仍然高效。

4.2 用 VLM 做文档问答

import base64
from openai import OpenAI

client = OpenAI()

def encode_image(image_path):
    with open(image_path, "rb") as f:
        return base64.b64encode(f.read()).decode("utf-8")

def vlm_document_qa(image_path, question):
    """使用 VLM 对文档图像进行问答"""
    b64_image = encode_image(image_path)

    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {
                "role": "system",
                "content": "你是一个文档分析专家。请根据提供的文档图像回答问题，"
                           "如果涉及数据请给出精确数字。"
            },
            {
                "role": "user",
                "content": [
                    {"type": "text", "text": question},
                    {
                        "type": "image_url",
                        "image_url": {
                            "url": f"data:image/png;base64,{b64_image}",
                            "detail": "high"
                        }
                    }
                ]
            }
        ],
        max_tokens=1000
    )
    return response.choices[0].message.content

# 使用示例
answer = vlm_document_qa(
    "revenue_chart.png",
    "请描述2025年各季度的营收变化趋势，Q3相比Q2增长了多少？"
)
print(answer)
# 输出: 从图表中可以看到，2025年营收呈持续上升趋势。
#       Q1营收约1.2亿元，Q2约1.35亿元，Q3达到1.58亿元。
#       Q3相比Q2增长约17%，增速明显加快...

5. 多模态 Embedding

多模态 RAG 的检索能力取决于 embedding 模型 — 它需要将不同模态（文本、图像、表格）映射到同一个向量空间，使跨模态检索成为可能。

5.1 CLIP：文本-图像对齐

CLIP（Contrastive Language-Image Pre-training）是 OpenAI 提出的经典模型，通过对比学习将文本和图像对齐到统一的 embedding 空间。

import torch
from transformers import CLIPProcessor, CLIPModel
from PIL import Image

model = CLIPModel.from_pretrained("openai/clip-vit-large-patch14")
processor = CLIPProcessor.from_pretrained("openai/clip-vit-large-patch14")

# 图像 embedding
image = Image.open("chart.png")
image_inputs = processor(images=image, return_tensors="pt")
image_embedding = model.get_image_features(**image_inputs)  # (1, 768)

# 文本 embedding
text_inputs = processor(text=["营收增长趋势图"], return_tensors="pt")
text_embedding = model.get_text_features(**text_inputs)      # (1, 768)

# 计算相似度（余弦相似度）
similarity = torch.cosine_similarity(image_embedding, text_embedding)
print(f"图文相似度: {similarity.item():.4f}")  # 如: 0.3127

5.2 BGE-VL：多模态 Embedding

BGE-VL 是智源研究院（BAAI）推出的多模态 embedding 模型，在 CLIP 基础上进行了中文优化和文档场景增强。

from FlagEmbedding import BGEM3FlagModel, visual_embedder

# 使用 BGE-VL 进行多模态 embedding
embedder = visual_embedder.VisualizedFlagModel(
    "BAAI/bge-vl-base",
    query_instruction_for_retrieval="为这个表示生成检索嵌入："
)

# 统一 embedding — 文本、图像、表格都进入同一向量空间
text_emb = embedder.encode(["2025年Q3营收达到1.58亿元"])     # 文本
image_emb = embedder.encode([["revenue_chart.png"]])           # 图像
table_emb = embedder.encode([["financial_table_snapshot.png"]]) # 表格截图

# 三者在同一空间中，可以直接计算相似度
from numpy import dot
from numpy.linalg import norm

sim_text_image = dot(text_emb[0], image_emb[0]) / (norm(text_emb[0]) * norm(image_emb[0]))
print(f"文本-图表相似度: {sim_text_image:.4f}")

5.3 统一 Embedding 空间

核心思想 将文本片段、表格截图、图表图片、公式渲染图全部通过同一个 embedding 模型编码，存入同一个向量数据库。查询时，无论是文本查询还是图像查询，都能命中所有相关模态的内容。

6.3 生成阶段

生成阶段将检索到的多模态上下文组装成 prompt，交给 VLM 或 LLM 生成回答。

多模态 RAG 生成示例
from langchain_core.messages import HumanMessage

def multimodal_generate(query, retrieved_contexts):
    """
    retrieved_contexts: list of dict
      - type: "text" / "image" / "table"
      - content: 文本内容 或 图像路径
      - metadata: 来源信息
    """
    content_parts = []

    # 组装多模态上下文
    for ctx in retrieved_contexts:
        if ctx["type"] == "text":
            content_parts.append({
                "type": "text",
                "text": f"[文本来源: {ctx['metadata']['source']}]\n{ctx['content']}"
            })
        elif ctx["type"] in ("image", "table"):
            content_parts.append({
                "type": "text",
                "text": f"[{ctx['type']}来源: {ctx['metadata']['source']}]"
            })
            content_parts.append({
                "type": "image_url",
                "image_url": {"url": f"data:image/png;base64,{ctx['content']}"}
            })

    # 添加用户查询
    content_parts.append({
        "type": "text",
        "text": f"\n问题: {query}\n请根据以上多模态上下文回答问题。"
    })

    message = HumanMessage(content=content_parts)
    response = vlm.invoke([system_prompt, message])
    return response.content

7. 实战案例：金融报告 RAG

以解析上市公司年报 PDF（含大量财务图表和数据表格）为例，构建完整的多模态 RAG 系统。

7.1 文档解析

import fitz  # PyMuPDF
import pdfplumber
from pathlib import Path
import json

def parse_annual_report(pdf_path):
    """解析年报 PDF，分离文本、表格、图像"""
    result = {"texts": [], "tables": [], "images": []}

    # 提取图像
    doc = fitz.open(pdf_path)
    for page_idx, page in enumerate(doc):
        # 提取页面文本
        text = page.get_text("text")
        if text.strip():
            result["texts"].append({
                "page": page_idx + 1,
                "content": text.strip(),
                "type": "text"
            })

        # 提取嵌入图像
        for img_idx, img in enumerate(page.get_images(full=True)):
            xref = img[0]
            base_image = doc.extract_image(xref)
            img_bytes = base_image["image"]
            img_path = f"extracted_images/p{page_idx+1}_img{img_idx+1}.png"
            Path(img_path).parent.mkdir(exist_ok=True)
            with open(img_path, "wb") as f:
                f.write(img_bytes)
            result["images"].append({
                "page": page_idx + 1,
                "path": img_path,
                "type": "image"
            })

    # 提取表格（使用 PDFPlumber）
    with pdfplumber.open(pdf_path) as pdf:
        for page_idx, page in enumerate(pdf.pages):
            tables = page.extract_tables()
            for tbl_idx, table in enumerate(tables):
                result["tables"].append({
                    "page": page_idx + 1,
                    "data": table,
                    "json": table_to_json(table),
                    "type": "table"
                })

    return result

# 使用示例
parsed = parse_annual_report("company_annual_report_2025.pdf")
print(f"文本段落: {len(parsed['texts'])}, 表格: {len(parsed['tables'])}, 图像: {len(parsed['images'])}")
# 输出: 文本段落: 45, 表格: 12, 图像: 28

7.3 构建多模态索引

from langchain_text_splitters import RecursiveCharacterTextSplitter
from pymilvus import Collection, FieldSchema, CollectionSchema, DataType, connections

# 连接向量数据库
connections.connect("default", host="localhost", port="19530")

# 定义 schema
fields = [
    FieldSchema("id", DataType.INT64, is_primary=True, auto_id=True),
    FieldSchema("embedding", DataType.FLOAT_VECTOR, dim=768),
    FieldSchema("content", DataType.VARCHAR, max_length=65535),
    FieldSchema("modality", DataType.VARCHAR, max_length=20),  # text/image/table
    FieldSchema("source_page", DataType.INT64),
    FieldSchema("metadata", DataType.JSON),
]
schema = CollectionSchema(fields, description="多模态RAG索引")
collection = Collection("multimodal_annual_report", schema)

# 文本分块 + Embedding
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
for text_block in parsed["texts"]:
    chunks = splitter.split_text(text_block["content"])
    for chunk in chunks:
        embedding = text_embedder.encode(chunk)  # BGE-M3
        collection.insert([
            [embedding.tolist()],
            [chunk],
            ["text"],
            [text_block["page"]],
            [json.dumps({"source": "年报正文"})]
        ])

# 图表描述 + Embedding
for chart in chart_analyses:
    embedding = text_embedder.encode(chart["description"])
    collection.insert([
        [embedding.tolist()],
        [chart["description"]],
        ["image"],
        [chart["page"]],
        [json.dumps({"source": chart["image_path"], "type": "chart"})]
    ])

collection.flush()
print(f"索引完成，共 {collection.num_entities} 条记录")

7.4 查询示例

query = "2025年Q3营收趋势是什么？相比Q2有什么变化？"

# 1. 向量检索
query_embedding = text_embedder.encode(query)
results = collection.search(
    data=[query_embedding.tolist()],
    anns_field="embedding",
    param={"metric_type": "COSINE", "params": {"nprobe": 16}},
    limit=10,
    output_fields=["content", "modality", "source_page", "metadata"]
)

# 2. 结果包含文本段落、图表描述、表格数据
for hit in results[0]:
    print(f"[{hit.entity.get('modality')}] 页{hit.entity.get('source_page')} "
          f"(相似度: {hit.score:.4f})")
    print(f"  {hit.entity.get('content')[:100]}...")
    print()

# 输出示例:
# [image] 页15 (相似度: 0.8921)

8. 动手练习

练习 1：基础 — PDF 多模态解析

选择一份包含图表和表格的 PDF 文档（如上市公司年报），使用 PyMuPDF 提取图像、PDFPlumber 提取表格、PaddleOCR 处理扫描页，将所有元素分类存储。统计文档中文本、表格、图像各有多少。

验收标准：能够正确提取并分类至少3种模态的元素，输出结构化 JSON。

练习 2：进阶 — CLIP 图文检索

使用 CLIP 模型对练习1中提取的图像生成 embedding，构建一个简单的图文检索系统。输入文本查询（如"营收增长趋势"），返回最相关的3张图表。

验收标准：输入不同查询，系统能返回语义相关的图表，而非随机结果。

练习 3：综合 — 完整多模态 RAG Pipeline

构建完整的多模态 RAG 系统：使用 BGE-VL 对文本和图像统一 embedding，存入 Milvus/Qdrant，实现跨模态检索，最终用 VLM（GPT-5.5 或 Qwen3-VL）生成包含图文引用的回答。

验收标准：输入问题后，系统返回的回答同时引用了文本段落和图表数据，答案准确且有据可查。

扩展方向 尝试 ColPali 方案作为对照实验 — 同样的文档，跳过 OCR 直接以图像检索，对比两种方案的检索质量和速度差异。这将帮助你理解不同技术路线的取舍。

人机交互与持久化

interrupt、Checkpoint、长期记忆与线程管理

为什么需要 Human-in-the-Loop

类比：自动驾驶汽车——大部分时候自动行驶，但在复杂路口、施工区域、突发状况时，系统会提示"请人类接管方向盘"。HITL 就是这个"人类接管"机制，让 AI Agent 在关键决策点暂停，等待人类审核或提供额外信息。

在生产环境中，完全自主的 Agent 存在风险。HITL 让你在以下场景中保持控制：

场景风险解决方案
发送邮件/消息内容错误、发错人发送前暂停，人工确认内容和收件人
数据库写操作数据损坏执行前暂停，人工审核 SQL 语句
API 调用（有副作用）不可逆操作调用前暂停，人工审批
低置信度决策结果不可靠置信度低于阈值时暂停，人工判断
合规审核违反法规特定操作自动触发人工审核流程

interrupt() 函数详解

interrupt() 是 LangGraph 推荐的人机交互方式（0.2+ 版本）。它在节点函数内部调用，暂停图执行，将上下文信息发送给人类，并等待人类响应后恢复执行。

核心机制：interrupt(value) 暂停图执行并将 value 作为"人类看到的信息"返回给调用方。当人类准备好回复时，通过 Command(resume=response) 恢复执行，interrupt() 的返回值就是人类的 response。

Python 
from langgraph.types import interrupt, Command
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver

# 定义带 HITL 的节点
def generate_plan(state):
    """生成执行计划"""
    plan = "1. 创建数据库表\n2. 导入数据\n3. 生成报告"
    return {"plan": plan}

def human_approval(state):
    """人工审批节点：暂停等待人类确认"""
    # interrupt() 暂停执行，返回人类的响应
    human_response = interrupt({
        "plan": state["plan"],
        "question": "请审核以上计划，是否批准执行？"
    })
    # human_response 就是人类通过 Command(resume=) 传入的值
    return {"approved": human_response.get("approved", False)}

def execute_plan(state):
    """执行计划"""
    return {"result": "计划已执行完毕"}

# 构建图
graph = StateGraph(dict)
graph.add_node("generate", generate_plan)
graph.add_node("approve", human_approval)
graph.add_node("execute", execute_plan)

graph.add_edge(START, "generate")
graph.add_edge("generate", "approve")
graph.add_edge("approve", "execute")
graph.add_edge("execute", END)

# 编译（必须有 checkpointer 才能使用 interrupt）
checkpointer = MemorySaver()
app = graph.compile(checkpointer=checkpointer)

# 第一次调用：执行到 interrupt() 时暂停
config = {"configurable": {"thread_id": "task-001"}}
result = app.invoke({"plan": "", "approved": False, "result": ""}, config)
# result 包含 interrupt 的 value，但图已暂停

Command(resume=value) 恢复模式

当图因 interrupt() 暂停后，使用 Command(resume=value) 恢复执行。传入的 value 就是 interrupt() 的返回值。

Python 
from langgraph.types import Command

# 人类审核后，通过 Command(resume=) 恢复执行
result = app.invoke(
    Command(resume={"approved": True, "feedback": "计划合理，批准执行"}),
    config=config
)
print(result["result"])  # -> "计划已执行完毕"

# 也可以拒绝
result = app.invoke(
    Command(resume={"approved": False, "feedback": "需要修改第二步"}),
    config=config
)

关键要点：Command(resume=value) 中的 value 可以是任何 Python 对象——字符串、字典、列表、甚至自定义类实例。在节点函数中，interrupt() 的返回值就是这个对象。设计好数据结构即可。

interrupt_after 编译时参数（旧方式）

在 interrupt() 函数出现之前，LangGraph 使用编译时参数 interrupt_after 来实现 HITL。

interrupt_after（旧方式）

  • 编译时指定哪些节点后暂停
  • 粒度较粗，只能在节点边界暂停
  • 通过 update_state 传入人类决策
  • 用 invoke(None) 恢复

interrupt() 函数（推荐）

  • 节点内部调用，精确控制暂停位置
  • 可在同一节点内多次调用
  • 通过 Command(resume=) 恢复
  • 可传递丰富的上下文信息
Python 
# 旧方式：interrupt_after（仍可用，但不推荐）
app = graph.compile(
    checkpointer=checkpointer,
    interrupt_after=["review"]  # review 节点执行完后暂停
)

# 运行——会在 review 后暂停
result = app.invoke(initial_state, config=config)

# 人类修改 State
app.update_state(config, {"approved": True})

# 恢复（传入 None 表示从暂停点继续）
result = app.invoke(None, config=config)

推荐使用 interrupt()：新项目请使用 interrupt() + Command(resume=) 模式。interrupt_after 仍可用但功能受限，未来可能逐步弃用。

Checkpointing：状态持久化

类比：Checkpoint 就像游戏的自动存档系统。图每执行一个节点就自动存档一次。你可以随时读档回到任意一步，查看历史状态，或者从断点恢复执行。

Checkpoint 是 LangGraph 的核心特性之一。它在每个节点执行后自动保存 State 的快照，支持暂停/恢复、时间回溯、断点续跑。

MemorySaver — 内存存储（开发测试）

Python 
from langgraph.checkpoint.memory import MemorySaver

# 创建内存 checkpoint 存储（仅当前进程有效）
checkpointer = MemorySaver()

# 编译时传入
app = graph.compile(checkpointer=checkpointer)

# 运行时指定 thread_id（每次相同 ID 的调用会延续同一个对话）
config = {"configurable": {"thread_id": "session-001"}}
result = app.invoke(input_state, config=config)

# 查看 checkpoint 历史
history = list(app.get_state_history(config))
for snapshot in history:
    print(f"Step {snapshot.step}: {snapshot.values}")

# 获取当前状态
current = app.get_state(config)
print(current.values)

SqliteSaver — 持久化存储（生产环境）

Python 
from langgraph.checkpoint.sqlite import SqliteSaver

# 使用 SQLite 持久化（数据不会因进程退出丢失）
checkpointer = SqliteSaver.from_conn_string("checkpoints.db")

app = graph.compile(checkpointer=checkpointer)

# 生产环境也可使用 PostgreSQL
# from langgraph.checkpoint.postgres import PostgresSaver
# checkpointer = PostgresSaver.from_conn_string("postgresql://...")
存储后端特点适用场景
MemorySaver内存存储，进程退出即丢失开发测试、原型验证
SqliteSaver文件存储，单机持久化小型生产、单机部署
PostgresSaver数据库存储，支持多实例生产环境、分布式部署

长期记忆：Store 抽象

Checkpoint 是线程内的短期记忆——同一个 thread_id 内的历史。而 Store 抽象提供了跨线程的长期记忆，适合存储用户偏好、历史摘要等需要在多次对话之间共享的信息。

类比：Checkpoint 是"短期工作记忆"——你记得这次对话的上下文。Store 是"长期记忆"——你记得这个用户的偏好、历史交互，不管是不是同一次对话。

Python 
from langgraph.store.memory import InMemoryStore

# 创建长期记忆存储
store = InMemoryStore()

# 编译时同时传入 checkpointer 和 store
app = graph.compile(
    checkpointer=checkpointer,  # 短期记忆（线程内）
    store=store                 # 长期记忆（跨线程）
)

# 在节点函数中使用 Store
def remember_preference(state, *, store):
    
    store.put(
        ("user_preferences", state["user_id"]),
        "language",
        {"preferred_lang": "中文", "updated_at": "2026-06-27"}
    )
    return {}

def recall_preference(state, *, store):
    
    prefs = store.get(
        ("user_preferences", state["user_id"]),
        "language"
    )
    if prefs:
        return {"preferred_lang": prefs.value["preferred_lang"]}
    return {"preferred_lang": "中文"}

Thread 线程管理

每个 thread_id 代表一个独立的执行上下文。同一个 thread_id 的多次调用会延续之前的 State 和 checkpoint。

Python 
# 同一个 thread_id = 同一个对话
config = {"configurable": {"thread_id": "user-123"}}

# 第一轮对话
result1 = app.invoke(
    {"messages": [HumanMessage(content="我叫张三")]},
    config=config
)

# 第二轮对话（自动延续第一轮的上下文）
result2 = app.invoke(
    {"messages": [HumanMessage(content="你还记得我叫什么吗？")]},
    config=config
)
# -> "你叫张三"

# 不同的 thread_id = 不同的对话（互不影响）
config_b = {"configurable": {"thread_id": "user-456"}}
result_b = app.invoke(
    {"messages": [HumanMessage(content="我叫谁？")]},
    config=config_b
)
# -> "我不知道你叫什么名字"

Thread 与 Checkpoint 的关系：每个 thread 拥有独立的 checkpoint 链。同一 thread 的 checkpoint 形成一条时间线，不同 thread 的 checkpoint 完全隔离。这使得你可以同时运行数千个独立对话而互不干扰。

实战：构建需要人工审批的 Agent

综合运用 HITL、Checkpoint 和 Thread 管理，构建一个在执行敏感操作前需要人工审批的 Agent：

Python 
from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.types import interrupt, Command
from langgraph.checkpoint.memory import MemorySaver

class AgentState(TypedDict):
    task: str
    plan: str
    approved: bool
    result: str

# 规划节点
def plan(state: AgentState) -> dict:
    return {"plan": f"执行方案：对 '{state['task']}' 进行自动化处理"}

# 人工审批节点
def approval(state: AgentState) -> dict:
    response = interrupt({
        "type": "approval_request",
        "plan": state["plan"],
        "task": state["task"]
    })
    return {"approved": response.get("approved", False)}

# 执行或拒绝
def execute(state: AgentState) -> dict:
    if state["approved"]:
        return {"result": f"任务 '{state['task']}' 已成功执行"}
    return {"result": "任务被拒绝，未执行"}

# 构建图
graph = StateGraph(AgentState)
graph.add_node("plan", plan)
graph.add_node("approval", approval)
graph.add_node("execute", execute)
graph.add_edge(START, "plan")
graph.add_edge("plan", "approval")
graph.add_edge("approval", "execute")
graph.add_edge("execute", END)

app = graph.compile(checkpointer=MemorySaver())

# 使用
config = {"configurable": {"thread_id": "task-001"}}
result = app.invoke({
    "task": "清理过期数据", "plan": "",
    "approved": False, "result": ""
}, config)

# 人工审批后恢复
result = app.invoke(
    Command(resume={"approved": True}),
    config
)
print(result["result"])  # -> "任务 '清理过期数据' 已成功执行"

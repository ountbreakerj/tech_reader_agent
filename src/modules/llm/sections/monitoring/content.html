📈 训练效果监控

实时监控训练过程，诊断问题并优化

损失曲线监控

类比：损失曲线就像是心电图——正常情况下应该是平稳下降然后趋于平稳。如果剧烈震荡、突然上升或长期不动，都说明训练出了问题。

训练曲线解读

曲线形态含义解决方案
✅ 稳定下降训练正常继续训练
⚠️ 剧烈震荡学习率太大减小学习率
📉 长期不动学习率太小增大学习率
📈 训练损失↓ 验证损失↑过拟合Early Stopping、正则化

import torch
from torch.utils.tensorboard import SummaryWriter

# 初始化TensorBoard
writer = SummaryWriter('runs/experiment_1')

# 训练循环
for epoch in range(num_epochs):
    model.train()

    for batch in train_loader:
        optimizer.zero_grad()
        outputs = model(batch["input_ids"])
        loss = criterion(outputs, batch["labels"])
        loss.backward()
        optimizer.step()
        train_loss += loss.item()

    # 记录训练指标
    avg_train_loss = train_loss / len(train_loader)
    writer.add_scalar('Loss/train', avg_train_loss, epoch)

    # 验证
    model.eval()
    val_loss, correct = 0, 0
    with torch.no_grad():
        for batch in val_loader:
            outputs = model(batch["input_ids"])
            val_loss += criterion(outputs, batch["labels"]).item()
            preds = outputs.argmax(dim=-1)
            correct += (preds == batch["labels"]).sum().item()

    avg_val_loss = val_loss / len(val_loader)
    accuracy = correct / len(val_dataset)

    # 记录验证指标
    writer.add_scalar('Loss/val', avg_val_loss, epoch)
    writer.add_scalar('Accuracy/val', accuracy, epoch)

    print(f"Epoch {epoch+1}: train_loss={avg_train_loss:.4f}, val_loss={avg_val_loss:.4f}, acc={accuracy:.4f}")

writer.close()

过拟合诊断与解决

过拟合信号

过拟合警告信号：
  • 训练损失持续下降，但验证损失开始上升
  • 验证准确率在达到峰值后开始下降
  • 模型在训练集上表现完美，但在新数据上表现很差

解决方案

方法原理代码实现
Early Stopping验证损失不再下降时停止监控验证损失，耐心等待
Dropout随机丢弃神经元nn.Dropout(0.1)
数据增强增加训练数据多样性回译、同义词替换等
权重衰减L2正则化weight_decay=0.01
Python
class EarlyStopping:
    """Early Stopping实现"""
    def __init__(self, patience=5, min_delta=0):
        self.patience = patience
        self.min_delta = min_delta
        self.counter = 0
        self.best_loss = None
        self.early_stop = False

    def __call__(self, val_loss):
        if self.best_loss is None:
            self.best_loss = val_loss
        elif val_loss > self.best_loss - self.min_delta:
            self.counter += 1
            if self.counter >= self.patience:
                self.early_stop = True
        else:
            self.best_loss = val_loss
            self.counter = 0

# 使用Early Stopping
early_stopping = EarlyStopping(patience=5)

for epoch in range(100):

    val_loss = evaluate(model, val_loader)

    early_stopping(val_loss)
    if early_stopping.early_stop:
        print(f"Early stopping at epoch {epoch}")
        break

梯度范数监控

类比：梯度范数就像血压——正常范围内说明训练健康，突然飙升说明有问题（梯度爆炸），持续过低说明模型学不动了（梯度消失）。

为什么监控梯度范数

梯度范数状态含义解决方案
✅ 稳定在合理范围训练正常无需调整
⚠️ 突然飙升（spike）梯度爆炸降低学习率、梯度裁剪
📉 接近0梯度消失检查模型架构、学习率
📈 持续增大训练不稳定降低学习率、增warmup

吞吐量与效率监控

关键效率指标

指标含义典型值
tokens/second每秒处理的token数取决于GPU和模型大小
GPU利用率GPU计算资源使用百分比目标 > 90%
MFUModel FLOPs Utilization目标 40%-60%
显存占用GPU显存使用量越接近上限越好
MFU（Model FLOPs Utilization）：衡量实际训练速度与GPU理论峰值算力的比值。MFU = 实际FLOPs / 峰值FLOPs。这是衡量训练效率的黄金指标。PaLM论文报告的MFU约46%，现代优化后可达50%-60%。
Python
import time
import torch

# 吞吐量监控
def measure_throughput(model, dataloader, device, num_steps=100):
    model.train()
    total_tokens = 0
    start_time = time.time()

    for i, batch in enumerate(dataloader):
        if i >= num_steps:
            break
        input_ids = batch["input_ids"].to(device)
        # 统计token数（不含padding）
        total_tokens += input_ids.numel()

        outputs = model(input_ids, labels=input_ids)
        loss = outputs.loss
        loss.backward()
        optimizer.step()
        optimizer.zero_grad()

    elapsed = time.time() - start_time
    tokens_per_sec = total_tokens / elapsed
    print(f"吞吐量: {tokens_per_sec:,.0f} tokens/sec")
    return tokens_per_sec

gpu_util = torch.cuda.utilization()

训练损失突刺（Loss Spike）处理

真实训练中的常见问题：在长时间的大模型训练中，损失曲线偶尔会出现突然飙升（loss spike），这是非常常见的现象。如何处理loss spike是LLM训练工程师的核心技能之一。

Loss Spike的常见原因

  • 数据异常：某个batch包含异常数据（如极长序列、损坏数据）
  • 学习率过大：训练后期学习率未充分衰减
  • 数值不稳定：FP16训练中的溢出
  • 梯度爆炸：某些层的梯度突然变大

恢复策略

Python
# 策略1：跳过异常batch（最简单）
loss = outputs.loss
if loss.item() > loss_threshold:  # 如阈值设为正常loss的5-10倍
    optimizer.zero_grad()
    continue  # 跳过这个batch

# 策略2：从checkpoint回滚
# 定期保存checkpoint（如每1000步）
# 发现loss spike后，回滚到最近的正常checkpoint
# 降低学习率后继续训练

# 策略3：梯度裁剪 + 学习率衰减
# 检测到loss spike时临时降低学习率
if loss.item() > loss_threshold:
    for pg in optimizer.param_groups:
        pg['lr'] *= 0.5  # 学习率减半
业界经验：GPT-4的训练报告中提到，整个训练过程出现了约20次loss spike。Meta的LLaMA训练中也观察到类似现象。关键是：保存足够频繁的checkpoint，以及有自动检测和回滚机制。

权重分布监控

权重分布监控：除了损失和准确率，监控模型权重和激活值的分布变化也很重要。权重突然变大或变小可能预示训练问题。
Python
import torch

# 记录权重分布（每N步记录一次）
def log_weight_stats(model, writer, global_step):
    for name, param in model.named_parameters():
        if param.requires_grad:
            # 记录权重的均值和标准差
            writer.add_scalar(f'Weights/{name}/mean', param.data.mean(), global_step)
            writer.add_scalar(f'Weights/{name}/std', param.data.std(), global_step)

            # 记录梯度的均值和标准差
            if param.grad is not None:
                writer.add_scalar(f'Grads/{name}/mean', param.grad.mean(), global_step)
                writer.add_scalar(f'Grads/{name}/std', param.grad.std(), global_step)

# 记录激活值分布
def log_activation_stats(model, writer, global_step):
    for name, module in model.named_modules():
        if isinstance(module, torch.nn.Linear):
            def hook_fn(module, input, output):
                writer.add_scalar(f'Activations/{name}/mean', output.mean(), global_step)
                writer.add_scalar(f'Activations/{name}/std', output.std(), global_step)
            module.register_forward_hook(hook_fn)
监控要点：如果某层的权重标准差持续增大，可能出现权重爆炸；如果梯度标准差持续接近0，该层可能无法学习。关注"dead neurons"——输出恒为0的神经元。

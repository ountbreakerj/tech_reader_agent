分类任务指标

指标公式适用场景
准确率（Accuracy）正确数 / 总数类别平衡时
精确率（Precision）TP / (TP+FP)关注假阳性
召回率（Recall）TP / (TP+FN)关注假阴性
F1分数2 × P × R / (P+R)精确率和召回率的平衡

# ROUGE-L：基于最长公共子序列（LCS）的F-measure
# 注意：应基于token级别计算，而非字符级别
# pip install rouge-score

# 方式1：使用rouge-score库（推荐）
from rouge_score import rouge_scorer
scorer = rouge_scorer.RougeScorer(['rougeL'], use_stemmer=True)
scores = scorer.score(reference_text, hypothesis_text)
print(scores['rougeL'])  # 返回 precision, recall, fmeasure

# ROUGE-L计算原理（供理解）：
# 1. 在token级别计算参考文本和候选文本的最长公共子序列（LCS）
# 2. Recall = LCS长度 / 参考文本token数
# 3. Precision = LCS长度 / 候选文本token数
# 4. F-measure = 2 * P * R / (P + R)
# 注意：不是用difflib.SequenceMatcher.ratio()做字符级比对！

评估代码实现

Python
import torch
from sklearn.metrics import accuracy_score, f1_score
import numpy as np

def evaluate_model(model, test_loader, device):
    """完整评估流程"""
    model.eval()
    all_preds = []
    all_labels = []
    total_loss = 0

    with torch.no_grad():
        for batch in test_loader:
            input_ids = batch["input_ids"].to(device)
            labels = batch["labels"].to(device)

            outputs = model(input_ids, labels=labels)
            loss = outputs.loss
            logits = outputs.logits

            total_loss += loss.item()
            preds = torch.argmax(logits, dim=-1)

            all_preds.extend(preds.cpu().numpy())
            all_labels.extend(labels.cpu().numpy())

    # 计算指标
    avg_loss = total_loss / len(test_loader)
    perplexity = np.exp(avg_loss)
    accuracy = accuracy_score(all_labels, all_preds)
    f1 = f1_score(all_labels, all_preds, average="weighted")

    return {
        "loss": avg_loss,
        "perplexity": perplexity,
        "accuracy": accuracy,
        "f1_score": f1
    }

LLM-as-Judge评估方法

LLM-as-Judge：用一个强大的LLM（如GPT-4、Claude）作为"裁判"来评估其他模型的输出质量。这种方法在2025-2026年已成为评估开放式对话质量的主流方法，MT-Bench、Arena-Hard、AlpacaEval 2.0均基于此。

主要框架

框架评估方式特点
MT-BenchGPT-4打分（1-10分）8类多轮对话，最初由LMSYS提出
Arena-Hard与基座模型对比胜率500个高难度prompt，与Chatbot Arena高度相关
AlpacaEval 2.0长度控制胜率（LC Win Rate）805个指令，防止模型通过冗长回答作弊
Python 
# LLM-as-Judge示例：用GPT-4评估模型回答质量
from openai import OpenAI

client = OpenAI()

judge_prompt = """请评估以下AI助手的回答质量（1-10分）。
评估维度：有用性、准确性、安全性、语言流畅度。

问题：{question}
回答：{answer}

请给出分数和简短理由。"""

def llm_judge(question, answer):
    response = client.chat.completions.create(
        model="gpt-4",
        messages=[{"role": "user",
                    "content": judge_prompt.format(
                        question=question, answer=answer)}],
        temperature=0,  # 确定性评判
    )
    return response.choices[0].message.content

LLM-as-Judge的局限性：

  • 位置偏见：倾向于偏好出现在特定位置的回答
  • 冗长偏见：倾向于给更长的回答更高分
  • 自我偏见：GPT-4可能偏好GPT-4风格的回答
  • 缓解方法：交换回答顺序取平均、使用长度控制、多裁判投票

数据污染与评估可靠性

数据污染（Data Contamination）：如果模型的训练数据中包含了评估基准的测试集，那么评估结果就不可信——相当于"考试前看了答案"。这是2025-2026年LLM评估领域最关注的问题之一。

污染的常见形式

  • 直接包含：训练数据中直接包含MMLU、GSM8K等基准的题目和答案
  • 间接包含：包含讨论这些题目的博客、论坛帖子、教材
  • 近似包含：包含与基准题目非常相似的问题

应对措施

  • 使用动态基准：如LiveCodeBench（持续更新）、Chatbot Arena（实时对比）
  • 使用n-gram去污染工具：检测训练数据和测试集的重叠
  • 关注可验证任务：代码（可执行验证）、数学（可检查推导步骤）
  • 多基准交叉验证：不要只看单一基准，综合多个评估结果

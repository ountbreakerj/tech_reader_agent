🔗 多库整合与数据同步

掌握关系库+向量库的数据同步方案，为RAG系统打好基础

数据同步概述

类比：数据同步就像是银行的账务系统——你在ATM机取钱（写入MySQL），几分钟后手机银行就能看到余额变化（同步到Milvus）。这个过程需要保证数据的一致性和及时性。

为什么需要多库同步

在实际项目中，不同的数据存储在不同的数据库中：

  • MySQL：存储用户信息、订单数据等结构化数据
  • Milvus：存储文本嵌入向量，用于语义搜索
  • Redis：存储会话信息、缓存数据

当MySQL中的数据发生变化时，需要同步更新到Milvus，以保证检索结果的一致性。

同步场景分类

类型说明适用场景
实时同步数据变化后立即同步对一致性要求高，如金融交易
准实时同步秒级到分钟级延迟大多数Web应用（推荐）
批量同步定时任务批量同步数据分析、报表

同步方案对比

📝 双写

应用同时写入两个数据库

延迟：极低（毫秒级）

复杂度：低

📡 CDC

监听数据库日志，异步同步

延迟：低（秒级）

复杂度：中

📨 消息队列

通过Kafka/RabbitMQ异步同步

延迟：低（毫秒-秒级）

复杂度：中-高

方案一致性延迟复杂度可靠性适用场景
同步双写强极低低中简单的应用，数据量小

双写方案实现

同步双写（最简单）

Python 
import mysql.connector
from pymilvus import MilvusClient
from sentence_transformers import SentenceTransformer

class DualWriter:
    """同步双写：同时写入MySQL和Milvus"""

    def __init__(self):
        # 初始化MySQL连接
        self.mysql_conn = mysql.connector.connect(
            host="localhost",
            user="root",
            password="password",
            database="mydb"
        )

        # 初始化Milvus连接
        self.milvus_client = MilvusClient("./milvus.db")

        # 初始化Embedding模型
        self.embed_model = SentenceTransformer('all-MiniLM-L6-v2')

    def insert_document(self, title: str, content: str):
        """同步双写文档"""
        try:
            # 1. 写入MySQL
            cursor = self.mysql_conn.cursor()
            cursor.execute(
                "INSERT INTO documents (title, content) VALUES (%s, %s)",
                (title, content)
            )
            doc_id = cursor.lastrowid
            self.mysql_conn.commit()

            # 2. 生成嵌入向量
            embedding = self.embed_model.encode(content).tolist()

            # 3. 写入Milvus
            self.milvus_client.insert(
                collection_name="documents",
                data=[{
                    "id": doc_id,
                    "embedding": embedding,
                    "title": title
                }]
            )

            print(f"✅ 双写成功: doc_id={doc_id}")
            return doc_id

        except Exception as e:
            # 回滚MySQL
            self.mysql_conn.rollback()
            print(f"❌ 双写失败: {e}")
            raise

异步双写（推荐）

Python 
import asyncio
from typing import List

class AsyncDualWriter:
    """异步双写：MySQL写入成功后异步更新Milvus"""

    def __init__(self):
        self.mysql_writer = MySQLWriter()
        self.milvus_writer = MilvusWriter()
        self.embed_model = SentenceTransformer('all-MiniLM-L6-v2')
        self.queue = asyncio.Queue()

    async def insert_document(self, title: str, content: str):
        """异步双写"""
        # 1. 同步写入MySQL（必须成功）
        doc_id = await self.mysql_writer.insert(title, content)

        # 2. 将Milvus更新放入队列（异步处理）
        await self.queue.put({
            "id": doc_id,
            "title": title,
            "content": content
        })

        print(f"✅ MySQL写入成功, Milvus更新已入队")
        return doc_id

    async def process_queue(self):
        """处理Milvus更新队列"""
        while True:
            item = await self.queue.get()

            try:
                # 生成嵌入向量
                embedding = self.embed_model.encode(item["content"]).tolist()

                # 写入Milvus
                await self.milvus_writer.insert(
                    doc_id=item["id"],
                    embedding=embedding,
                    title=item["title"]
                )

                print(f"✅ Milvus更新成功: doc_id={item['id']}")

            except Exception as e:
                print(f"❌ Milvus更新失败: {e}")
                # 重试逻辑
                await self.retry(item)

            finally:
                self.queue.task_done()

    async def retry(self, item, max_retries: int = 3):
        """重试Milvus写入（指数退避）"""
        # TODO: 生产环境应实现指数退避重试，并记录失败日志
        for attempt in range(max_retries):
            try:
                embedding = self.embed_model.encode(item["content"]).tolist()
                await self.milvus_writer.insert(
                    doc_id=item["id"],
                    embedding=embedding,
                    title=item["title"]
                )
                return
            except Exception as e:
                print(f"重试第 {attempt + 1} 次失败: {e}")
                await asyncio.sleep(2 ** attempt)
        print(f"❌ 超过最大重试次数，丢弃: doc_id={item['id']}")

异步双写优势：

  • MySQL写入不被Milvus延迟影响
  • 通过队列削峰，应对突发流量
  • 失败重试机制保证最终一致性

CDC方案详解

类比：CDC（Change Data Capture）就像是数据库的"新闻发言人"——每当数据库发生变化，它就会自动通知外界："嘿，我刚插入了一条新数据！"

CDC原理

CDC通过监听数据库的事务日志（如MySQL的binlog）来捕获数据变化：

sequenceDiagram
    participant App as 应用程序
    participant MySQL as MySQL
    participant CDC as CDC工具
    participant Kafka as Kafka
    participant Milvus as Milvus

    App->>MySQL: 插入/更新数据
    MySQL->>MySQL: 记录binlog
    CDC->>MySQL: 读取binlog
    CDC->>Kafka: 发送变更事件
    Kafka->>Milvus: 消费事件，更新向量

Milvus 2.5+ 原生全文检索（BM25）

Milvus 2.5 开始内置 BM25 全文检索功能，支持稀疏向量（Sparse Vector）和倒排索引。这意味着在某些架构中，不再需要单独维护一个 MySQL 来做关键词检索——Milvus 可以同时处理语义搜索和关键词搜索，从而减少 CDC 同步链路的复杂度和维护成本。对于只关心"全文 + 向量"混合检索的场景，这是一条值得关注的简化路径。

MySQL→Milvus实战

完整的同步Pipeline

Python 
import time
import mysql.connector
from pymilvus import MilvusClient, DataType, CollectionSchema, FieldSchema
from sentence_transformers import SentenceTransformer

class MySQLToMilvusSync:
    """MySQL到Milvus的实时同步"""

    def __init__(self):
        # MySQL连接
        self.mysql_conn = mysql.connector.connect(
            host="localhost",
            user="root",
            password="password",
            database="mydb"
        )

        # Milvus连接
        self.milvus_client = MilvusClient("./milvus_sync.db")

        # Embedding模型
        self.embed_model = SentenceTransformer('all-MiniLM-L6-v2')

        # 同步状态（记录最后同步的ID）
        self.last_synced_id = 0

    def create_milvus_collection(self):
        """创建Milvus Collection"""
        if self.milvus_client.has_collection("documents"):
            self.milvus_client.drop_collection("documents")

        fields = [
            FieldSchema("id", DataType.INT64, is_primary=True),
            FieldSchema("embedding", DataType.FLOAT_VECTOR, dim=384),
            FieldSchema("title", DataType.VARCHAR, max_length=256),
            FieldSchema("synced_at", DataType.INT64)
        ]
        schema = CollectionSchema(fields)

        self.milvus_client.create_collection(
            collection_name="documents",
            schema=schema
        )

        # 创建索引
        index_params = self.milvus_client.prepare_index_params()
        index_params.add_index(
            field_name="embedding",
            index_type="IVF_FLAT",
            metric_type="COSINE",
            params={"nlist": 128}
        )
        self.milvus_client.create_index(
            collection_name="documents",
            index_params=index_params
        )

    def sync_incremental(self):
        """增量同步：只同步新增和更新的数据"""
        cursor = self.mysql_conn.cursor(dictionary=True)

        # 查询自上次同步以来新增或更新的数据
        cursor.execute("""
            SELECT id, title, content
            FROM documents
            WHERE id > %s
            ORDER BY id ASC
            LIMIT 1000
        """, (self.last_synced_id,))

        rows = cursor.fetchall()

        if not rows:
            print("没有新数据需要同步")
            return 0

        print(f"发现 {len(rows)} 条新数据")

        # 批量生成嵌入向量
        texts = [row["content"] for row in rows]
        embeddings = self.embed_model.encode(texts).tolist()

        # 批量写入Milvus
        data = [
            {
                "id": row["id"],
                "embedding": emb,
                "title": row["title"],
                "synced_at": int(time.time())
            }
            for row, emb in zip(rows, embeddings)
        ]

        self.milvus_client.insert(
            collection_name="documents",
            data=data
        )

        # 更新同步水位
        self.last_synced_id = rows[-1]["id"]

        print(f"✅ 同步完成, 最新ID: {self.last_synced_id}")
        return len(rows)

    def get_last_synced_id(self) -> int:
        """获取上次同步的最大ID（可从数据库或文件中读取持久化的水位）"""
        # TODO: 生产环境应将水位持久化到数据库或文件，避免重启后全量重跑
        return 0

    def run_sync_loop(self, interval: int = 5):
        """运行同步循环"""
        self.create_milvus_collection()
        self.last_synced_id = self.get_last_synced_id()

        print(f"🚀 开始同步, 每 {interval} 秒检查一次")

        while True:
            try:
                count = self.sync_incremental()
                if count > 0:
                    print(f"同步了 {count} 条数据")
            except Exception as e:
                print(f"❌ 同步错误: {e}")

            time.sleep(interval)

    'milvus_sync_lag_documents',
    'Number of documents waiting to be synced'

# 在同步代码中记录指标
def sync_with_metrics(syncer):
    start_time = time.time()

    try:
        count = syncer.sync_incremental()
        sync_counter.labels(status='success').inc(count)
        sync_latency.set(time.time() - start_time)
        sync_lag.set(0 if count == 0 else count)

    except Exception as e:
        sync_counter.labels(status='error').inc()
        print(f"Sync error: {e}")

数据一致性检查

Python 
def check_consistency(mysql_conn, milvus_client):
    """检查MySQL和Milvus的数据一致性"""

    # 获取MySQL中的ID列表
    cursor = mysql_conn.cursor()
    cursor.execute("SELECT id FROM documents ORDER BY id")
    mysql_ids = set(row[0] for row in cursor.fetchall())

    # 获取Milvus中的ID列表
    milvus_result = milvus_client.query(
        collection_name="documents",
        filter="id >= 0",
        output_fields=["id"]
    )
    milvus_ids = set(item["id"] for item in milvus_result)

    # 对比差异
    missing_in_milvus = mysql_ids - milvus_ids
    extra_in_milvus = milvus_ids - mysql_ids

    print(f"MySQL记录数: {len(mysql_ids)}")
    print(f"Milvus记录数: {len(milvus_ids)}")
    print(f"Milvus缺少: {len(missing_in_milvus)} 条")
    print(f"Milvus多余: {len(extra_in_milvus)} 条")

    if missing_in_milvus:
        print(f"缺少的ID: {list(missing_in_milvus)[:10]}")

    return len(missing_in_milvus) == 0 and len(extra_in_milvus) == 0

多库同步的数据一致性挑战

  • 分布式事务缺失：MySQL 和 Milvus 之间无法使用 ACID 事务，双写或 CDC 都可能出现一侧成功、另一侧失败的情况
  • 顺序性保证：CDC 消费者需要保证事件的顺序处理，否则可能出现"先删除后插入"被乱序为"先插入后删除"的问题
  • 延迟窗口：最终一致性模型下，数据写入 MySQL 到 Milvus 可查询之间存在秒级到分钟级的延迟窗口，用户可能看到不一致的检索结果
  • 重试幂等性：重试机制必须保证幂等——同一条数据重复写入 Milvus 不应产生重复向量
  • 删除同步：删除操作最容易被忽略，务必在同步链路中处理 DELETE 事件，否则 Milvus 中会残留"僵尸"向量

监控建议：

  • 使用Prometheus + Grafana监控同步延迟和QPS
  • 设置告警：同步延迟超过60秒告警
  • 定期运行一致性检查，记录差异
  • 保留同步日志，便于问题排查

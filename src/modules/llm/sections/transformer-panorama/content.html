🔬 Transformer 全景详解

从 Tokenization 到 KV Cache，系统理解现代大模型的完整架构与推理机制

整体架构：从 Token 到 Logits

Transformer 的完整通路可以分成五个阶段：输入编码、位置信息注入、多层 Transformer Block 变换、最终归一化、以及输出投影（lm_head）到词表概率。

graph TB
    A[原始文本] --> B[Tokenizer BPE分词]
    B --> C[Token IDs序列]
    C --> D[Embedding矩阵查表
得到稠密向量]
    D --> E[加入位置编码
RoPE或绝对位置]
    E --> F[Transformer Block 1
Multi-Head Self-Attention + FFN]
    F --> G[Transformer Block 2]
    G --> H[... 重复 N 层 ...]
    H --> I[最终 RMSNorm / LayerNorm]
    I --> J[lm_head 线性投影到词表]
    J --> K[Softmax 得到 next-token 概率]

现代 LLM（GPT 系、Llama 系）几乎全部采用 仅 Decoder 架构：去掉了原始 Transformer 的 Encoder 和 Cross-Attention，因为在无监督预训练场景下不需要固定的条件序列，单 Decoder + Causal Mask 就能从左到右自回归生成。BERT 系列则保留了 Encoder 路径做双向理解。

Embedding 矩阵的维度是 vocab_size × d_model（Llama-3.1-8B 为 128256 × 4096 ≈ 5.3 亿参数），输出 lm_head 通常与它共享权重（tied embeddings），这样既省了一大块参数，又保证了输入嵌入与输出投影在同一语义空间。

Tokenization：BPE 与词表

模型不直接处理字符，而是将文本切分为子词单元（subword）。最主流的方案是 Byte-Pair Encoding（BPE）：从单字节起步，反复合并出现频率最高的相邻对，直到词表达到目标大小。现代变体 BBPE（Byte-level BPE）确保任意 UTF-8 字节都有对应 token，彻底消除「未知词」问题。

中文一个汉字通常占 2–3 个 token（UTF-8 编码 3 字节，多数模型把高频汉字合并为单 token），英文单词约 0.75 个 token。这意味着同等语义内容，中文比英文多消耗约 1.5–2 倍 token，影响上下文窗口和成本。

tokenizer 文件（tokenizer.json + tokenizer_config.json）记录了合并规则和特殊 token（如 BOS、EOS、PAD）。模型只认识训练时见过的 token 序列，切换 tokenizer 就等于换了一门语言——模型权重完全失效，这是为什么 tokenizer 版本必须和模型权重对应。

Self-Attention：逐步拆解

自注意力的核心直觉：对序列中每个位置，动态计算它与所有其他位置的相关性权重，然后用这些权重对所有位置的「值」做加权求和。

Q / K / V 三个投影各扮演什么角色

输入序列 x ∈ ℝ^{N×d} 经过三组独立的线性变换得到 Q（Query）、K（Key）、V（Value）——不是三者相等，而是同一输入经三个不同权重矩阵投影：

  • Q（查询）：当前位置想找什么信息
  • K（键）：每个位置能提供什么信息
  • V（值）：实际要聚合的内容

    X --> WK[权重矩阵 W_K]

点积打分 → 缩放 → Softmax → 加权求和

相似度打分：scores = Q × K^T，形状 N × N，每个元素是两个向量的点积。

为什么要除以 √d_k？ 点积的方差随维度 d_k 线性增长（两个均值 0、方差 1 的随机向量，点积的方差是 d_k）。不缩放时，高维空间的点积会很大，将 softmax 推向饱和区（梯度几乎为 0），训练无法收敛。除以 √d_k 把方差拉回 1。

每行归一化]

Causal Mask

纯 Decoder 模型生成时，位置 i 只能看到位置 0…i 的信息（否则训练和推理不一致）。实现方式是在 softmax 之前把上三角部分置为 -∞，经 softmax 后这些位置的权重变为 0。

正确的 PyTorch 实现（多头）

常见错误：先对 [N, d_model] 的张量调用 head_dim × head_dim 的 Linear，再 reshape 分头——维度不匹配会直接 RuntimeError。正确做法是先 reshape 分头，再做投影，或者用 d_model × d_model 的 Linear 做一次变换后再 reshape。

import torch
import torch.nn as nn
import torch.nn.functional as F
import math

class MultiHeadSelfAttention(nn.Module):
    def __init__(self, d_model: int, num_heads: int):
        super().__init__()
        assert d_model % num_heads == 0
        self.h = num_heads
        self.d_k = d_model // num_heads
        # 用 d_model -> d_model 的 Linear，而不是 head_dim -> head_dim
        self.W_q = nn.Linear(d_model, d_model, bias=False)
        self.W_k = nn.Linear(d_model, d_model, bias=False)
        self.W_v = nn.Linear(d_model, d_model, bias=False)
        self.W_o = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x: torch.Tensor, mask=None):
        B, N, D = x.shape
        # 投影后再 reshape 分头
        q = self.W_q(x).reshape(B, N, self.h, self.d_k).transpose(1, 2)  # B,h,N,d_k
        k = self.W_k(x).reshape(B, N, self.h, self.d_k).transpose(1, 2)
        v = self.W_v(x).reshape(B, N, self.h, self.d_k).transpose(1, 2)
        # 点积注意力，einsum 下标要让序列维共享（q 用 l，k/v 用 s）
        # 等价于 torch.matmul(q, k.transpose(-2, -1)) / math.sqrt(self.d_k)
        scores = torch.einsum("bhql,bhsl->bhqs", q, k) / math.sqrt(self.d_k)
        if mask is not None:
            scores = scores.masked_fill(mask == 0, float("-inf"))
        attn = F.softmax(scores, dim=-1)
        out = torch.einsum("bhqs,bhsd->bhqd", attn, v)  # B,h,N,d_k
        out = out.transpose(1, 2).reshape(B, N, D)       # B,N,D
        return self.W_o(out)

Multi-Head Attention：多视角并行理解

单头注意力的缺陷：Q/K/V 均来自同一输入，点积矩阵 QK^T 在训练初期容易对角线激活最强（即位置 i 最关注自己），弱化了对其他重要位置的聚焦。多头把 d_model 切分成 h 份，每个头独立学习不同的关注模式：

  • 头 1 可能学习语法主谓关系
  • 头 2 可能学习指代消解（代词指向名词）
  • 头 3 可能学习句子级别的局部结构

拼接后再过一个输出投影 W_o，允许各头的信息混合。参数量：4 × d_model²（Q、K、V、O 各一个 d_model×d_model 矩阵）。

MHA → MQA → GQA：KV Cache 与参数的权衡

KV Cache 大小与 K/V 的头数线性相关。设批大小 B、序列长 L、层数 layer、K/V 头数 n_kv、每头维度 d：

KV Cache 字节 = 2 × B × L × layer × n_kv × d × dtype_bytes

Llama-3.1-8B（GQA，8 个 KV 头，每头 128 维，32 层，bf16）：批大小 1、序列 8192 时约 2×1×8192×32×8×128×2 ≈ 1.07 GB。Llama-3.1-70B（8 个 KV 头，128 维，80 层）同条件约 2×1×8192×80×8×128×2 ≈ 2.68 GB。

位置编码：让模型感知序列顺序

自注意力的 QK^T 只关心向量内容，不关心位置——打乱输入顺序，注意力分数完全不变。必须额外注入位置信息。

RoPE 的旋转直觉

RoPE（旋转位置编码，arXiv 2104.09864，2021 年 4 月）的核心思想：用旋转矩阵把位置信息编码进 Q 和 K，而不是加进输入 x。对位置 m 的 query 和位置 n 的 key，它们的点积只依赖相对距离 m−n，而不是绝对位置——这使得 RoPE 在推理长度超过训练长度时有较好的外推能力。

具体做法：把向量按维度两两分组，对第 i 组施加旋转角 θᵢ = m / 10000^(2i/d)。旋转矩阵只改变方向，不改变模长，因此不引入额外的数值不稳定性。

graph LR
    Q[Query 向量] --> R[对每个二维子空间
乘以旋转矩阵 R_theta_m]
    K[Key 向量] --> S[对每个二维子空间
乘以旋转矩阵 R_theta_n]
    R --> D[点积 RQ · RK = f 相对距离 m-n]
    S --> D

长度外推

NTK-aware scaling（线性缩放基础频率）和 YaRN 是两种主流的 RoPE 外推方法，本质上都是调整旋转频率，让模型在推理时能处理比训练时更长的序列，但都需要少量继续预训练才能完全恢复性能。

ALiBi 的做法更直接：在注意力分数上加一个与相对距离成比例的负偏置，不改变参数，外推效果在一定范围内不弱于 RoPE，但推理速度略低（需要额外的 bias 计算）。

FFN 与 MoE：信息转换与稀疏激活

每个 Transformer Block 包含注意力层和前馈网络（FFN）两部分。FFN 的参数量占 Transformer Block 的约 2/3，是模型存储知识的主要场所。

FFN 结构

标准 FFN 是两层线性变换，中间有激活函数。常见尺寸：d_model → 4×d_model → d_model。

  • ReLU（原始 Transformer）：简单但稀疏，负值直接归零
  • GELU（BERT、GPT-2）：平滑近似，训练更稳定
  • SwiGLU（Llama、PaLM）：x · σ(x) ⊙ W·x，两路相乘，实验表明比 GELU 在 LLM 训练上更好；中间维度通常是 2/3 × 4d（约 2.67d）保持参数量不变

MoE：用稀疏激活扩大模型容量

关键事实：MoE 中每层用多个独立的 FFN（即「专家」）替换单一 FFN，注意力层、LayerNorm、embedding 等全部共享。专家不是完整的 Transformer block。

graph TB
    X[输入 token 向量] --> Router[路由网络
计算每个专家的得分]
    Router --> Top2[Top-2 路由
选择得分最高的 2 个专家]
    Top2 --> E1[专家 1 FFN]
    Top2 --> E2[专家 2 FFN]
    E1 --> WSum[加权求和]
    E2 --> WSum
    WSum --> Out[本层输出]

Mixtral 8×7B：每层 8 个专家 FFN，每个 token 激活 top-2，总参数约 46.7B（8 个 7B 专家 FFN + 所有共享层），每次推理激活约 12.9B。这就是为什么总参 46.7B 而非 56B——注意力层与 7 个未激活专家的参数不参与计算。

残差连接与归一化

Post-LN vs Pre-LN

原始 Transformer（《Attention Is All You Need》第 3.1 节）使用 Post-LN：

x = LayerNorm(x + SubLayer(x))

这里 LayerNorm 包住了残差相加之后的整个结果——「后置归一化」的含义正是如此。另一种常见错误写法 x + LayerNorm(SubLayer(x)) 既非 Post-LN 也非 Pre-LN，是不存在的变体。

现代 LLM 几乎全部改用 Pre-LN（也叫 Pre-Norm）：

x = x + SubLayer(LayerNorm(x))

graph LR
    PostLN[Post-LN 原始 Transformer
x = LayerNorm x + SubLayer x]
    PreLN[Pre-LN 现代 LLM
x = x + SubLayer LayerNorm x]
    PostLN -->|训练不稳定
深层梯度消失| Issue
    PreLN -->|梯度稳定
不需要 warmup| Stable

Pre-LN 的优势：梯度在残差路径上直通到早期层，无需精心设计学习率 warmup；但输出层方差会随深度累积，最终层通常需要额外的 LayerNorm。

RMSNorm

LayerNorm 需要计算均值和方差，RMSNorm 只计算均方根（去掉了均值中心化步骤）：RMSNorm(x) = x / RMS(x) × γ。在实践中效果相当，但计算量约少 10–30%（取决于实现），Llama、Mistral 系列广泛采用。

推理机制：Prefill、Decode 与 KV Cache

这一节直接回答《深入理解 AI Agent》第 2 章的核心疑问：为什么改动前缀会让缓存失效？

两个阶段

graph TB
    P[Prefill 阶段
并行处理输入 prompt] --> K[计算并缓存所有 token 的 K V]
    K --> D[Decode 阶段
每步生成一个 token]
    D --> DK[只计算新 token 的 K V
追加到 KV Cache]
    DK --> D
  • Prefill：一次性处理整个 prompt，计算密集（GPU 利用率高），主要延迟来源是内存带宽和计算量，结果是 prompt 中每个 token 的 K/V 向量存储在 KV Cache 里。
  • Decode：每步只处理刚生成的一个 token，读取 KV Cache 里已有的 K/V，追加新 token 的 K/V，生成下一个 token。计算量极小，瓶颈是 KV Cache 的内存读带宽。

KV Cache 显存计算

设批大小 B、序列总长 L、层数 layer、KV 头数 n_kv、每头维度 d_head、数据类型字节数 dtype_bytes（bf16 = 2）：

KV Cache 字节 = 2 × B × L × layer × n_kv × d_head × dtype_bytes

（系数 2 来自 K 和 V 各一份）

具体数字：Llama-3.1-70B（80 层，8 个 KV 头，128 维/头，bf16），批大小 1，序列 32768 token：

2 × 1 × 32768 × 80 × 8 × 128 × 2 ≈ 10.7 GB

为什么改前缀导致缓存失效

KV Cache 是位置绑定的——第 i 个 token 的 K/V 向量是在「已经看到了位置 0…i-1 所有信息」的条件下计算的。如果前缀改变了，后续所有 token 的因果上下文都改变了，它们的 K/V 不再正确，必须重新计算。

这就是 Agent 上下文设计的核心架构约束：把稳定内容（系统提示、工具定义、用户画像）放前面，把易变内容（用户最新消息、工具结果）放后面。前缀命中率直接决定推理成本——一旦在系统提示里加入时间戳，每次请求都要重算整个 prompt，Prefix Cache 毫无意义。

Prefix Cache（跨请求缓存）

Prefix Cache 是在 KV Cache 基础上的进一步优化：服务端把高频前缀的 KV Cache 在多个请求之间复用（Anthropic 的 prompt caching、vLLM 的 automatic prefix caching）。当多个请求共享相同的系统提示时，服务端只需计算一次，后续请求直接命中缓存。命中节省的成本与前缀长度成正比，典型优化 50–90% 的 TTFT（Time To First Token）。

计算复杂度与注意力优化

自注意力的时间复杂度是 O(N²·d)：每个 token 要与其他所有 token 做点积，结果是 N×N 的注意力矩阵。对于长序列（N = 128k），这个矩阵本身就有 128k² = 16G 个元素，根本放不进 GPU 的 SRAM（通常只有几十 MB）。

Flash Attention：同样的数学，更少的内存搬运

Flash Attention 不改变注意力的数学结果，而是重排计算顺序：将 Q/K/V 分成小块（tiles），在 SRAM 内完成块内的所有计算，使用「online softmax」技巧在不存储完整 N×N 矩阵的情况下完成归一化。

graph TB
    Naive[标准实现
写 N x N 矩阵到 HBM
再读回做 softmax]
    FA[Flash Attention
分 tile 在 SRAM 内计算
不写 N x N 到 HBM]
    Naive -->|HBM 读写次数 O N^2| Slow
    FA -->|HBM 读写次数 O N| Fast

瓶颈不是 FLOP，而是 HBM 带宽。Flash Attention 将 HBM 访问量从 O(N²) 降到 O(N)，速度提升 2–4 倍，显存从 O(N²) 降到 O(N)，使百万 token 上下文成为可能。PyTorch 现在通过 F.scaled_dot_product_attention() 自动使用 Flash Attention，旧接口 torch.backends.cuda.sdp_kernel() 已弃用，应改用 torch.nn.attention.sdpa_kernel。

其他长上下文优化

PagedAttention：将 KV Cache 分成页（pages）管理，减少显存碎片，是 vLLM 的核心技术。Continuous batching：不等到一批请求全部完成才发起下一批，而是逐 step 调度，极大提升 GPU 利用率。这两个技术是生产推理服务的基础，对模型本身透明。

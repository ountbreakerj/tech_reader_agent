LCEL详解：LangChain表达式语言

掌握 Runnable 协议、管道语法与链式组合

LCEL 设计哲学

类比：LCEL 就像是 Unix 的管道 |。在终端里，cat file | grep error | sort | uniq 将多个简单工具串联成复杂操作。LCEL 同样用 | 将 Prompt、LLM、Parser 等组件串联，数据在管道中流动，每一步做一件事。

LCEL（LangChain Expression Language）是 LangChain 1.x 的核心设计理念。它的基础是 Runnable 协议——所有组件都实现了统一的接口：

方法说明适用场景
invoke(input)同步单次调用最基本用法，处理单条输入
batch([inputs])批量调用（自动并发）处理多条输入，性能优化
stream(input)流式输出实时显示 LLM 生成内容
ainvoke(input)异步单次调用async/await 场景
abatch([inputs])异步批量调用高并发服务端
astream(input)异步流式输出异步流式场景
核心优势：因为所有组件共享同一接口，任意两个 Runnable 都可以 A | B 串联。不管 A 是 Prompt、LLM 还是自定义函数，不管 B 是 Parser、另一个 LLM 还是检索器——它们的输入输出协议是一致的。

Pipe 语法详解

| 操作符将两个 Runnable 串联为一个 RunnableSequence。左边的输出变成右边的输入。

Python 
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser

prompt = ChatPromptTemplate.from_template("翻译成英文：{text}")
llm = ChatOpenAI(model="gpt-5.5")
parser = StrOutputParser()

# 等价写法
chain = prompt | llm | parser              # 管道语法（推荐）
chain = prompt.pipe(llm).pipe(parser)    # 显式 .pipe()（不常用）

# 数据流：str -> list[Message] -> AIMessage -> str
#          {text}  prompt输出      llm输出     parser输出

result = chain.invoke({"text": "你好世界"})
# -> "Hello World"
类型转换链：PromptTemplate 接收 dict 输出 str；ChatPromptTemplate 接收 dict 输出 list[BaseMessage]；ChatModel 接收消息列表输出 AIMessage；StrOutputParser 接收 AIMessage 输出 str。这就是为什么它们能用 | 串联——输入输出类型是匹配的。

核心 Runnable 方法

invoke — 单次调用

Python 
# invoke 接收单个输入，返回单个输出
result = chain.invoke({"text": "人工智能改变世界"})
print(result)  # -> "Artificial intelligence is changing the world"

batch — 批量调用

Python 
# batch 接收输入列表，返回输出列表
# 默认并发执行，自动处理速率限制
inputs = [
    {"text": "你好世界"},
    {"text": "机器学习"},
    {"text": "深度学习"}
]
results = chain.batch(inputs)

# 可通过 max_concurrency 控制并发数
results = chain.batch(inputs, {"max_concurrency": 2})

# 异步批量（适合 Web 服务）
results = await chain.abatch(inputs)

stream — 流式输出

Python 
# stream 返回一个生成器，逐步产出结果
for chunk in chain.stream({"text": "量子计算的未来"}):
    print(chunk, end="", flush=True)

# 异步流式
async for chunk in chain.astream({"text": "量子计算的未来"}):
    print(chunk, end="", flush=True)

RunnablePassthrough / RunnableLambda / RunnableParallel

除了 LLM 和 Prompt，LCEL 还提供了三个常用辅助类来构建更灵活的管道。

RunnablePassthrough — 透传输入

Python 
from langchain_core.runnables import RunnablePassthrough

# RunnablePassthrough 直接将输入透传为输出
passthrough = RunnablePassthrough()
result = passthrough.invoke("hello")
# -> "hello"

# 常用于保留原始输入，同时传递给其他分支
# 典型场景：RAG 中保留原始问题

RunnableLambda — 自定义函数

Python 
from langchain_core.runnables import RunnableLambda

# 方式一：用 RunnableLambda 包装函数
def count_chars(text: str) -> dict:
    return {"text": text, "count": len(text)}

counter = RunnableLambda(count_chars)
result = counter.invoke("Hello")
# -> {"text": "Hello", "count": 5}

# 方式二：直接在管道中使用 lambda（自动包装）
chain = prompt | llm | (lambda x: x.content.upper())
result = chain.invoke({"text": "你好"})

# 方式三：用 .map() 对列表每个元素应用函数
upper = RunnableLambda(lambda x: x.upper())
result = upper.batch(["hello", "world"])
# -> ["HELLO", "WORLD"]

RunnableParallel — 并行执行

Python 
from langchain_core.runnables import RunnableParallel, RunnablePassthrough

# RunnableParallel 将多个 Runnable 并行执行
# 输入同时传递给所有分支，输出合并为 dict

# 简写方式（在管道中直接用 dict）
chain = (
    RunnableParallel({
        "original": RunnablePassthrough(),
        "length": RunnableLambda(lambda x: len(x)),
        "upper": RunnableLambda(lambda x: x.upper())
    })
)

result = chain.invoke("hello world")
# -> {"original": "hello world", "length": 11, "upper": "HELLO WORLD"}

# 实际场景：RAG 中同时获取上下文和保留问题
rag_setup = RunnableParallel({
    "context": retriever | format_docs,
    "question": RunnablePassthrough()
})
类比：RunnableParallel 就像是餐厅的"套餐"——你点了一个订单，厨房同时开始做主菜（检索上下文）和配菜（保留原始问题），最后一起端上来组成完整的套餐（prompt 输入字典）。

链式组合：Prompt | LLM | OutputParser

这是 LCEL 最经典的组合模式。数据在管道中依次经过三个阶段：

1
Prompt — 接收 dict 变量，输出消息列表 list[BaseMessage]
2
LLM — 接收消息列表，输出 AIMessage
3
OutputParser — 接收 AIMessage，输出 str / dict / Pydantic
Python 
from langchain_core.prompts import ChatPromptTemplate
from langchain_anthropic import ChatAnthropic
from langchain_core.output_parsers import StrOutputParser

# 构建翻译链
translate_prompt = ChatPromptTemplate.from_messages([
    ("system", "你是专业翻译，将用户输入翻译成{target_lang}，只输出翻译结果"),
    ("human", "{text}")
])
llm = ChatAnthropic(model="claude-opus-5")
parser = StrOutputParser()

translate_chain = translate_prompt | llm | parser

# 构建摘要链
summarize_prompt = ChatPromptTemplate.from_template(
    "请用一句话总结以下内容：\n{text}"
)
summarize_chain = summarize_prompt | llm | parser

# 组合链：先翻译，再摘要
pipeline = translate_chain | summarize_chain

result = pipeline.invoke({
    "target_lang": "英文",
    "text": "LangChain 是一个用于构建基于大语言模型的应用程序的框架。它提供了标准化的接口和工具，简化了开发流程。"
})

分支与合并

通过 RunnableParallel + RunnablePassthrough，可以实现数据的分支处理和结果合并。

Python 
from langchain_core.runnables import RunnableParallel

# 分支：同时对一段文本做翻译和摘要
branch_chain = RunnableParallel({
    "translation": translate_prompt | llm | parser,
    "summary": summarize_prompt | llm | parser,
    "original": RunnablePassthrough()
})

result = branch_chain.invoke({
    "target_lang": "英文",
    "text": "深度学习是机器学习的一个子领域..."
})
# -> {"translation": "Deep learning is...", "summary": "...", "original": "..."}

# 合并：将分支结果汇总为最终报告
def merge_results(data):
    return f"""原文：{data['original']}
翻译：{data['translation']}
摘要：{data['summary']}"""

full_chain = branch_chain | RunnableLambda(merge_results)
并行执行：RunnableParallel 中的多个分支是真正并行执行的（利用线程池或异步），所以"翻译"和"摘要"同时进行，总耗时约等于最慢的那个分支，而不是两者之和。

错误处理

LCEL 提供了两种内置的容错机制：回退和重试。

with_fallbacks — 回退

Python 
from langchain_openai import ChatOpenAI
from langchain_anthropic import ChatAnthropic

# 主模型失败时，自动切换到备选模型
primary_llm = ChatOpenAI(model="gpt-5.5")
fallback_llm = ChatAnthropic(model="claude-opus-5")

chain = prompt | primary_llm.with_fallbacks([fallback_llm]) | parser

# 如果 OpenAI API 调用失败，自动用 Claude 重试
result = chain.invoke({"text": "你好"})

with_retry — 重试

Python 
# 配置重试策略
llm_with_retry = llm.with_retry(
    stop_after_attempt=3,    # 最多重试3次
    wait_exponential_jitter=True  # 指数退避 + 随机抖动
)

chain = prompt | llm_with_retry | parser

# 也可以对整个链配置重试
chain_with_retry = chain.with_retry(stop_after_attempt=2)
注意：with_retry 只重试可重试的异常（如网络超时、429 速率限制）。对于 400 参数错误等不可重试异常，不会触发重试。建议搭配 with_fallbacks 使用，实现"重试后回退"的完整容错链。

实战：构建一个 RAG Chain

综合运用 LCEL 的各种组件，构建一个完整的 RAG（检索增强生成）管道：

Python 
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnableParallel, RunnablePassthrough
from langchain_core.output_parsers import StrOutputParser
from langchain_openai import ChatOpenAI
from langchain_milvus import Milvus
from langchain_openai import OpenAIEmbeddings

# 1. 初始化组件
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vectorstore = Milvus(embedding_function=embeddings, collection_name="docs")
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})
llm = ChatOpenAI(model="gpt-5.5", temperature=0)

# 2. 辅助函数
def format_docs(docs):
    """将检索到的文档列表格式化为单个字符串"""
    return "\n\n".join(
        f"[来源: {doc.metadata.get('source', '未知')}]\n{doc.page_content}"
        for doc in docs
    )

# 3. 构建 RAG Prompt
rag_prompt = ChatPromptTemplate.from_messages([
    ("system", """你是一个知识问答助手。根据以下检索到的上下文回答问题。
如果上下文中没有相关信息，请说明你不确定。

上下文：
{context}"""),
    ("human", "{question}")
])

# 4. 组装 RAG Chain
rag_chain = (
    RunnableParallel({
        "context": retriever | format_docs,   # 检索 + 格式化
        "question": RunnablePassthrough()    # 保留原始问题
    })
    | rag_prompt    # 填入 prompt 模板
    | llm           # 调用 LLM
    | StrOutputParser()  # 提取文本
)

# 5. 调用
answer = rag_chain.invoke("什么是向量数据库？")
print(answer)

# 6. 流式输出（用户逐字看到回答）
for chunk in rag_chain.stream("Milvus 和 Chroma 的区别是什么？"):
    print(chunk, end="", flush=True)
LCEL 的价值：整个 RAG 管道只有约 10 行核心代码，但包含了检索、格式化、提示词构建、LLM 调用、输出解析五个步骤，且支持流式输出、批量调用、异步执行、错误重试——这些都不需要额外代码。这就是 LCEL 管道语法的威力。

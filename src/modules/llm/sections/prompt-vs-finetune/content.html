⚖️ 模块0：提示调优 vs 微调

PEFT方法全景与选型指南

三种适配策略

策略原理训练参数量数据需求效果
全参数微调更新模型所有参数100%万-十万级最好（但成本高）
Prompt-Tuning只训练输入的提示向量<0.1%百-千级接近微调
Prefix-Tuning在每层添加可训练前缀~0.1%百-千级接近微调

PEFT（Parameter-Efficient Fine-Tuning）的核心思想：冻结大模型的大部分参数，只训练少量新增参数，即可达到接近全参数微调的效果。

Prompt-Tuning详解

Prompt-Tuning在输入前拼接一组可训练的连续向量（Soft Prompt），通过反向传播优化这些向量。

Hard Prompt（手工设计）

  • 自然语言文本
  • 需要人类设计
  • 效果依赖设计质量
  • 不可微分

Soft Prompt（可训练）

  • 连续向量
  • 自动学习
  • 效果随数据提升
  • 可微分优化

P-Tuning v2

在每一层Transformer都添加可训练的提示向量（不仅是输入层），效果更接近全参数微调。

PEFT方法全景

方法原理新增参数量训练速度适用模型
LoRA在权重矩阵旁添加低秩分解矩阵A和B~0.1-1%快所有Transformer
QLoRA4-bit量化 + LoRA~0.1%快显存受限场景
Adapter在FFN后插入小型网络~1-5%中BERT/GPT
Prefix-Tuning每层添加可训练前缀向量~0.1%快所有Transformer
DoRA分解权重为方向+大小，LoRA只更新方向~0.1%快比LoRA更优

LoRA原理

将权重更新矩阵 ΔW 分解为两个低秩矩阵的乘积：ΔW = A × B

  • 原始权重 W ∈ R^{d×d}（冻结不训练）
  • A ∈ R^{d×r}, B ∈ R^{r×d}（r << d，可训练）
  • 前向传播：h = Wx + BAx

选型决策指南

场景推荐方法原因
数据很少（<100条）Prompt Engineering不需要训练
数据中等（100-1万条）LoRA/QLoRA参数高效，效果好
数据充足（>1万条）全参数微调效果最好
显存有限（<16GB）QLoRA (4-bit)大幅减少显存
需要快速迭代LoRA训练快，可热切换
多任务部署LoRA适配器切换基座模型共享，仅切换小矩阵

from peft import LoraConfig, get_peft_model

config = LoraConfig(
    task_type="CAUSAL_LM",
    r=16,                # 秩
    lora_alpha=32,       # 缩放系数
    lora_dropout=0.05,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
)
model = get_peft_model(base_model, config)
print(f"可训练参数: {model.print_trainable_parameters()}")
# 输出: trainable params: 4.2M || all params: 7B || 0.06%

2024-2026推荐：QLoRA是显存受限场景的首选；LoRA是生产部署的标准方案；全参数微调只在数据充足+资源充裕时使用。

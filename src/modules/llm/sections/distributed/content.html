分布式训练

从数据并行到 3D 混合并行，掌握大模型训练的核心工程能力

1. 为什么需要分布式训练

以一个 70B 参数的模型为例，训练时需要消耗的显存远超单卡容量：

显存 = 模型参数 + 梯度 + 优化器状态 + 激活值
FP16 参数: 70B × 2 bytes = 140 GB
FP32 梯度: 70B × 4 bytes = 280 GB
Adam 优化器: 70B × (4+4+4) bytes = 840 GB（FP32 参数副本 + 一阶/二阶动量）
合计: ~1,260 GB（不含激活值）
即使使用 BF16 混合精度（参数 2B + 梯度 2B + 优化器 8B = 12B/参数），70B 模型仍需 840 GB 显存，相当于 10.5 张 H100 80GB。加上激活值，实际需求更高。
显存组成FP32 (bytes)BF16 混合精度 (bytes)说明
模型参数42FP32 或 BF16 存储
梯度42与参数精度一致
Adam 一阶动量 (m)44FP32 维护
Adam 二阶动量 (v)44FP32 维护
FP32 参数副本-4混合精度必需
合计/参数1616不含激活值

2. 数据并行（Data Parallel）

数据并行是最基础的分布式策略：每个 GPU 持有完整模型副本，将数据均分到各卡上并行计算，然后同步梯度。

DP vs DDP vs FSDP2

方式通信GIL 限制适用场景
DP（DataParallel）单进程多线程，参数服务器受 GIL 限制单机少量 GPU（已过时）
DDP（DistributedDataParallel）多进程，AllReduce无限制生产环境标准方案
FSDP2（Fully Sharded DP）多进程，分片参数/梯度/优化器无限制超大模型单卡放不下

DDP 训练代码

import torch
import torch.distributed as dist
from torch.nn.parallel import DistributedDataParallel as DDP
from torch.utils.data import DataLoader, DistributedSampler

def train_ddp(local_rank):
    # 1. 初始化进程组
    dist.init_process_group(backend="nccl")
    torch.cuda.set_device(local_rank)

    # 2. 创建模型并包装 DDP
    model = MyModel().cuda()
    model = DDP(model, device_ids=[local_rank])

    # 3. 使用 DistributedSampler 保证各卡数据不重叠
    sampler = DistributedSampler(dataset, shuffle=True)
    loader = DataLoader(dataset, batch_size=8, sampler=sampler)

    optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4)

    for epoch in range(10):
        sampler.set_epoch(epoch)  # 保证每 epoch shuffle 不同
        for batch in loader:
            input_ids = batch["input_ids"].cuda()
            labels = batch["labels"].cuda()
            loss = model(input_ids, labels).loss
            loss.backward()   # DDP 自动在 backward 中做 AllReduce 同步梯度
            optimizer.step()
            optimizer.zero_grad()

    dist.destroy_process_group()

# 启动: torchrun --nproc_per_node=8 train.py
DDP 使用 Bucket AllReduce 优化通信：将多个小梯度张量打包成桶（默认 25MB），减少通信次数。同时在反向传播过程中与计算重叠（overlap），几乎零额外开销。

3. FSDP2（Fully Sharded Data Parallel）

FSDP2 是 PyTorch 原生的全分片数据并行方案（取代 FSDP1），其核心思想是：不让每张卡都持有完整的参数、梯度和优化器状态，而是将它们分片存储到各卡上。

FSDP2 工作流程

1. 前向传播：需要某层参数时，AllGather 从各卡收集完整参数
2. 计算完成后立即释放非本地分片
3. 反向传播：再次 AllGather 获取完整参数，计算梯度
4. ReduceScatter 同步梯度，每卡只保留自己的梯度分片
5. 每卡只更新自己负责的优化器状态分片

FSDP2 训练代码

from torch.distributed.fsdp import fully_shard, MixedPrecisionPolicy

def train_fsdp2():
    dist.init_process_group(backend="nccl")

    # 混合精度策略
    mp_policy = MixedPrecisionPolicy(
        param_dtype=torch.bfloat16,   # 参数使用 BF16
        reduce_dtype=torch.bfloat16,  # 梯度规约使用 BF16
    )

    model = MyLLaMA().cuda()

    # 逐层应用 FSDP2 分片
    for layer in model.layers:
        fully_shard(layer, mp_policy=mp_policy)  # 每个 Transformer 块独立分片
    fully_shard(model, mp_policy=mp_policy)      # 最外层也分片

    optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4)

    for batch in dataloader:
        loss = model(batch["input_ids"].cuda())
        loss.backward()
        optimizer.step()
        optimizer.zero_grad()

# 启动: torchrun --nproc_per_node=8 train_fsdp2.py
FSDP2 的显存优势：8 卡训练 70B 模型时，每卡仅存储 1/8 的参数/梯度/优化器状态（约 105 GB），加上激活值后，每张 H100 80GB 有望放下（配合 activation checkpointing）。

4. DeepSpeed ZeRO 三阶段详解

DeepSpeed ZeRO（Zero Redundancy Optimizer）是微软的分布式训练框架，通过逐步分片消除冗余来降低显存占用。

阶段分片内容每卡显存 (70B, 8卡)通信开销
Stage 1优化器状态~400 GB / 8 = 50 GB与 DDP 相同
Stage 2优化器状态 + 梯度~280 GB / 8 = 35 GB与 DDP 相同
Stage 3优化器状态 + 梯度 + 参数~140 GB / 8 = 17.5 GB比 DDP 多 1.5x

import deepspeed

def train_deepspeed():
    model = MyLLaMA()
    # DeepSpeed 初始化：自动处理分布式、混合精度、ZeRO
    model_engine, optimizer, _, lr_scheduler = deepspeed.initialize(
        model=model,
        config="ds_config.json",
        model_parameters=model.parameters(),
    )

    for batch in dataloader:
        input_ids = batch["input_ids"].to(model_engine.device)
        loss = model_engine(input_ids).loss
        model_engine.backward(loss)       # 自动混合精度 + ZeRO 分片
        model_engine.step()               # 自动梯度裁剪 + 参数更新

# 启动: deepspeed --num_gpus=8 train.py --deepspeed_config ds_config.json

5. ZeRO-Offload / ZeRO-Infinity

当 GPU 显存依然不够时，可以将部分数据卸载到 CPU 内存甚至 NVMe SSD。

ZeRO-Offload（Stage 2 + CPU Offload）

将优化器状态和梯度更新计算卸载到 CPU 上执行。GPU 只负责前向和反向传播。
代价：CPU-GPU 通信带宽成为瓶颈，训练速度降低约 30-50%。

ZeRO-Infinity（Stage 3 + NVMe Offload）

进一步将参数也卸载到 NVMe SSD，利用 NVMe 的高带宽（~7 GB/s）进行分页传输。
效果：在单节点 8 卡上可以训练万亿参数模型。
代价：训练速度显著降低，适合资源受限场景。

策略GPU 显存需求CPU 内存需求NVMe 需求相对速度
ZeRO-3低--1.0x
ZeRO-3 + Offload Opt极低高-0.5-0.7x
ZeRO-Infinity极低中高0.3-0.5x

6. 张量并行（Tensor Parallel）

张量并行（Megatron-LM 方式）将单个矩阵运算拆分到多张 GPU 上，层内并行。

列并行 + 行并行

FFN：W1 按列切分（列并行），W2 按行切分（行并行），每个 GPU 计算部分结果后 AllReduce。
Attention：按注意力头切分，每个 GPU 负责若干头的 Q/K/V 计算，最后 AllReduce。

# Megatron-LM 风格的列并行线性层（概念代码）
class ColumnParallelLinear(nn.Module):
    def __init__(self, in_features, out_features, tp_size):
        super().__init__()
        # 每个 GPU 只存 out_features / tp_size 列
        self.weight = nn.Parameter(
            torch.empty(out_features // tp_size, in_features)
        )

    def forward(self, x):
        # 局部矩阵乘法，无需通信
        return F.linear(x, self.weight)  # (B, L, out/tp)

class RowParallelLinear(nn.Module):
    def __init__(self, in_features, out_features, tp_size):
        super().__init__()
        self.weight = nn.Parameter(
            torch.empty(out_features, in_features // tp_size)
        )

    def forward(self, x):
        out = F.linear(x, self.weight)  # 局部计算
        dist.all_reduce(out)              # AllReduce 汇总各卡结果
        return out
张量并行要求 GPU 间有极高的通信带宽（NVLink 600+ GB/s），因此通常只在单节点内使用。跨节点一般使用流水线并行。

7. 流水线并行（Pipeline Parallel）

流水线并行将模型按层切分到不同 GPU 上，数据像流水线一样依次流过各阶段。

方案策略气泡率特点
GPipe先全部前向，再全部反向(p-1)/m简单但显存峰值高
PipeDream 1F1B交替执行前向和反向(p-1)/m显存峰值低
Interleaved 1F1B每卡负责多个不连续层更低通信更频繁
流水线气泡问题

假设模型分成 4 段（4 张 GPU），p=4。每个 micro-batch 的前向/反向都需要等前一段完成，导致 GPU 空闲（气泡）。
解决办法：将一个 mini-batch 切成多个 micro-batch（梯度累积），提高流水线利用率。

# PyTorch 原生 Pipeline Parallel（概念）
from torch.distributed.pipelining import SplitPoint, pipeline

# 定义模型切分点
pipe = pipeline(
    module=model,
    mb_args=(input_ids,),
    split_spec={
        "layers.7": SplitPoint.BEGINNING,  # 前 8 层在 GPU 0
        "layers.15": SplitPoint.BEGINNING, # 后 8 层在 GPU 1
    }
)

# 生成调度计划
schedule = pipe.build_schedule(n_microbatches=16)
output = schedule.step(input_ids)

8. 混合并行策略（3D 并行）

大规模训练通常结合三种并行：数据并行（DP）+ 张量并行（TP）+ 流水线并行（PP），形成 3D 并行。

典型 3D 并行配置（64 GPU = 8 节点 × 8 卡）

TP = 8（节点内 8 卡，利用 NVLink 高带宽）
PP = 8（8 个节点，跨节点通信量较小）
DP = 1（或更大，取决于模型大小和 batch size）
总 GPU 数 = TP × PP × DP = 8 × 8 × 1 = 64

并行维度切分方式最佳通信典型值
Tensor Parallel层内切分（矩阵拆分）NVLink（节点内）2-8
Pipeline Parallel层间切分（模型分段）网络（跨节点）2-16
Data Parallel数据切分网络剩余 GPU / TP / PP
Sequence Parallel序列长度切分NVLink与 TP 相同
选择并行策略时的核心原则：高带宽通信给 TP（节点内 NVLink），低带宽通信给 PP 和 DP（跨节点网络）。张量并行每层都通信，必须放在最快的链路上。

9. 序列并行（Sequence Parallel）

序列并行将 LayerNorm / Dropout / 激活值 沿序列维度切分到各 GPU，进一步降低显存。

Megatron-SP 原理

在张量并行区域之外（LayerNorm、Dropout），将激活值按序列维度切分。
进入 TP 区域前 AllGather 收集完整序列，离开 TP 区域后 ReduceScatter 重新切分。
效果：激活值显存降低到 TP 的 1/TP，且不增加额外通信量（利用 TP 已有的 AllReduce 改为 AllGather + ReduceScatter）。

# 序列并行中的 RMSNorm（概念代码）
class SequenceParallelRMSNorm(nn.Module):
    def __init__(self, d_model, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(d_model))
        self.eps = eps

    def forward(self, x):
        # x: (B, L/tp, D) - 序列维度已切分
        # 需要 AllGather 获取完整 L 维度的统计量
        full_x = all_gather(x, dim=1)  # (B, L, D)
        rms = torch.sqrt(full_x.pow(2).mean(-1, keepdim=True) + self.eps)
        # ReduceScatter 将结果重新切回序列维度
        out = (full_x / rms) * self.weight
        return reduce_scatter(out, dim=1)  # (B, L/tp, D)

10. 显存估算实战

FP16/BF16 混合精度训练（无并行）：
显存 ≈ N × (2 + 2 + 4 + 4 + 4) bytes + 激活值
= N × 16 bytes + A

N = 参数量，A = 激活值显存（取决于 batch_size 和 seq_len）
ZeRO-3: 显存 ≈ N × 16 / num_gpus + A

Python 显存计算器

def estimate_memory(params_b, strategy="bf16", n_gpus=1):
    """估算训练显存需求（单位 GB）"""
    params = params_b * 1e9  # 参数量转为实际数量

    if strategy == "bf16":
        # BF16 混合精度: 2B参数 + 2B梯度 + 4B×3优化器
        param_mem = params * 2 / 1e9      # BF16 参数
        grad_mem  = params * 2 / 1e9      # BF16 梯度
        opt_mem   = params * 12 / 1e9     # Adam: FP32 copy + m + v
        total = param_mem + grad_mem + opt_mem
    elif strategy == "zero3":
        # ZeRO Stage 3: 所有状态分片
        total = (params * 16) / (1e9 * n_gpus)

    # 激活值（粗估，每参数约 0.5-1 GB for 7B @ bs=1, seq=2048）
    activation = params_b * 0.07  # 经验公式

    result = {
        "model_states": f"{total:.1f} GB",
        "activation": f"{activation:.1f} GB",
        "total": f"{total + activation:.1f} GB",
    }
    return result

# 示例
print(estimate_memory(7, "bf16"))
# {'model_states': '112.0 GB', 'activation': '0.5 GB', 'total': '112.5 GB'}
print(estimate_memory(70, "zero3", n_gpus=8))
# {'model_states': '140.0 GB', 'activation': '4.9 GB', 'total': '144.9 GB'}
实际训练中还需加上 CUDA context（约 0.5-1 GB）、临时缓冲区等开销。建议预留 10-15% 的额外显存。使用 torch.cuda.max_memory_allocated() 监控实际峰值显存。

15.2 LLM-as-Judge 方法论

核心框架

LLM-as-Judge 用一个强大的 LLM 作为评估器，为模型输出打分或进行对比排名。这种方法成本远低于人工标注，且可以快速迭代。

三大主流框架

MT-Bench：80 个多轮对话问题，覆盖写作、推理、数学、编码等 8 个类别。使用 GPT-4 作为 judge，1-10 分评分。

Arena-Hard：从 LMArena 的真实用户问题中筛选 500 个高难度问题。用 win-rate 预测 Arena 排名，相关性高达 0.9+。

AlpacaEval 2.0：805 个指令，将模型输出与 GPT-4 Turbo 参考输出进行对比。使用长度控制的 win-rate（LC-WR）减少长度偏差。

位置偏差与自我偏好问题

LLM-as-Judge 的已知偏差

  • 位置偏差（Position Bias）：Judge 倾向于给第一个（或最后一个）呈现的回复更高分。解决方案：交换顺序评估两次，取平均。
  • 自我偏好（Self-Preference Bias）：GPT-4 倾向于给 GPT-4 的输出更高分。解决方案：使用不同的 judge 模型交叉验证。
  • 长度偏差（Verbosity Bias）：更长的回复往往得到更高分，即使质量不更好。解决方案：使用长度控制指标（如 AlpacaEval LC-WR）。
  • 格式偏差：使用 markdown、列表等格式的回复得到更高分。解决方案：在 judge prompt 中明确要求忽略格式。

15.5 数据污染与评估可靠性

训练数据泄露到测试集的问题

数据污染（Data Contamination）是 LLM 评估面临的最严重问题之一：模型的训练数据中可能包含了测试集的题目和答案，导致基准分数虚高。

数据污染的典型场景

  • Common Crawl 爬取了包含 MMLU/GSM8K 题目的网页和论坛帖子
  • GitHub 代码库中包含了 HumanEval 的解题代码
  • 数学竞赛网站（如 AoPS）上的题目被收录到训练数据
  • 论文预印本中包含基准测试结果，被模型"记忆"

检测方法

# 数据污染检测的几种方法

# 方法一：n-gram 重叠检测
def check_ngram_contamination(train_texts, test_texts, n=13):
    """
    检测训练数据中是否包含测试集的 n-gram
    13-gram 重叠是常用的检测标准（GPT-3 论文使用的方法）
    """
    from collections import Counter

    def get_ngrams(text, n):
        words = text.lower().split()
        return set(tuple(words[i:i+n]) for i in range(len(words) - n + 1))

    # 建立训练数据 n-gram 索引
    train_ngrams = set()
    for text in train_texts:
        train_ngrams.update(get_ngrams(text, n))

    # 检测测试样本
    contaminated = []
    for i, text in enumerate(test_texts):
        test_ngrams = get_ngrams(text, n)
        overlap = test_ngrams & train_ngrams
        if len(overlap) > 0:
            contamination_rate = len(overlap) / len(test_ngrams) if test_ngrams else 0
            contaminated.append((i, contamination_rate, len(overlap)))

    return contaminated

# 方法二：困惑度异常检测
import torch

def perplexity_based_detection(model, tokenizer, test_texts):
    """
    被污染的样本通常困惑度极低（模型已经"见过"这些文本）
    """
    perplexities = []
    for text in test_texts:
        inputs = tokenizer(text, return_tensors="pt", truncation=True)
        with torch.no_grad():
            outputs = model(**inputs, labels=inputs["input_ids"])
        ppl = torch.exp(outputs.loss).item()
        perplexities.append(ppl)

    # 困惑度异常低的样本可能是被污染的
    median_ppl = sorted(perplexities)[len(perplexities) // 2]
    suspicious = [(i, ppl) for i, ppl in enumerate(perplexities)
                  if ppl < median_ppl * 0.1]  # 低于中位数 10 倍

    return suspicious, perplexities

# 方法三：Membership Inference Attack
def membership_inference(model, tokenizer, text):
    """
    通过 Loss 局部最小值检测某段文本是否在训练集中
    已知成员的 loss 分布与非成员不同
    """
    inputs = tokenizer(text, return_tensors="pt")
    with torch.no_grad():
        loss = model(**inputs, labels=inputs["input_ids"]).loss.item()
    return loss  # 极低的 loss 暗示可能被记忆

动态评估的重要性

为了应对数据污染，动态评估（Dynamic Evaluation）正在成为趋势：

  • LiveCodeBench：持续收集最新的编程竞赛题目，按时间窗口评估
  • LMArena：来自真实用户的实时问题，无法预先训练
  • Private test sets：部分评测组织使用未公开的测试集
  • Procedurally generated tasks：程序化生成的测试题目（如 ARC-AGI）

def compute_weighted_score(model_results):
    """计算加权综合分数"""
    total_score = 0
    for dim, config in evaluation_framework.items():
        if dim in model_results:
            dim_score = sum(model_results[dim].values()) / len(model_results[dim])
            total_score += dim_score * config["weight"]
            print(f"{dim}: {dim_score:.2%} (weight: {config['weight']})")
    print(f"\nWeighted Total: {total_score:.2%}")
    return total_score

安全维度评估

安全性评估不应被忽视：

  • 有害输出（Toxicity）：测试模型是否会生成有害、暴力、色情内容
  • 偏见（Bias）：检测模型对性别、种族、宗教等的偏见（BBQ 基准）
  • 幻觉（Hallucination）：评估模型编造事实的倾向（TruthfulQA）
  • 越狱抵抗力：测试模型对 jailbreak 攻击的鲁棒性
  • 隐私保护：检测模型是否会泄露训练数据中的个人信息

效率维度评估

import time

def benchmark_efficiency(model, tokenizer, prompts, batch_sizes=[1, 8, 32]):
    """
    评估模型的效率指标
    """
    results = {}

    for bs in batch_sizes:
        batch_prompts = prompts[:bs]

        # 首 Token 延迟 (TTFT)
        start = time.perf_counter()
        inputs = tokenizer(batch_prompts, return_tensors="pt", padding=True)
        with torch.no_grad():
            first_token = model.generate(**inputs, max_new_tokens=1)
        ttft = time.perf_counter() - start

        # 生成速度 (Tokens/sec)
        start = time.perf_counter()
        with torch.no_grad():
            outputs = model.generate(**inputs, max_new_tokens=256)
        total_time = time.perf_counter() - start
        total_tokens = outputs.shape[0] * outputs.shape[1]
        tokens_per_sec = total_tokens / total_time

        # 内存占用
        import torch
        if torch.cuda.is_available():
            memory_gb = torch.cuda.max_memory_allocated() / 1e9
        else:
            memory_gb = 0

        results[bs] = {
            "ttft_ms": ttft * 1000,
            "tokens_per_sec": tokens_per_sec,
            "memory_gb": memory_gb,
        }

        print(f"Batch={bs}: TTFT={ttft*1000:.0f}ms, "
              f"Tok/s={tokens_per_sec:.0f}, Mem={memory_gb:.1f}GB")

    return results

15.7 动手练习

练习 1：搭建完整评估管线 使用 lm-eval-harness 对一个开源模型（如 Llama 3 8B）在 MMLU、GSM8K、HellaSwag、ARC-Challenge 四个基准上进行评估。记录结果并与官方报告对比，分析差异可能的原因。

练习 2：实现 LLM-as-Judge 设计一个 Judge prompt，用 GPT-4 或 Claude 评估 20 个模型回复的质量（1-10 分）。分别进行：(1) 单一评分，(2) Pairwise 对比。分析两种方式的一致性，并检验是否存在位置偏差（交换顺序后结果是否变化）。

练习 3：RAG 系统评估 搭建一个简单的 RAG 系统（如基于 LangChain），使用 RAGAS 评估其在不同检索策略（BM25 vs 向量检索 vs 混合检索）下的 faithfulness、answer_relevancy、context_precision 和 context_recall。绘制对比图表。

练习 4：数据污染检测 从 GSM8K 测试集中随机选取 50 道题，使用不同的 prompt 模板（原始格式、改写格式、翻译为中文）分别让模型作答。比较三种情况下的准确率——如果原始格式准确率显著高于改写格式，可能存在数据污染。

练习 5：构建多维评估报告 选择 2 个开源模型（如 Llama 3 8B 和 Mistral 7B），从推理、数学、代码、指令遵循四个维度进行评估。生成一份包含雷达图、详细分数表格和优劣势分析的评估报告。

练习 6：自定义动态评估集 创建一个包含 30 道题目的动态评估集（10 道数学、10 道代码、10 道常识推理），确保题目是模型训练数据中不太可能出现的（如最近的新闻事件、新发布的编程库 API）。用这个评估集测试 3 个模型，分析结果。

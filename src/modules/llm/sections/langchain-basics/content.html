LangChain基础：核心概念

理解 LangChain 生态系统、核心组件与基础用法

LangChain 生态系统概览

类比：如果把构建 LLM 应用比作盖房子，LangChain 生态系统就是一整套建筑工具箱。langchain-core 是地基和钢筋（核心抽象），langchain 是预制件（高层接口），langchain-community 是各种五金配件（第三方集成），各 provider 包则是专业设备（如 OpenAI、Anthropic 的专用接口）。

包结构与职责

包名职责典型导入
langchain-core（1.6.1）核心抽象：BaseChatModel、Runnable、LCEL、消息类型from langchain_core.prompts import ChatPromptTemplate
langchain（1.4.0）LangChain v1 高层 Agent 入口与中间件from langchain.agents import create_agent
langchain-community（0.4.2）第三方集成：vectorstores、loaders、embeddingsfrom langchain_community.vectorstores import Chroma
langchain-text-splitters（1.1.2）文本分割器（RecursiveCharacterTextSplitter 等）from langchain_text_splitters import RecursiveCharacterTextSplitter
langchain-openai（1.6.0）OpenAI / Azure 集成from langchain_openai import ChatOpenAI
langchain-anthropic（1.7.1）Claude 系列模型集成from langchain_anthropic import ChatAnthropic
langgraph（1.2.11）图编排引擎、Agent、HITL、持久化from langgraph.graph import StateGraph

导入迁移：LangChain v1 已将核心抽象和集成拆到独立 provider 包。新代码应从 langchain_core、langchain_community 或具体 provider 包导入；例如 from langchain.prompts 应改为 from langchain_core.prompts。直接安装 langchain 仍然可用，但它主要提供高层 Agent API。

LangChain v1 迁移要点（截至 2026-09-04）：新代码使用 from langchain.agents import create_agent 构建 Agent；LLMChain、AgentExecutor、create_tool_calling_agent 等旧式 API 已移入 langchain-classic，用于维护存量项目。动态提示词、工具筛选、重试和 HITL 等横切能力通过 middleware 配置。提示词、消息和文本分割器分别从 langchain_core、langchain_core.messages、langchain_text_splitters 导入。需要自定义循环、supervisor 或 handoff 时，再使用 LangGraph 的 StateGraph 编排 create_agent 实例。

核心组件一览

LangChain 的所有功能都围绕以下五大核心组件构建：

组件作用关键类
Chat Models统一接口调用大模型ChatOpenAI, ChatAnthropic
Prompts模板化提示词PromptTemplate, ChatPromptTemplate
Output Parsers解析 LLM 输出为结构化数据StrOutputParser, JsonOutputParser
Retrievers从外部数据源检索文档VectorStoreRetriever
Tools让 LLM 调用外部能力@tool, StructuredTool

关键理解：这些组件都实现了 Runnable 协议，意味着它们可以像管道一样用 | 操作符串联起来，形成 LCEL（LangChain Expression Language）链。这是 LangChain 1.x 的核心设计理念。

Chat Models 基础用法

LangChain 为每个 LLM 提供商提供了专门的集成包。最常用的两个是 ChatOpenAI 和 ChatAnthropic。

ChatOpenAI

Python 
from langchain_openai import ChatOpenAI

# 基础用法
llm = ChatOpenAI(
    model="gpt-5.5",
    temperature=0.7,
    max_tokens=2048
)

# 调用模型
response = llm.invoke("你好，请介绍一下自己")
print(response.content)

# 使用消息列表
from langchain_core.messages import SystemMessage, HumanMessage

messages = [
    SystemMessage(content="你是一个Python专家"),
    HumanMessage(content="解释装饰器的用法")
]
response = llm.invoke(messages)

ChatAnthropic

Python 
from langchain_anthropic import ChatAnthropic

# 模型 ID 仅作示例，请以 Anthropic 当前 models 列表为准
llm = ChatAnthropic(
    model="claude-sonnet-5",
    temperature=0,
    max_tokens=4096
)

# invoke 与 ChatOpenAI 接口完全一致
response = llm.invoke("用简洁的语言解释量子计算")
print(response.content)

# 流式输出
for chunk in llm.stream("写一首关于编程的诗"):
    print(chunk.content, end="", flush=True)

模型标识符说明：截至 2026-09，示例使用 Claude Sonnet 5（claude-sonnet-5）。模型 ID 会随版本更新，部署前请以各厂商的 models 列表和当前 provider 包文档为准。

PromptTemplate 与 ChatPromptTemplate

LangChain 提供两种提示词模板：简单模板 PromptTemplate 和对话模板 ChatPromptTemplate。实际开发中推荐使用后者。

PromptTemplate — 简单模板

Python 
from langchain_core.prompts import PromptTemplate

# 方式一：from_template
prompt = PromptTemplate.from_template(
    "请将以下文本翻译成{language}：{text}"
)

# 格式化生成完整提示词
result = prompt.format(
    language="英文",
    text="人工智能正在改变世界"
)
# -> "请将以下文本翻译成英文：人工智能正在改变世界"

# 方式二：显式定义变量
prompt = PromptTemplate(
    template="为{product}写一段{style}风格的广告文案，不超过{limit}字",
    input_variables=["product", "style", "limit"]
)

ChatPromptTemplate — 对话模板（推荐）

Python 
from langchain_core.prompts import ChatPromptTemplate

# 方式一：from_messages — 多角色消息模板
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一位资深的{role}，请用专业但通俗的语言回答问题"),
    ("human", "{question}")
])

messages = prompt.format_messages(
    role="数据科学家",
    question="什么是过拟合？"
)

# 方式二：from_template — 自动包装为 human message
simple_prompt = ChatPromptTemplate.from_template(
    "总结以下文本的要点：\n\n{text}"
)

# 方式三：支持 few-shot 示例
few_shot_prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一个代码审查助手"),
    ("human", "审查这段代码：print('hello')"),
    ("ai", "建议：使用 logging 模块替代 print 进行日志输出"),
    ("human", "审查这段代码：{code}")
])

选择建议：PromptTemplate 适合纯文本补全模型（如旧版 GPT-3）；ChatPromptTemplate 专为对话模型设计，支持 system/human/ai 多角色消息，是当前的推荐用法。

Output Parsers 输出解析器

LLM 返回的是纯文本。输出解析器将其转换为结构化数据，便于后续程序处理。

StrOutputParser — 最常用

Python 
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

prompt = ChatPromptTemplate.from_template("用一句话解释：{concept}")
llm = ChatOpenAI(model="gpt-5.5")

# StrOutputParser 从 AIMessage 中提取 .content 字符串
parser = StrOutputParser()

chain = prompt | llm | parser
result = chain.invoke({"concept": "量子纠缠"})
print(result)  # -> 纯文本字符串

JsonOutputParser — 结构化输出

Python 
from langchain_core.output_parsers import JsonOutputParser
from pydantic import BaseModel, Field

# 定义输出结构
class MovieReview(BaseModel):
    title: str = Field(description="电影名称")
    rating: float = Field(description="评分，0-10")
    summary: str = Field(description="一句话影评")

parser = JsonOutputParser(pydantic_object=MovieReview)

# 在 prompt 中注入格式指令
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是影评专家。\n{format_instructions}"),
    ("human", "请评价电影：{movie}")
])

chain = prompt | llm | parser
result = chain.invoke({
    "movie": "星际穿越",
    "format_instructions": parser.get_format_instructions()
})
# -> {"title": "星际穿越", "rating": 9.5, "summary": "..."}

with_structured_output — Pydantic 直出

Python 
# 推荐方式：让模型原生支持结构化输出
llm = ChatOpenAI(model="gpt-5.5")
structured_llm = llm.with_structured_output(MovieReview)

# 直接返回 Pydantic 对象
review = structured_llm.invoke("评价电影：盗梦空间")
print(review.title)    # 盗梦空间
print(review.rating)   # 9.0

实践建议：优先使用 with_structured_output()，它利用了模型原生的结构化输出能力（如 OpenAI 的 function calling），比 JsonOutputParser 更可靠。但要注意，不同模型对结构化输出的支持程度不同。

第一个 LangChain 应用

将上面的组件组合起来，构建一个完整的"文本翻译+摘要"应用：

1
安装依赖 — pip install langchain langchain-openai langchain-core
2
设置 API Key — export OPENAI_API_KEY="sk-..."
3
编写代码 — 见下方完整示例
4
运行测试 — py app.py
Python 
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_openai import ChatOpenAI

# 1. 定义组件
prompt = ChatPromptTemplate.from_messages([
    ("system", "你是翻译专家，请将用户输入翻译成{language}"),
    ("human", "{text}")
])
llm = ChatOpenAI(model="gpt-5.5", temperature=0)
parser = StrOutputParser()

# 2. 组合为链（LCEL 管道语法）
chain = prompt | llm | parser

# 3. 调用
result = chain.invoke({
    "language": "英文",
    "text": "LangChain 是一个用于构建 LLM 应用的框架"
})
print(result)
# -> "LangChain is a framework for building LLM applications."

# 4. 批量调用
results = chain.batch([
    {"language": "英文", "text": "你好世界"},
    {"language": "日文", "text": "今天天气真好"},
])

# 5. 流式输出
for chunk in chain.stream({"language": "法文", "text": "我喜欢编程"}):
    print(chunk, end="", flush=True)

核心要点：这就是 LangChain 1.x 的基本开发模式——定义组件，用 | 管道串联，通过 invoke/batch/stream 调用。下一章将详细讲解 LCEL 管道语法的高级用法。

Agent 工作流模式：从固定流程到多角色协作

Agent 的差别不只在模型，也在于谁决定下一步以及状态如何流动。先根据任务的可控性、延迟预算和失败代价选择编排模式，再决定是否需要引入更复杂的 Agent 框架。

快速判断：流程可以事先画出来就用 Workflow；需要模型根据工具结果逐步决定就用 ReAct；步骤很多但可以先拆解就用 Plan-and-Execute；任务可以按角色拆分且需要并行或互审时再考虑 Multi-Agent。

四种模式对比

模式核心流程自主性实现复杂度常见框架
Workflow (DAG)预定义流程，按图执行高低LangGraph、Haystack
ReAct思考 → 行动 → 观察循环中中LangGraph、Bedrock Agents
Plan-and-Execute先计划，后执行中中高LangGraph、LlamaIndex
Multi-Agent多角色分工协作低高CrewAI、AutoGen

如何选择与落地

  • Workflow (DAG)：节点和边由代码或配置预先定义，适合审批、抽取、质检等固定流程。它的可控性和可审计性最好，但遇到未预设的分支时需要显式补充节点或交给人工。
  • ReAct：模型在每轮读取当前状态，决定是否调用工具，再根据观察结果继续或结束。必须设置最大步数、超时和循环检测，避免错误工具调用无限重试。
  • Plan-and-Execute：先由规划器生成任务清单，再由执行器逐项完成；执行失败时可以让规划器只重排剩余步骤。规划与执行分离后更容易估算进度，但计划过时或拆分错误会带来额外开销。
  • Multi-Agent：把研究、执行、审查等职责交给不同角色，可采用 supervisor、顺序流水线或并行 fan-out。要明确消息协议、共享状态边界和最终汇总者，避免重复劳动、冲突写入和责任不清。

工程建议：从最简单的模式开始，先用单次调用或 Workflow 验证业务规则，再逐步引入 ReAct、规划和多 Agent。复杂度应由真实的分支、并行或隔离需求驱动，而不是由框架名称驱动。

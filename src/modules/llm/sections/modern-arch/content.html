14.1 Flash Attention

IO-aware 精确注意力的原理

标准 Transformer 的自注意力机制计算复杂度为 O(N²)，且需要将完整的 N×N 注意力矩阵写入 GPU 的 HBM（高带宽内存）。Flash Attention 的核心创新是 IO-aware——它不改变数学等价性，而是通过重新组织计算顺序，大幅减少对 HBM 的读写次数。

关键思想：利用 GPU 的 SRAM（片上内存，速度比 HBM 快 ~10x）进行分块（tiling）计算，将 Q、K、V 分成小块加载到 SRAM 中，在片上完成 softmax 和矩阵乘法，避免将中间注意力矩阵写回 HBM。

Flash Attention 核心公式 通过在线 softmax 算法（online softmax trick），可以逐块计算 softmax 而无需存储完整注意力矩阵。IO 复杂度从 O(N²) 降低到 O(N²d²/M)，其中 M 是 SRAM 大小。

Flash Attention 2 / 3 改进

Flash Attention 2 在 v1 基础上进一步优化：

  • 减少非矩阵乘法运算（non-matmul FLOPs），将 rescaling 操作延迟到最后
  • 改进并行策略：在序列长度维度上并行，而非仅在 batch 和 head 维度上
  • 工作分区优化：在 warp 之间更好地分配工作，减少共享内存读写
  • 速度比 Flash Attention 1 快约 2x

Flash Attention 3（2024年发布，针对 Hopper 架构 GPU）：

  • 利用 H100 的异步特性（WGMMA、TMA）实现 warp 级别的生产者-消费者模式
  • FP8 量化注意力计算，保持精度的同时进一步加速
  • 利用 Hopper 的硬件特性实现更好的计算-通信重叠

14.2 RoPE（旋转位置编码）

原理：旋转矩阵编码相对位置

RoPE（Rotary Position Embedding）由苏剑林在 2021 年提出。核心思想是：通过旋转矩阵将位置信息注入到 Query 和 Key 向量中，使得两个 token 的注意力分数仅依赖于它们的相对位置。

对于 d 维向量，RoPE 将其分成 d/2 个二维子空间，每个子空间应用角度为 m·θᵢ 的旋转：

# RoPE 的数学表示
# 给定位置 m 的向量 x = [x₀, x₁, x₂, x₃, ..., x_{d-2}, x_{d-1}]
# RoPE 将其变换为：
# x' = [x₀·cos(m·θ₀) - x₁·sin(m·θ₀),
#        x₀·sin(m·θ₀) + x₁·cos(m·θ₀),
#        x₂·cos(m·θ₁) - x₃·sin(m·θ₁),
#        x₂·sin(m·θ₁) + x₃·cos(m·θ₁),
#        ...]
#
# 其中 θᵢ = 10000^(-2i/d)
#
# 关键性质： = _{m-n}
# 即 q 和 k 的内积只取决于相对位置 (m-n)

RoPE 实现代码

import torch
import torch.nn as nn

class RotaryPositionalEmbedding(nn.Module):
    def __init__(self, dim, max_seq_len=8192, base=10000):
        super().__init__()
        # 计算频率: θᵢ = base^(-2i/d)
        inv_freq = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim))
        self.register_buffer("inv_freq", inv_freq)
        self.dim = dim

    def forward(self, seq_len, device):
        # 生成位置索引 [0, 1, 2, ..., seq_len-1]
        t = torch.arange(seq_len, device=device, dtype=self.inv_freq.dtype)
        # 计算角度矩阵: (seq_len, dim//2)
        freqs = torch.outer(t, self.inv_freq)
        # 拼接得到完整角度: (seq_len, dim)
        emb = torch.cat([freqs, freqs], dim=-1)
        return emb.cos(), emb.sin()

def apply_rotary_pos_emb(q, k, cos, sin):
    """应用旋转位置编码到 q 和 k"""
    def rotate_half(x):
        x1, x2 = x[..., :x.shape[-1]//2], x[..., x.shape[-1]//2:]
        return torch.cat([-x2, x1], dim=-1)

    # 扩展维度以广播: (1, 1, seq_len, dim)
    cos = cos.unsqueeze(0).unsqueeze(0)
    sin = sin.unsqueeze(0).unsqueeze(0)

    q_embed = q * cos + rotate_half(q) * sin
    k_embed = k * cos + rotate_half(k) * sin
    return q_embed, k_embed

# 使用示例
rope = RotaryPositionalEmbedding(dim=128)
cos, sin = rope(seq_len=2048, device="cuda")

q = torch.randn(2, 8, 2048, 128, device="cuda")
k = torch.randn(2, 8, 2048, 128, device="cuda")
q_rope, k_rope = apply_rotary_pos_emb(q, k, cos, sin)

RoPE 的优势

  • 相对位置感知：内积天然反映相对距离，无需学习绝对位置
  • 远距离衰减：随着相对距离增大，内积自然衰减，符合直觉
  • 良好的外推性：通过 NTK-aware 缩放、YaRN 等技术可扩展到远超训练长度
  • 无额外参数：不引入可学习参数，仅通过数学变换实现
为什么几乎所有现代 LLM 都用 RoPE？ RoPE 综合了绝对位置编码（实现简单）和相对位置编码（理论优雅）的优点。从 LLaMA、Mistral、Qwen、DeepSeek 到 Gemma，几乎所有 2023 年后的主流开源 LLM 都采用 RoPE。它与线性注意力、Flash Attention 等技术完全兼容，且通过 YaRN/NTK 可轻松扩展上下文窗口。

14.3 GQA（分组查询注意力）

MHA vs MQA vs GQA 对比

机制全称KV Head 数量KV Cache 大小质量速度
MHAMulti-Head AttentionH（= Q heads）最大最高最慢
MQAMulti-Query Attention1最小（1/H）较低最快
GQAGrouped-Query AttentionG（G < H）中等（G/H）接近MHA接近MQA

GQA 是 MHA 和 MQA 的折中：将 H 个 Query Head 分成 G 组，每组共享一个 KV Head。当 G=H 时退化为 MHA，G=1 时退化为 MQA。

import torch
import torch.nn as nn

class GroupedQueryAttention(nn.Module):
    def __init__(self, d_model, num_q_heads=32, num_kv_heads=8, head_dim=128):
        super().__init__()
        self.num_q_heads = num_q_heads
        self.num_kv_heads = num_kv_heads
        self.head_dim = head_dim
        self.num_groups = num_q_heads // num_kv_heads  # 每组共享的 Q head 数

        self.q_proj = nn.Linear(d_model, num_q_heads * head_dim, bias=False)
        self.k_proj = nn.Linear(d_model, num_kv_heads * head_dim, bias=False)
        self.v_proj = nn.Linear(d_model, num_kv_heads * head_dim, bias=False)
        self.o_proj = nn.Linear(num_q_heads * head_dim, d_model, bias=False)

    def forward(self, x, mask=None):
        B, L, _ = x.shape
        q = self.q_proj(x).view(B, L, self.num_q_heads, self.head_dim).transpose(1, 2)
        k = self.k_proj(x).view(B, L, self.num_kv_heads, self.head_dim).transpose(1, 2)
        v = self.v_proj(x).view(B, L, self.num_kv_heads, self.head_dim).transpose(1, 2)

        # 将 KV heads 扩展到与 Q heads 一致
        k = k.repeat_interleave(self.num_groups, dim=1)  # (B, num_q_heads, L, head_dim)
        v = v.repeat_interleave(self.num_groups, dim=1)

        # 标准注意力计算
        scale = self.head_dim ** -0.5
        attn = (q @ k.transpose(-2, -1)) * scale
        if mask is not None:
            attn = attn.masked_fill(mask == 0, float("-inf"))
        attn = torch.softmax(attn, dim=-1)
        out = (attn @ v).transpose(1, 2).reshape(B, L, -1)
        return self.o_proj(out)

# 示例：Llama 2 70B 的 GQA 配置
gqa = GroupedQueryAttention(
    d_model=8192,
    num_q_heads=64,   # 64 个 Q heads
    num_kv_heads=8,    # 8 个 KV heads（8:1 分组）
    head_dim=128
)

Llama 2/3/4 使用 GQA 的原因

Llama 2 的 70B 模型首先引入 GQA（8 个 KV groups），原因如下：

  • KV Cache 减少 8x：推理时每个 token 只需缓存 8 个 KV head 而非 64 个
  • 推理吞吐提升 ~30%：更大的 batch size 可以放入相同显存
  • 质量损失极小：相比 MHA，困惑度差异在 0.1% 以内
  • Llama 3 全系列（8B/70B/405B）继续使用 GQA，Llama 4 进一步优化了分组策略

14.4 MLA（多头潜在注意力）

DeepSeek V2/V3 的创新设计

MLA（Multi-head Latent Attention）是 DeepSeek V2 引入的注意力机制，其核心思想是：将 KV 投影到低维潜在空间（latent space），再从潜在空间恢复，从而大幅压缩 KV Cache。

import torch
import torch.nn as nn

class MultiHeadLatentAttention(nn.Module):
    def __init__(self, d_model=2048, num_heads=16, head_dim=128,
                 kv_lora_rank=512, q_lora_rank=512):
        super().__init__()
        self.num_heads = num_heads
        self.head_dim = head_dim
        self.kv_lora_rank = kv_lora_rank

        # KV 压缩: 将 KV 压缩到低维 latent
        self.kv_compress = nn.Linear(d_model, kv_lora_rank, bias=False)
        # KV 解压
        self.k_decompress = nn.Linear(kv_lora_rank, num_heads * head_dim, bias=False)
        self.v_decompress = nn.Linear(kv_lora_rank, num_heads * head_dim, bias=False)

        # Q 也做低秩压缩
        self.q_compress = nn.Linear(d_model, q_lora_rank, bias=False)
        self.q_decompress = nn.Linear(q_lora_rank, num_heads * head_dim, bias=False)

        # RoPE 需要单独的小维度
        self.k_rope_proj = nn.Linear(d_model, 64, bias=False)  # 从 h_t 直接投影 RoPE key
        self.q_rope_proj = nn.Linear(q_lora_rank, 64, bias=False)

        self.o_proj = nn.Linear(num_heads * head_dim, d_model, bias=False)

    def forward(self, x):
        B, L, _ = x.shape

        # 压缩 KV 到 latent space
        kv_latent = self.kv_compress(x)  # (B, L, kv_lora_rank)
        # 缓存时只需存 kv_latent，而非完整 KV！

        # 解压得到 K, V
        k = self.k_decompress(kv_latent).view(B, L, self.num_heads, self.head_dim)
        v = self.v_decompress(kv_latent).view(B, L, self.num_heads, self.head_dim)

        # Q 压缩 + 解压
        q_latent = self.q_compress(x)
        q = self.q_decompress(q_latent).view(B, L, self.num_heads, self.head_dim)

        # RoPE 一路直接从 h_t 投影，绕过低秩压缩，故称 decoupled
        k_rope = self.k_rope_proj(x)  # (B, L, 64)
        q_rope = self.q_rope_proj(q_latent)

        return q, k, v, kv_latent  # 推理时只需缓存 kv_latent

14.5 MoE（混合专家）详解

路由机制：Top-K 门控

MoE（Mixture of Experts）的核心思想是用多个"专家"网络替代 FFN 层中的单一前馈网络，由门控网络（Router）为每个 token 选择激活哪些专家。

import torch
import torch.nn as nn
import torch.nn.functional as F

class TopKRouter(nn.Module):
    def __init__(self, d_model, num_experts, top_k=2):
        super().__init__()
        self.top_k = top_k
        self.gate = nn.Linear(d_model, num_experts, bias=False)

    def forward(self, x):
        # x: (batch, seq_len, d_model)
        logits = self.gate(x)  # (batch, seq_len, num_experts)

        # 选择 top-k 专家
        top_k_logits, top_k_indices = logits.topk(self.top_k, dim=-1)
        top_k_weights = F.softmax(top_k_logits, dim=-1)

        return top_k_weights, top_k_indices, logits

class MoELayer(nn.Module):
    def __init__(self, d_model, d_ff, num_experts=8, top_k=2):
        super().__init__()
        self.num_experts = num_experts
        self.top_k = top_k
        self.router = TopKRouter(d_model, num_experts, top_k)

        # 每个专家是一个独立的 FFN
        self.experts = nn.ModuleList([
            nn.Sequential(
                nn.Linear(d_model, d_ff, bias=False),
                nn.SiLU(),
                nn.Linear(d_ff, d_model, bias=False)
            ) for _ in range(num_experts)
        ])

    def forward(self, x):
        # x: (batch, seq_len, d_model)
        B, L, D = x.shape
        weights, indices, router_logits = self.router(x)

        output = torch.zeros_like(x)
        x_flat = x.view(-1, D)  # (B*L, D)
        weights_flat = weights.view(-1, self.top_k)
        indices_flat = indices.view(-1, self.top_k)

        for k in range(self.top_k):
            expert_idx = indices_flat[:, k]  # (B*L,)
            expert_weight = weights_flat[:, k].unsqueeze(-1)  # (B*L, 1)

            for e in range(self.num_experts):
                mask = (expert_idx == e)
                if mask.any():
                    expert_input = x_flat[mask]
                    expert_output = self.experts[e](expert_input)
                    output.view(-1, D)[mask] += expert_weight[mask] * expert_output

        return output, router_logits

负载均衡

MoE 训练中的一大挑战是负载不均衡：少数专家被过度使用，多数专家闲置。解决方案包括：

def load_balancing_loss(router_logits, num_experts, top_k):
    """
    辅助损失函数：鼓励均匀路由
    router_logits: (batch, seq_len, num_experts)
    """
    probs = F.softmax(router_logits, dim=-1)  # (B, L, E)

    # 每个专家被选中的频率
    # 使用 top-k 的 one-hot 近似
    _, indices = router_logits.topk(top_k, dim=-1)
    one_hot = F.one_hot(indices, num_experts).float()
    freq = one_hot.mean(dim=[0, 1, 2])  # (E,) 每个专家的平均选中频率

    # 每个专家的平均路由概率
    mean_prob = probs.mean(dim=[0, 1])  # (E,)

    # 负载均衡损失 = N * sum(freq * mean_prob)
    # 理想情况下 freq 和 mean_prob 都是均匀的 (1/E)
    loss = num_experts * (freq * mean_prob).sum()
    return loss

MoE 训练挑战

  • 通信开销：分布式训练时专家分布在不同 GPU，需要 All-to-All 通信
  • 训练不稳定：路由决策是离散的，梯度估计困难
  • 专家坍缩：少数专家被反复选中，其余专家得不到训练
  • 微调困难：少量数据下容易过拟合，需要特殊的微调策略

14.6 SSM 与 Mamba

状态空间模型原理

SSM（State Space Model）源自控制理论，用连续状态方程描述系统行为：

# 连续时间 SSM:
# h'(t) = A·h(t) + B·x(t)    (状态方程)
# y(t)  = C·h(t) + D·x(t)    (输出方程)
#
# 离散化后（ZOH 离散化）:
# h_t = A̅·h_{t-1} + B̅·x_t
# y_t = C·h_t
#
# 其中 A̅ = exp(Δ·A), B̅ = (Δ·A)^(-1)·(A̅ - I)·Δ·B
#
# 优势：可以用卷积（并行训练）或递推（高效推理）两种方式计算

Mamba 的选择性机制

Mamba（S6 模型）的核心创新：让 SSM 的参数 B、C、Δ 依赖于输入（input-dependent），从而使模型具备内容感知的选择能力。

import torch
import torch.nn as nn

class SelectiveSSM(nn.Module):
    """简化的 Mamba 选择性 SSM 层"""
    def __init__(self, d_model, d_state=16, d_conv=4, expand=2):
        super().__init__()
        d_inner = d_model * expand

        # 输入投影
        self.in_proj = nn.Linear(d_model, d_inner * 2, bias=False)

        # 1D 因果卷积
        self.conv1d = nn.Conv1d(d_inner, d_inner, d_conv,
                                 padding=d_conv-1, groups=d_inner)

        # SSM 参数投影（input-dependent！这是 Mamba 的关键）
        self.x_proj = nn.Linear(d_inner, d_state * 2 + 1, bias=False)
        # 输出: B(d_state), C(d_state), Δ(1)

        # A 参数（对数空间初始化，确保稳定性）
        A = torch.arange(1, d_state + 1, dtype=torch.float32)
        self.A_log = nn.Parameter(torch.log(A))
        self.D = nn.Parameter(torch.ones(d_inner))

        self.out_proj = nn.Linear(d_inner, d_model, bias=False)

    def forward(self, x):
        # x: (B, L, D)
        B_batch, L, _ = x.shape

        # 双分支：一个经过 SSM，一个做门控
        xz = self.in_proj(x)
        x_branch, z = xz.chunk(2, dim=-1)

        # 因果卷积
        x_conv = self.conv1d(x_branch.transpose(1, 2))[:, :, :L].transpose(1, 2)
        x_conv = torch.nn.functional.silu(x_conv)

        # 计算 input-dependent 的 B, C, Δ
        x_ssm = self.x_proj(x_conv)
        B_param, C_param, delta = x_ssm.split(
            [self.A_log.shape[0], self.A_log.shape[0], 1], dim=-1
        )
        delta = torch.nn.functional.softplus(delta)  # 确保 Δ > 0

        # 离散化 A
        A = -torch.exp(self.A_log)  # (d_state,)
        # A̅ = exp(Δ·A)，此处简化处理
        deltaA = torch.exp(delta.unsqueeze(-1) * A)  # (B, L, d_state)
        deltaB = delta.unsqueeze(-1) * B_param.unsqueeze(2)  # 简化

        # 状态递推（实际中使用并行扫描算法加速）
        d_state = A.shape[0]
        h = torch.zeros(B_batch, x_conv.shape[-1] // 1, d_state,
                        device=x.device)  # 简化示例
        # ... 省略完整递推逻辑

        return self.out_proj(x_conv * torch.nn.functional.silu(z))

Mamba-2 改进

Mamba-2（2024）揭示了 SSM 与注意力之间的深层联系（SSD 框架），实现了：

  • 理论训练速度比 Mamba-1 快 2-8x
  • 结构化状态空间对偶性（SSD），统一了 SSM 和线性注意力
  • 支持更高效的分块并行计算

Jamba 混合架构

AI21 的 Jamba 采用 Transformer + Mamba 混合架构：交替堆叠 Transformer 层和 Mamba 层，兼取两者之长。部分层使用 MoE 进一步提升模型容量。类似地，Zamba 和 Griffin 等模型也探索了混合路线。

14.7 RWKV

线性注意力 RNN 的核心思想

RWKV（Receptance Weighted Key Value）由彭博提出，结合了 Transformer 和 RNN 的优势：

  • 训练像 Transformer：可以并行计算，充分利用 GPU
  • 推理像 RNN：每步只需 O(1) 复杂度，无需 KV cache
# RWKV 的时间混合机制（简化）
# Attention 部分：
# wkv_t = (Σ_{i=1}^{t-1} e^{-(t-1-i)w + k_i} · v_i + e^{u+k_t} · v_t)
#       / (Σ_{i=1}^{t-1} e^{-(t-1-i)w + k_i} + e^{u+k_t})
#
# 其中:
# w = 时间衰减参数（learnable）
# u = 当前 token 的 bonus 参数
# k, v = key, value（来自线性投影）
#
# 递推形式:
# a_t = e^{-w} · a_{t-1} + e^{k_t} · v_t    (分子递推)
# b_t = e^{-w} · b_{t-1} + e^{k_t}           (分母递推)
# wkv_t = (a_t + e^{u+k_t} · v_t) / (b_t + e^{u+k_t})

RWKV-6/7 改进

RWKV-6（2024）引入了多项改进：

  • 数据依赖的线性插值：时间衰减参数 w 依赖于输入数据，类似 Mamba 的选择性机制
  • 多头机制：引入类似 GQA 的多头结构
  • 1.5T token 训练：在 100+ 语言的语料上训练
  • 性能逼近同规模 Transformer（如 Llama 3 等）

RWKV-7（2025，代号 Goose）：

  • 进一步引入了 state evolution 机制
  • 在多个基准上超越了同规模 Transformer
  • 证明了线性复杂度架构可以匹配 Transformer 的表达能力
  • 支持 100 万+ token 的上下文长度，推理内存恒定
RWKV 的独特价值 RWKV 是唯一一个同时兼具"并行训练"和"恒定推理复杂度"的架构，且完全开源（Apache 2.0）。对于需要在边缘设备或低资源环境下部署长上下文应用的场景，RWKV 可能是最实用的选择。

14.8 动手练习

练习 1：实现简化版 Flash Attention 使用 Python/PyTorch 实现分块注意力（tiled attention），只使用 O(N) 额外内存。你可以参考在线 softmax 算法，逐块加载 K、V 并更新输出。验证你的实现与标准注意力在数学上等价（误差 < 1e-5）。
练习 2：RoPE 外推实验 实现 NTK-aware RoPE 缩放（修改 base 频率），测试模型在超出训练长度时的困惑度变化。分别测试 base=10000（原始）、base=500000（NTK 缩放）在 2x 和 4x 训练长度下的表现。
练习 3：GQA 对比实验 在小模型（如 125M 参数）上对比 MHA（32 heads）、GQA-8（32Q/8KV）、MQA（32Q/1KV）三种配置的训练收敛速度和推理吞吐量。统计不同序列长度下的 KV cache 内存占用。
练习 4：MoE 路由可视化 训练一个小型 MoE 模型（4 专家，top-2），记录每个 batch 的路由决策。可视化：(1) 每个专家的负载分布；(2) 不同 token 类型（名词、动词、标点等）的路由偏好；(3) 加入负载均衡损失前后的变化。
练习 5：Mamba vs Transformer 对比 在长序列任务上（如 16K、32K、64K token 的语言建模）对比 Mamba 和同等参数量 Transformer 的 (1) 训练速度，(2) 推理速度，(3) 内存占用，(4) 困惑度。绘制性能-序列长度曲线。

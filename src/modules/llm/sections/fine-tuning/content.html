🎨 微调实战

掌握Full Fine-Tuning、LoRA、QLoRA等微调方法

Full Fine-Tuning

类比：Full Fine-Tuning就像是把一本百科全书从头到尾重新读一遍——所有知识（参数）都更新。优点是效果好，缺点是需要很多时间和资源。

优缺点对比

✅ 优点

  • 效果最好
  • 实现简单
  • 可以适应任何任务

❌ 缺点

  • 需要大量显存
  • 训练时间长
  • 容易过拟合

LoRA原理与实践

类比：LoRA就像是在百科全书上贴便利贴——不重写整本书，只在关键页面贴上更新。这样既节省资源，又能达到不错的效果。

LoRA核心思想

LoRA（Low-Rank Adaptation）的核心是低秩分解：不更新所有参数，而是只训练两个小矩阵W_A和W_B，通过它们的乘积来近似参数更新。

Python 
from peft import LoraConfig, get_peft_model
from transformers import AutoModelForCausalLM

# 加载预训练模型
model = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3.1-8B-Instruct")

# 配置LoRA
lora_config = LoraConfig(
    r=8,                          # 低秩维度（越小越省显存）
    lora_alpha=32,                 # 缩放因子
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],  # 所有attention投影层（推荐）
    lora_dropout=0.1,              # Dropout防止过拟合
    bias="none",                   # 不训练bias
    task_type="CAUSAL_LM"          # 因果语言模型任务
)

# 应用LoRA
model = get_peft_model(model, lora_config)

# 查看可训练参数量
model.print_trainable_parameters()
# 输出示例（Llama-3.1-8B、r=8、q/k/v/o）：trainable params ≈ 6,815,744 || all params ≈ 8.03B || trainable% ≈ 0.085%
LoRA参数详解：
  • r（秩）：低秩矩阵的维度。r=8最常用，越大效果越好但显存占用越多
  • lora_alpha：缩放因子，通常设为r的2-4倍
  • target_modules：要适配的层。最佳实践是所有attention投影层 ["q_proj", "k_proj", "v_proj", "o_proj"]，也可加入MLP层 ["gate_proj", "up_proj", "down_proj"]
  • 可训练参数量：通常只有总参数的0.1%-1%

QLoRA实战

📖 什么是QLoRA：QLoRA = 4-bit量化 + LoRA。将模型量化到4-bit（大幅减少显存），然后用LoRA微调。这是在消费级GPU上微调大模型的最佳方案。
Python 
from transformers import (
    AutoModelForCausalLM,
    AutoTokenizer,
    BitsAndBytesConfig,
)
from peft import LoraConfig, get_peft_model
from trl import SFTTrainer, SFTConfig

# 1. 4-bit量化配置
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",        # NF4量化
    bnb_4bit_compute_dtype=torch.bfloat16,  # 计算精度
    bnb_4bit_use_double_quant=True,    # 双重量化
)

# 2. 加载量化后的模型
model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3.1-8B-Instruct",
    quantization_config=bnb_config,
    device_map="auto"
)

# 3. LoRA配置
lora_config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM"
)

model = get_peft_model(model, lora_config)

# 4. 训练参数
training_args = SFTConfig(
    output_dir="./output",
    num_train_epochs=3,
    per_device_train_batch_size=4,
    gradient_accumulation_steps=4,
    learning_rate=2e-4,
    warmup_ratio=0.1,
    fp16=True,
    logging_steps=10,
    save_strategy="epoch",
    max_seq_length=512,
)

# 5. 开始训练
trainer = SFTTrainer(
    model=model,
    train_dataset=train_dataset,
    args=training_args,
)

trainer.train()
💡 QLoRA显存对比（以7B模型为例）：
  • Full Fine-Tuning（FP16）：约112GB（参数 + 梯度 + 优化器状态）
  • LoRA微调（FP16）：约28GB（冻结基座 + 可训练适配器 + 优化器）
  • QLoRA（4-bit量化）：约6-10GB（4-bit基座约3.5GB + 适配器 + 优化器）
  • 可训练参数量：约总参数的0.1%
  • 效果：可达Full Fine-tuning的95%以上

LoRA变体（2025-2026前沿）

📖 LoRA的演进：原始LoRA发布后，研究者提出了多种改进变体，分别解决了不同的局限性。以下是2025-2026年最值得关注的几种。
方法核心思想优势
DoRA将权重分解为幅度（magnitude）+ 方向（direction），仅用LoRA适配方向更接近全参微调的效果，尤其在低秩时
rsLoRA将LoRA的缩放因子从 alpha/r 改为 alpha/sqrt(r)在高秩时更稳定，允许使用更大的r值
LoRA+为A矩阵和B矩阵使用不同的学习率（B的学习率通常更大）收敛更快，最终效果更好
GaLore对梯度做低秩投影而非对参数做低秩分解全参数质量，LoRA级别的显存占用
Python 
# DoRA（Weight-Decomposed Low-Rank Adaptation）
# pip install peft>=0.10.0
from peft import LoraConfig, get_peft_model

lora_config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    use_dora=True,  # 启用DoRA
    task_type="CAUSAL_LM",
)

# rsLoRA：使用rank-stabilized缩放
lora_config = LoraConfig(
    r=64,  # 可以使用更高的秩
    lora_alpha=16,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    use_rslora=True,  # 启用rsLoRA
    task_type="CAUSAL_LM",
)

# GaLore：梯度低秩投影
# pip install galore-torch
from galore_torch import GaLoreAdamW

# GaLore作用于优化器，不需要LoRA
optimizer = GaLoreAdamW(
    model.parameters(),
    lr=1e-4,
    rank=128,       # 梯度投影的秩
    update_proj_gap=200,  # 每200步更新投影矩阵
)

对齐训练（Alignment Training）

🔑 为什么需要对齐训练：SFT（监督微调）教会模型"如何回答"，但对齐训练教会模型"什么样的回答是好的"。这是让模型变得安全、有用、无害的关键步骤。没有对齐的模型可能产生有害、偏见或不真实的内容。

对齐训练方法概览

方法核心思想数据需求代表应用
RLHF训练奖励模型，用PPO优化策略偏好对（chosen/rejected）ChatGPT、Claude
DPO直接从偏好数据优化，无需奖励模型偏好对（chosen/rejected）Zephyr、Llama-3
ORPO将SFT和偏好学习合并为一步偏好对简洁高效
KTO仅需二元反馈（好/坏），无需配对数据二元标签适合真实用户反馈
GRPO组内相对策略优化，无需价值网络可验证答案DeepSeek-R1

RLHF流程

文本
# RLHF（Reinforcement Learning from Human Feedback）三阶段

阶段1 - SFT：用高质量对话数据做监督微调
   → 得到 SFT Model

阶段2 - 奖励模型训练：让人类标注偏好对（回答A更好 vs 回答B更好）
   → 训练 Reward Model，输出"哪个回答更好"的分数

阶段3 - PPO强化学习：用奖励模型的分数作为奖励信号
   → 用PPO算法优化SFT模型，使其生成更高奖励的回答
   → 加入KL散度惩罚，防止模型偏离太远

DPO：更简单的对齐方案

Python 
# DPO（Direct Preference Optimization）
# 不需要训练奖励模型，直接从偏好数据优化
# pip install trl>=0.12.0

from trl import DPOTrainer, DPOConfig
from transformers import AutoModelForCausalLM, AutoTokenizer

# 加载SFT后的模型
model = AutoModelForCausalLM.from_pretrained("your-sft-model")
tokenizer = AutoTokenizer.from_pretrained("your-sft-model")

# 偏好数据格式：
# {"prompt": "问题", "chosen": "好的回答", "rejected": "不好的回答"}

dpo_config = DPOConfig(
    output_dir="./dpo_output",
    num_train_epochs=1,
    per_device_train_batch_size=4,
    learning_rate=5e-7,    # DPO学习率通常比SFT小得多
    beta=0.1,               # KL惩罚系数
)

trainer = DPOTrainer(
    model=model,
    args=dpo_config,
    train_dataset=preference_dataset,
    processing_class=tokenizer,
)

trainer.train()

GRPO：DeepSeek-R1的方法

Python
# GRPO（Group Relative Policy Optimization）
# DeepSeek-R1使用的对齐方法，不需要价值网络
# 核心思想：对同一个问题生成多个回答，组内相对排序

from trl import GRPOTrainer, GRPOConfig

grpo_config = GRPOConfig(
    output_dir="./grpo_output",
    num_train_epochs=1,
    learning_rate=1e-6,
    num_generations=8,      # 每个prompt生成8个候选
    max_completion_length=512,
)

# 需要一个奖励函数来打分
# 对于数学/代码等可验证任务，可以用正确性作为奖励
def reward_func(completions, **kwargs):
    # 根据答案正确性返回奖励分数
    return [compute_reward(c) for c in completions]

trainer = GRPOTrainer(
    model=model,
    args=grpo_config,
    train_dataset=dataset,
    reward_funcs=reward_func,
)
trainer.train()
💡 选择建议：
  • 入门推荐DPO：最简单，不需要训练奖励模型，TRL库直接支持
  • 资源有限选ORPO：一步到位，不需要单独的SFT阶段
  • 真实用户反馈选KTO：不需要配对数据，只需要好/坏标签
  • 数学/代码任务选GRPO：DeepSeek-R1验证了其在推理任务上的强大效果

Agent与工具开发

构建能自主决策和调用外部工具的智能 Agent

create_agent（LangChain v1）

类比：ReAct? 模式就像一个经验丰富的侦探——先推理（Reasoning）：“根据现有线索，我需要查看监控”，再行动（Acting）：调用“查看监控”工具，然后根据结果继续推理，直到破案。

LangChain v1 提供了 create_agent 入口，它内部自动构建了一个包含"推理-行动-观察"循环的图。替代了 LangChain 中已弃用的 AgentExecutor。

Python 
from langchain.agents import create_agent
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langchain_core.messages import HumanMessage

# 定义工具
@tool
def get_weather(city: str) -> str:
    """获取指定城市的天气信息"""
    return f"{city}今天晴天，气温25度"

@tool
def calculate(expression: str) -> str:
    """计算数学表达式"""
    return str(eval(expression))

# 一行创建 Agent
agent = create_agent(
    model=ChatOpenAI(model="gpt-5.5"),
    tools=[get_weather, calculate],
    system_prompt="你是一个有用的助手，善于使用工具解决问题"
)

# 运行 Agent
result = agent.invoke({
    "messages": [HumanMessage(content="北京今天天气怎么样？再帮我算一下 123 * 456")]
})

# 查看最终回复
print(result["messages"][-1].content)
底层原理：create_agent 返回一个可运行的 Agent 图，内部由 LangGraph 状态机驱动，包含两个节点："agent"（调用 LLM 决定下一步）和 "tools"（执行工具调用），通过条件边实现"调用工具 -> 观察结果 -> 再次推理"的循环，直到 LLM 认为可以给出最终答案。

Agent 执行流程

1
用户输入 — 消息进入 Agent 节点
2
LLM 推理 — 模型分析问题，决定是否需要调用工具
3
工具调用 — 如果 LLM 返回 tool_calls，ToolNode 执行对应工具
4
结果观察 — 工具返回结果作为 ToolMessage 加入消息历史
5
循环或结束 — LLM 再次判断：继续调用工具 或 给出最终回答

自定义工具：@tool 装饰器

@tool 装饰器是定义工具的最简方式。函数的 docstring 会自动成为工具的描述，帮助 LLM 理解工具用途。函数签名自动转为参数 schema。

Python 
from langchain_core.tools import tool

@tool
def search_database(query: str, limit: int = 5) -> str:
    """搜索知识库中的文档。

    Args:
        query: 搜索关键词
        limit: 返回结果数量，默认5
    """
    # 模拟搜索
    return f"找到 {limit} 条关于 '{query}' 的结果"

# 自定义工具名称
@tool(name="web_search", description="搜索互联网获取最新信息")
def _search(query: str) -> str:
    return f"互联网搜索结果: {query}"

# 查看工具的自动生成的 schema
print(search_database.args_schema.model_json_schema())
Docstring 很重要：LLM 通过 docstring 理解工具的用途。写清楚"这个工具做什么"、"每个参数的含义"，能显著提高 Agent 选择和使用工具的准确率。

StructuredTool 与 Pydantic Schema

当工具参数较复杂时，使用 Pydantic 模型定义参数 schema 更为规范。

Python 
from langchain_core.tools import StructuredTool
from pydantic import BaseModel, Field

# 定义参数 schema
class SearchInput(BaseModel):
    query: str = Field(description="搜索关键词")
    source: str = Field(
        description="数据来源",
        default="all",
        enum=["all", "web", "database", "files"]
    )
    max_results: int = Field(description="最大返回数量", default=10)

# 定义执行函数
def _search(query: str, source: str = "all", max_results: int = 10) -> str:
    return f"从{source}搜索'{query}'，返回{max_results}条结果"

# 创建 StructuredTool
search_tool = StructuredTool.from_function(
    func=_search,
    name="advanced_search",
    description="从多种数据源搜索信息",
    args_schema=SearchInput,
    return_direct=False  # True = 工具结果直接返回给用户，不经过LLM
)

@tool vs StructuredTool 对比

方式优点适用场景
@tool 装饰器简洁，函数签名即 schema简单工具，参数少且类型基本
StructuredTool完全控制 schema，支持 enum、default复杂参数、需要精确控制描述
BaseTool 子类最大灵活性，可重写 _run/_arun需要异步、复杂状态管理

ToolNode 内置节点

ToolNode 是 LangGraph 提供的预构建节点，它接收 LLM 的 tool_calls，自动执行对应的工具函数，并将结果作为 ToolMessage 返回。

Python 
from langgraph.prebuilt import ToolNode
from langgraph.graph import StateGraph, START, END

tools = [get_weather, calculate]
tool_node = ToolNode(tools)

# 手动构建 Agent 图（等价于 create_agent）
graph = StateGraph(MessagesState)
graph.add_node("agent", call_model)
graph.add_node("tools", tool_node)

# 条件路由：LLM 是否要调用工具？
graph.add_conditional_edges(
    "agent",
    should_continue,
    {
        "continue": "tools",  # 有 tool_calls -> 执行工具
        "end": END,            # 无 tool_calls -> 结束
    }
)
graph.add_edge("tools", "agent")  # 工具结果返回给 Agent

# should_continue 函数
def should_continue(state):
    last_message = state["messages"][-1]
    if last_message.tool_calls:
        return "continue"
    return "end"
ToolNode 要求：工具列表中的每个工具必须有唯一的名称，且工具函数的参数类型必须是 JSON 可序列化的（str、int、float、bool、list、dict）。

多工具编排与工具选择

当 Agent 拥有多个工具时，LLM 会根据用户问题自动选择最合适的工具。你也可以通过 system prompt 引导工具选择策略。

Python 
from langchain.agents import create_agent
from langchain_openai import ChatOpenAI

# 定义多个专业工具
tools = [
    search_database,       # 搜索知识库
    get_weather,           # 查天气
    calculate,             # 计算器
    run_sql_query,         # SQL 查询
    send_email,            # 发邮件
]

# 通过 prompt 引导工具选择策略
system_prompt = """你是一个智能助手，拥有以下工具：
- search_database: 搜索知识库，适用于文档检索
- get_weather: 查询天气，适用于天气相关问题
- calculate: 数学计算，适用于数值计算
- run_sql_query: SQL 查询，适用于数据库查询
- send_email: 发送邮件，适用于邮件任务

规则：
1. 优先使用最合适的工具，不要用错工具
2. 如果不需要工具，直接回答
3. 复杂任务可以组合使用多个工具
"""

agent = create_agent(
    model=ChatOpenAI(model="gpt-5.5"),
    tools=tools,
    system_prompt=system_prompt
)

MCP（Model Context Protocol）工具集成

MCP 是 Anthropic 提出的开放协议，用于标准化 LLM 与外部工具/数据源的连接方式。LangGraph 支持直接将 MCP Server 提供的工具作为 Agent 工具使用。

类比：MCP 就像是 USB 接口标准。以前每个设备（工具）都有自己独特的连接方式，有了 USB（MCP），任何设备都可以即插即用。MCP 让不同的工具服务器（文件系统、数据库、API）通过统一协议接入 Agent。
Python 
# 安装 MCP 适配器
# pip install langchain-mcp-adapters

from langchain_mcp_adapters.client import MultiServerMCPClient
from langchain.agents import create_agent

# 连接 MCP 服务器
async with MultiServerMCPClient({
    "filesystem": {
        "transport": "stdio",
        "command": "npx",
        "args": ["@anthropic/mcp-filesystem", "/path/to/dir"]
    },
    "database": {
        "transport": "sse",
        "url": "http://localhost:8080/sse"
    }
}) as client:
    # MCP 工具自动转为 LangChain 工具
    tools = client.tools

    agent = create_agent(
        model=ChatOpenAI(model="gpt-5.5"),
        tools=tools
    )

    result = await agent.ainvoke({
        "messages": [("human", "读取 /path/to/dir 下的 README 文件")]
    })
MCP 传输方式：stdio 适用于本地进程（如 npx 启动的工具服务器）；sse（Server-Sent Events）适用于远程 HTTP 服务器。大多数 MCP 服务器同时支持两种方式。

实战：构建一个多工具 Agent

综合以上知识，构建一个能查天气、做计算、搜索文档的多工具 Agent：

Python 
from langchain.agents import create_agent
from langgraph.checkpoint.memory import MemorySaver
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langchain_core.messages import HumanMessage

# 定义工具集
@tool
def get_weather(city: str) -> str:
    """获取城市的实时天气"""
    weather_data = {
        "北京": "晴，25度，湿度40%",
        "上海": "多云，28度，湿度65%",
    }
    return weather_data.get(city, f"{city}的天气数据暂不可用")

@tool
def calculate(expression: str) -> str:
    """计算数学表达式，支持加减乘除和幂运算"""
    try:
        return str(eval(expression, {"__builtins__": {}}))
    except Exception as e:
        return f"计算错误: {e}"

@tool
def search_docs(query: str) -> str:
    """搜索内部文档知识库"""
    # 实际项目中对接向量数据库
    return f"文档搜索结果: 关于'{query}'找到了3篇相关文档"

# 创建带持久化的 Agent
checkpointer = MemorySaver()
agent = create_agent(
    model=ChatOpenAI(model="gpt-5.5"),
    tools=[get_weather, calculate, search_docs],
    checkpointer=checkpointer,
    system_prompt="你是一个多技能助手，善于综合使用工具解决复杂问题"
)

# 运行（带线程ID以支持多轮对话）
config = {"configurable": {"thread_id": "user-001"}}
result = agent.invoke(
    {"messages": [HumanMessage(content="北京天气怎么样？再帮我算 15% 的折扣价是多少钱（原价 299）")]},
    config=config
)
print(result["messages"][-1].content)

# 第二轮对话（自动保持上下文）
result = agent.invoke(
    {"messages": [HumanMessage(content="帮我搜索一下关于天气预测的文档")]},
    config=config
)
生产建议：实际项目中，工具函数应包含完善的错误处理和超时控制。对于敏感操作（如发邮件、写数据库），建议配合 HITL（人机交互）机制，在执行前要求人工确认。
